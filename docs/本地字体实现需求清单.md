## 0. 冻结口径、三个上限与裁定结论

### 0.1 已冻结口径（与设计一致，实现不得偏离）

| 编号 | 口径 | 设计出处 |
| --- | --- | --- |
| F1 | 阅读器选项字段名是 **`fonts.localFonts`**，不是 `fonts.local`；`FontSource` 新增的判别键是 **`local`** | §3.1 / §3.2 |
| F2 | `LocalFontsOptions` 共 **5** 个字段：`enabled` / `defaultEnabled` / `remember` / `maxFonts` / `consentText`（设计表头误写「四个字段」） | §3.2 |
| F3 | 注入顺序：**宿主 `fonts.default` 在前、本机字体在后**（`supplementary` 同理），宿主显式配置始终优先 | §6.1 / §12.5 |
| F4 | `{ local }` 来源在「未开启 / 不支持 / 权限非 granted」时**静默跳过**，不阻塞打开、不回退其它来源 | §2.1 / §4.4 |
| F5 | `queryLocalFonts` **只做定向查询**，禁止无参全量枚举；`blob()` 字节经 `compat.ts` 的 `readBlobBytes()` 读取（Chrome 67 无 `Blob.arrayBuffer`） | §1.4 / §8 |
| F6 | 本机字体注入的 `FontInput.family` 取**文档声明的 `FontName`**（如 `宋体`），不是本机字体的 family | §6.1 |
| F7 | 不做字体热替换：开关变化一律走「重开当前文档 + 恢复视图」 | §2.3 / §3.5 |
| F8 | 引擎侧只新增 `getFontResources()` 一个字体相关公开 API，不新增其它 | §3.6 |

### 0.2 三个「上限」必须分别命名（最容易各理解一套的地方）

| 名称 | 数值 | 语义 | 归属 |
| --- | --- | --- | --- |
| **单声明候选上限** `MAX_CANDIDATES_PER_DECLARATION` | **6** | 一个声明经「变体后缀 → 基础名 → 原始名」展开后截断到 6 个候选名（设计 §3.3） | `local-font-names.ts` |
| **单次查询名数上限** `MAX_NAMES_PER_QUERY` | 8 | 一次 `queryLocalFonts({ postscriptNames })` 调用最多塞 8 个名字，是浏览器层面的保险丝（设计 §1.4） | `local-fonts.ts` |
| **单文档查询声明数上限** `maxFonts`（选项，默认 8） | 8 | 一份文档最多查询多少个**文档声明字体**（设计 §3.2） | `document-controller.ts` |

实现约定：**一个声明一次调用，候选截断到 6**，因此天然满足「单次调用 ≤ 8」。`maxFonts` 与上面两个名字数上限**无关**，不得混用同一个常量或变量名。

### 0.3 裁定结论（已由 captain 裁定，实现按此执行）

| 编号 | 冲突/歧义 | 设计原文 | 裁定结论 |
| --- | --- | --- | --- |
| C1 | 候选名上限 | §1.4「单次查询的候选名不超过 8 个」；§3.3「候选名总数上限 6 个」 | 按 §0.2 三个数分别命名；实现取更严者：一个声明一次调用，候选截断到 6 |
| C2 | 注入顺序 | §6.1「追加在宿主配置之后……或……放在前面」 | 固定「**宿主配置在前、本机字体在后**」（=F3）；§6.1 的「或…放在前面」是设计笔误 |
| C3 | `settings` 是否新增功能键 | 设计未提 | **不新增** `VIEWER_FEATURES` 键，不做 featureGate；访问控制只来自 `sidebar` 功能门控 + `fonts.localFonts.enabled` |
| C4 | `FontSource` 判别键 | `fonts.localFonts` 与 `{ local }` 并存 | 选项名 `localFonts`、来源判别字段 `local`（=F1）；**两者不同名是刻意的**，禁止「统一」成同一个名字 |
| C5 | 选项字段数 | 表头「四个字段」，实际 5 个 | 按 5 字段冻结（=F2）；「四个字段」是设计笔误 |
| C6 | 类型命名 | §3.5 `LocalFontsStatus`；§9「`LocalFontStatus` 相关类型」 | 两个类型都导出：`LocalFontStatus`（**单数=权限枚举值**）、`LocalFontsStatus`（**复数=状态对象**）；收口 typecheck 时注意不可撞名 |
| C7 | 拒绝后的「提示」 | §4.4「按『不可用』处理并提示」；§5.1「不加 toast 引导」 | **不发 toast**；只在侧栏 `settings` 面板内写状态文案 `未获得授权` |
| C8 | e2e 是否桩化权限 | §10 只要求桩化 `queryLocalFonts` | 桩化 `window.queryLocalFonts` **和** `navigator.permissions.query`（`denied` 返回 `[]` 与「未安装」无法区分，见设计 §1.1） |
| C9 | `DocumentFontResource.documentLevel` 取值来源 | §3.6 注释「来自 DocumentRes/PublicRes 时为 true」 | 只要进入 `DocumentResourceIndex.fonts`（= `PublicRes`/`DocumentRes` 合并结果）即 `true`；页级 `PageRes.xml` 声明不出现（=设计 §12.7） |
| C10 | `getFontResources()` 返回顺序 | REQ 草案原写「保持 Map 插入顺序」 | **改为按 `id` 升序排序**（字符串比较 `a.id < b.id`，不用数字排序、不用 `localeCompare`）。Map 顺序取决于 XML 书写次序，跨文档不稳定。对应 REQ-003 第 2 条与 T-E1 用例 |
| C11 | 名称大小写还原 | REQ 草案原写「首字符大写还原」（`microsoft yahei` → `MicrosoftYahei`） | **该推断规则整句作废**：内置表优先；内置表未命中时**不推断大小写**，只保留已是合法 PostScript 形态的名称；`names` 可保留归一化原名参与查询。实测 `Simsun`≠`SimSun`，草稿规则已导致黑体失效（阻断级） |
| C12 | 空结果缓存策略 | REQ 草案原写「denied/不支持/未安装的空结果也缓存」 | **只缓存正向命中结果与本机未安装**；`denied`/`unsupported`/`prompt` 权限态**一律不缓存**（权限是可变用户决定，缓存会导致用户改权限后本实例内无法恢复）。对应 REQ-0160 |
| C13 | 开关解析与持久化归属 | REQ 草案原写放在 `local-fonts.ts` | **改归 t3（ui-impl，viewer/状态层）**；`local-fonts.ts` 只保留纯查询与类型定义，不读写 localStorage、不解析生效值。对应 REQ-007 / REQ-008 |
| C14 | resolver 的 `localFonts` 接线 | REQ 草案原写 `declarations()` 回调 | **删除该设计**：`FontSourceResolverOptions.localFonts` 只接收 `{ enabled: boolean }`；resolver 只负责开关判断与缓存清理；声明筛选 / `maxFonts` 裁剪 / 注入顺序全部归 t3 的 `document-controller`（resolver 不依赖文档模型，避免反向依赖引擎类型）。对应 REQ-0180 |

### 0.4 验收流程约束：引擎 API 变更后必须先 build 依赖再 typecheck UI

`packages/ofdrw-viewer-ui/tsconfig.json` 的 `paths` 指向 `../ofdrw-viewer-engine/dist/index.d.ts` 与 `../ofdrw-viewer-crypto/dist/index.d.ts`，而不是源码。

因此：**引擎/密码库公共 API 有变更时，必须先 `build` 依赖，再 `typecheck` UI，否则是假失败**（例如引擎新增 `getFontResources` 后，UI 仍读到旧 `dist`，会报「`getFontResources` 不存在在类型上」的假失败）。全团队（impl-core / ui-impl / qa-engineer / integrator）验证一律按此顺序：

```bash
pnpm -C packages/ofdrw-viewer-engine build
pnpm -C packages/ofdrw-viewer-crypto build
pnpm -C packages/ofdrw-viewer-ui typecheck
```

（本工作区已实测：未 build 时 UI typecheck 报 168 条 `TS2307`；build 后为 0。）

## 1. 引擎契约（设计 §3.6、§9）

### REQ-001 新增 `DocumentFontResource` 类型

- **文件**：`packages/ofdrw-viewer-engine/src/api/ui-types.ts`
- **要求**：与设计 §3.6 **逐字一致**的只读接口：

```ts
export interface DocumentFontResource {
  readonly id: string;
  readonly fontName: string;      // OFD FontName
  readonly familyName?: string;   // OFD FamilyName
  readonly charset: string;       // unicode / prc / big5 / symbol
  readonly serif: boolean;
  readonly bold: boolean;
  readonly italic: boolean;
  readonly fixedSize: boolean;
  readonly fontFile?: string;     // 有内嵌字体时给出
  readonly documentLevel: boolean; // 来自 DocumentRes/PublicRes 时为 true

```

- **派生规则**：字段来自 `packages/ofdrw-viewer-engine/src/model/types.ts` 的 `FontResource`；映射必须保持 `charset` 原样字符串、缺省 `familyName`/`fontFile` 时**省略字段**（不写 `undefined`）。
- **验收**：`DocumentFontResource` 的每个可选字段在值缺失时不出现（`'familyName' in resource === false`）。

### REQ-002 新增 `DocumentFontResourcesOptions` 与 `getFontResources` 签名

- **文件**：`packages/ofdrw-viewer-engine/src/api/ui-types.ts`
- **要求**：`OFDDocumentApi` 增加：

```ts
export interface DocumentFontResourcesOptions {
  signal?: AbortSignal;
}

getFontResources(
  options?: DocumentFontResourcesOptions,

```

- **验收**：`OFDDocumentApi` 上除 `getFontResources` 外**没有**其它新增字体相关成员（=F8）。

### REQ-003 实现 `OFDDocument.getFontResources()`

- **文件**：`packages/ofdrw-viewer-engine/src/api/document.ts`
- **要求**：
  1. 数据源只读打开阶段已解析的 `this.documentResources.fonts`（`DocumentResourceIndex`，见 `packages/ofdrw-viewer-engine/src/resource/types.ts`）——**零额外 IO**，不触发字体/页面加载；
  2. 顺序：**按 `id` 升序排序**（用字符串比较 `a.id < b.id`；不用数字排序、不用 `localeCompare`）。**不得**依赖 `Map` 插入顺序——它取决于 `PublicRes`/`DocumentRes` 的 XML 书写次序，跨文档不稳定（C10）；
  3. `id` 用归一化后的十进制资源 ID（Map 的键）；
  4. 可重复调用，每次返回新数组（调用方修改不影响后续）；
  5. 打开期间 `signal` 中止 → 以 `OFD_ABORTED` 拒绝；文档关闭后调用 → 以 `OFD_CLOSED` 拒绝；
  6. 文档没有字体声明 → `resolve([])`，不抛错。
- **验收**：见 REQ-004。

### REQ-004 引擎导出与单测

- **文件**：`packages/ofdrw-viewer-engine/src/index.ts`、`packages/ofdrw-viewer-engine/test/api/font-resources.test.ts`

## 2. `FontSource` 与选项（设计 §3.1、§3.2）

### REQ-005 `FontSource` 增加 `local` 态

- **文件**：`packages/ofdrw-viewer-ui/src/font.ts`
- **要求**：在现有四态（`data` / `url` / `path` / `filePath`）后追加：

```ts
| {
    /** 本机字体名：PostScript 名、英文名或中文名；数组按顺序尝试，命中即停止。 */
    readonly local: string | readonly string[];
    /** 覆盖读到的字体面 family；缺省用字体面自身的 family。 */
    readonly family?: string;
  }
```

- **约定**：
  - `local` 与其它来源**同层**：写在 `default` 里就是默认字体候选，写在 `supplementary` 里就是补字候选；
  - `local` 为空字符串 / 空数组 → 视为非法来源，走 `onError`（不抛到宿主）；
  - 宿主可直接写 PostScript 名（`SimSun`）精确指定。
- **验收**：类型层面 `Extract<FontSource, { local: unknown }>` 存在；运行时对空值报错。

### REQ-006 新增 `LocalFontsOptions` 与 `ViewerFontOptions.localFonts`

- **文件**：`packages/ofdrw-viewer-ui/src/font.ts`
- **要求**：与设计 §3.2 一致：

```ts
export interface ViewerFontOptions {
  readonly default?: readonly FontSource[];
  readonly supplementary?: readonly FontSource[];
  readonly loader?: FontSourceLoader;
  readonly aliases?: FontAliasTable;
  /** 本地字体能力配置；省略等价于「关闭 + 不展示开关」。 */
  readonly localFonts?: LocalFontsOptions;
}

export interface LocalFontsOptions {
  /** 是否展示「使用本机字体」开关；缺省 false，false 时整个能力不可见。 */
  readonly enabled?: boolean;
  /** 宿主默认值：用户从未做过选择时生效；缺省 false。 */
  readonly defaultEnabled?: boolean;
  /** 是否把用户选择记在 localStorage；缺省 true。 */
  readonly remember?: boolean;
  /** 单个文档最多查询多少个文档声明字体；缺省 8。 */
  readonly maxFonts?: number;
  /** 授权确认框文案覆盖（例如内网统一口径）。 */
  readonly consentText?: string;
}
```

- **默认值**：`enabled=false`、`defaultEnabled=false`、`remember=true`、`maxFonts=8`、`consentText=undefined`。
- **校验**：`maxFonts` 非有限数或 `< 1` 时按 8 处理（不抛错）；`maxFonts` 上限钳到 32（防止误配导致长查询）。
- **验收**：`fonts` 省略、`fonts.localFonts` 省略、`fonts.localFonts={}` 三种情况下 `enabled` 生效值均为 `false`。

### REQ-007 开关生效值解析（唯一实现点）

- **归属**：**t3（ui-impl，viewer/状态层）**；`local-fonts.ts` 只保留纯查询与类型定义，**不承载**开关生效值解析（C13 归属修正）。
- **文件**：`packages/ofdrw-viewer-ui/src/viewer.ts`（唯一实现点）+ 必要的状态辅助模块
- **要求**：按设计 §3.2 表格实现，且**只在一个纯函数里解析**（便于单测）：

| 条件 | `enabled`（生效值） | `visible`（是否展示开关） |
| --- | --- | --- |
| `fonts.localFonts` 未配置 | `false` | `false` |
| `fonts.localFonts.enabled !== true` | `false` | `false` |
| 浏览器无 `queryLocalFonts` | `false` | `false` |
| 上述均通过且 `remember !== false` 且 localStorage 有用户选择 | 用户选择 | `true` |
| 否则 | `defaultEnabled === true` | `true` |

- **语义**：「宿主配置决定默认值，用户选择优先」。
- **验收**：纯函数单测覆盖 5 行表格 + 用户选择 `false` 覆盖 `defaultEnabled=true` 的组合（共 6 例）。

### REQ-008 持久化格式（privacy 约束）

- **归属**：**t3（ui-impl，viewer/状态层）**（C13 归属修正）；`local-fonts.ts` 不读写 localStorage。
- **文件**：`packages/ofdrw-viewer-ui/src/viewer.ts`（或同层状态辅助模块）
- **要求**：
  - 存储键：`ofd-viewer:local-fonts`（单一键，`try/catch` 包裹，隐私模式下读写失败静默降级为「无记忆」）；
  - 值：`{"enabled": boolean, "notified": boolean}`（仅布尔值，**不存字体清单**，=设计 §7）；
  - `remember === false` 时**不读写** localStorage；
  - localStorage 不可用（`SecurityError`）时按「无用户选择」处理。
- **验收**：断言写出的 JSON 只含 `enabled`/`notified` 两个键。

## 3. 名字与变体识别（设计 §3.3、§3.4）

### REQ-009 新增 `local-font-names.ts` 与 `expandLocalFontCandidates`

- **文件**：`packages/ofdrw-viewer-ui/src/local-font-names.ts`（新增）
- **要求**：签名与设计 §3.3 逐字一致：

```ts
export interface LocalFontCandidates {
  readonly source: string;           // 原始声明，用于诊断
  readonly names: readonly string[]; // 候选 PostScript 名，按尝试顺序
  readonly base?: string;            // 命中内置表时的基础名
}

export function expandLocalFontCandidates(
  input: { fontName: string; familyName?: string; bold?: boolean; italic?: boolean },
  aliases: FontAliasTable,
): LocalFontCandidates;
```

- **约束**：纯函数——不访问 `window`/`navigator`/DOM，不产生 I/O。
- **验收**：函数在 node/jsdom 环境均可调用，相同输入返回结构相等的输出。

### REQ-010 展开顺序（三步，固定）

- **文件**：`packages/ofdrw-viewer-ui/src/local-font-names.ts`
- **要求**（严格按此顺序产出候选）：
  1. **别名表**：内置别名组 + `fonts.aliases`（与引擎同一份数据，复用 `composeFontAliases()`），把声明归一到同组名称，挑出其中的 **PostScript 写法（纯 ASCII）**；归一化必须复用引擎 `normalizeFontName()`（小写 + 去空白/连字符/下划线/逗号/点），中文名丢弃。
  2. **内置常见字体表**（REQ-012）：按归一化名**精确匹配**优先，再退到**包含匹配**（覆盖 `宋体(方正)`）；命中后产出「基础名 + 变体后缀」。
  3. **文档原始名**：原样保留作最后候选。
- **名称还原规则**（C11）：**内置表优先**；内置表未命中时**不推断大小写**——只保留已是合法 PostScript 形态的名称，不做「首字符大写」之类的改写；`names` 可同时保留归一化原名参与查询。
  - 依据：`queryLocalFonts({postscriptNames})` 大小写敏感（`Simsun` ≠ `SimSun`，见设计 §1.3）；草稿的「首字母大写」推断规则已导致黑体失效，属**阻断级**问题。
- **验收（写死）**：
  - `expandLocalFontCandidates({ fontName: '宋体' }, aliases).names` **含 `SimSun`** 且**不含 `Simsun`**；
  - `expandLocalFontCandidates({ fontName: '黑体' }, aliases).names` **含 `SimHei`** 且**不含 `Simhei`**。

### REQ-011 变体回退链

- **文件**：`packages/ofdrw-viewer-ui/src/local-font-names.ts`
- **要求**：按设计 §3.3 顺序：

```text
精确名:  <base>-Bold → <base>Bold → <base>-Bd        （粗体）
        <base>Light / -Light / Lt                    （细体）
        <base>-Medium / Medium                        （中粗）
        <base>-Black / Black / -Heavy                 （特黑）
        <base>-Italic / Italic                        （斜体）
基础名:  <base>
原始名:  文档声明的原样字符串
```

- 变体词来源：**先看声明名里的词**（`宋体 Bold`、`SimSun-Light`、`黑体 粗体`），**再看** `bold`/`italic` 属性；都没有则只尝试基础名；
- 单声明候选名总数上限 **6**（`MAX_CANDIDATES_PER_DECLARATION`，见 §0.2 C1）；重复候选去重且保持首次出现顺序；
- 基础名本身**永远**在变体候选之后（保证 `SimHei-Bold` 不存在时落回 `SimHei`）。

## 4. `local-fonts.ts`：权限、查询、读取（设计 §1、§5.3）

### REQ-0100 类型与状态

- **文件**：`packages/ofdrw-viewer-ui/src/local-fonts.ts`（新增）
- **要求**：

```ts
export type LocalFontStatus = 'prompt' | 'granted' | 'denied' | 'unsupported';

export interface LocalFontsStatus {
  readonly supported: boolean;   // 浏览器是否提供 API
  readonly enabled: boolean;     // 开关是否开启（用户选择或宿主默认值）
  readonly permission: LocalFontStatus; // 未申请 / 已授权 / 已拒绝 / 不支持
  readonly loading: boolean;     // 最近一次读取是否正在进行
}
```

- **验收**：`permission` 取值只能是这四个字符串；`LocalFontStatus`（单数）与 `LocalFontsStatus`（复数）不可混用或互相顶替（C6）。

### REQ-0110 能力检测

- **要求**：`typeof window.queryLocalFonts === 'function'` 才视为 `supported`；不依赖 UA 判断（Chrome 103+，兼容目标是 Chrome 67，=§8）。**不做 polyfill**。
- **验收**：删除/还原 `window.queryLocalFonts` 后 `supported` 随之变化；`SecurityError`（非安全上下文、`Permissions-Policy` 禁用、不透明源）统一按 `supported=false` 处理。

### REQ-0120 权限查询

- **要求**：用 `navigator.permissions.query({ name: 'local-fonts' })` 读取权限：
  - `granted` → `permission='granted'`；
  - `denied` → `permission='denied'`；
  - `prompt`、`Permissions` 不可用、`name` 不被识别（抛 `TypeError`）→ `permission='prompt'`；
  - 结果不计入 `supported`，仅影响状态文案与是否弹确认框。
- **验收**：`permissions.query` 抛错时回落 `prompt` 而不是 `unsupported`。

### REQ-0130 定向查询

- **要求**：
  - 唯一查询入口形如 `queryLocalFonts({ postscriptNames })`；**禁止**无参调用；
  - 候选名按顺序整批传入，命中即以「第一个非空结果」为准，命中即停止（不重复查询）；
  - 一个声明一次调用、候选截断到 6，天然满足单次调用的 `postscriptNames` 长度 ≤ **8**（`MAX_NAMES_PER_QUERY`，见 §0.2）；
  - 结果按「声明名 + 候选名列表」缓存（REQ-0160）；
  - `resolve([])`（未安装 / `denied`）不抛错，按「未命中」处理；**两者都不得写入会阻止后续重试的缓存**（未安装可缓存，`denied` 不缓存，见 REQ-0160 / C12）。
- **验收**：断言调用实参恒为 `{ postscriptNames: [...] }`，且数组长度 ≤ 6。

### REQ-0140 读取字节

- **要求**：
  - `FontData.blob()` → `readBlobBytes()`（`packages/ofdrw-viewer-ui/src/compat.ts`）读取为 `Uint8Array`；
  - 字节为空 → 跳过该字体面；
  - 单个字体面读取失败只跳过该面，不影响其它面（=§6.2）；
  - 字节只在内存中交给引擎，不写入任何存储（=§7）。
- **验收**：`readBlobBytes` 被调用而非 `blob.arrayBuffer()`；空 blob 不产出 `FontInput`。

### REQ-0150 查询复用 `AbortSignal`

- **要求**：使用本次 `open()` 的 `AbortSignal`；中途中止 → 丢弃结果、不写入缓存、不上报失败（与现有 `FontSourceResolver` 的 `AbortError` 口径一致）。
- **验收**：中止后 `resolve` 结果为空且缓存不含该键。

### REQ-0160 缓存与清空

- **要求**：
  - 缓存键 = `local:` + 声明名 + `|` + 候选名（`names.join(',')`），按该键缓存「已读好的 `FontInput`」；
  - 生命周期：**实例销毁**；同一文档重开不重复查询（=§6.2）；
  - **关闭开关时清空本地字体缓存**（与 `FontSourceResolver.cache` 的 `url`/`path` 缓存无关，后者不受影响）；
  - **缓存范围（C12）**：只缓存①正向命中结果、②「本机未安装」；**`denied` / `unsupported` / `prompt` 权限态一律不缓存**——权限是可变用户决定、不是字体存在性事实，缓存否定结果会让用户改完站点权限后本实例内永远无法恢复（只能刷新页面）；
  - 关闭开关时同样清空缓存（无论命中与否），以允许重新尝试。
- **验收**：单测断言「重开不重复查询」「关开关后再次开启会重新查询」。

## 6. `document-controller` 读取与注入（设计 §6.1、§6.3）

### REQ-0190 读取文档声明并筛选

- **文件**：`packages/ofdrw-viewer-ui/src/document-controller.ts`、`packages/ofdrw-viewer-ui/src/font.ts`
- **要求**：
  1. 在 `openWithOptions()` 内、`openDocument()` **之后**才能读到声明（`getFontResources()` 需要文档实例）——因此注入顺序为「先打开文档（无本机字体）→ 读声明 → 重开一次带本机字体」，**或**改为「先用声明缓存预读」的二段式；两种实现的对外可观察行为必须一致（首屏成型、不出现缺字跳变，=§2.2）。

- **验收**：单测断言「带 `fontFile` 的声明不产生 `local` 查询」。

### REQ-0200 注入顺序与合并

- **要求**：
  - `defaultFonts` = `[...宿主 default 解析结果, ...本机字体输入]`；
  - `supplementaryFonts` = `[...宿主 supplementary 解析结果, ...本机字体输入]`；
  - 只有非空才传字段（沿用现有 `resolveFonts()` 口径）；
  - 本机字体在两组中都参与（按声明所在层决定，见 REQ-0210 的分配规则：默认放 `supplementary`，宿主未配置任何 `default` 时放 `default`）。
- **验收**：断言引擎入参数组第一个 `family` 永远是宿主来源的 family（=F3/C2）。

### REQ-0210 失败口径（warning 矩阵）

- **要求**：与设计 §6.3 一致：

| 情形 | 行为 | 诊断 |
| --- | --- | --- |
| 浏览器不支持 | 来源跳过 | **不报 warning** |

## 7. `viewer` 公共 API 与授权流程（设计 §3.5、§4）

### REQ-0220 三个新方法

- **文件**：`packages/ofdrw-viewer-ui/src/viewer.ts`

```ts
getLocalFontsStatus(): LocalFontsStatus;
setLocalFontsEnabled(enabled: boolean): Promise<void>;
onLocalFontsStatusChange(handler: (status: LocalFontsStatus) => void): () => void;
```

- 不新增 `open()` 参数；`open()` 内部照常执行（=§3.5）；

- **验收**：三个方法在包根类型可见；退订后不再收到回调。

### REQ-0230 状态事件

- **要求**：状态变化同时通过 ①`onLocalFontsStatusChange`、②核心事件 `local-fonts:change`（`event.detail` 为 `LocalFontsStatus`）暴露；两者**同源**（一次变化各触发一次，顺序不限）；

- **验收**：一次 `setLocalFontsEnabled(true)` 只触发一次 `local-fonts:change`；侧栏文案与 `getLocalFontsStatus()` 一致。

### REQ-0240 授权流程（首次使用）

- **要求**：严格按设计 §4.1 的 ①~⑤：
  1. `open()` 按原有方式加载（不阻塞、不询问）；
  2. 文档就绪后，若 `supported && enabled && permission === 'prompt' && 本会话未打扰过` → 弹轻确认框；
  3. 用户点「允许」→ **在该 click 事件内同步调用** `queryLocalFonts()`（浏览器只接受用户手势）；
  4. 授权成功 → 记录状态 → 自动重开当前文档 → 恢复页码/缩放/旋转；
  5. 授权被拒 → 关闭开关、本会话不再询问、不回退任何内容（保持第 ① 步画面）。
- **约束**：**不得**在 `open()` 里静默申请权限；**不得**在没有用户手势时调用 `queryLocalFonts()`（实测必然 `SecurityError`）。
- **验收**：viewer 单测断言「没有用户手势时不调用 `queryLocalFonts`」。

### REQ-0250 重开与视图恢复

- **要求**：
  - 重开走现有 `open(source)` 路径，来源使用 `this.lastOpenSource`（=§3.5）；
  - 重开前记录 `{ pageNumber, scale, zoomMode, rotation, sidebarView }`，重开后按记录恢复（页码按 1-based，越界钳到 `[1, pageCount]`）；
  - 重开期间递增 `openToken`，旧打开的迟到结果必须丢弃（沿用现有机制）；
  - 重开失败只上报 error，不改变开关状态。
- **验收**：viewer 单测：在第 100 页、`scale=1.5`、`rotation=90` 时触发重开，重开后三者一致（=§10 T-V3）。

### REQ-0260 关闭开关

- **要求**（=§4.3）：清空本地字体缓存 → 立即重开当前文档（同样恢复视图）→ 浏览器授权保持「已授权」，再次开启**不弹授权框**；拒绝/不可用的反馈只在面板内展示，不发 toast（C7）。
- **验收**：关闭后 `defaultFonts` 中不再出现本机字体；再次开启不调用浏览器授权流程（`permissions` 已 `granted` 时直接查询）。

### REQ-0270 用户拒绝后

- **要求**（=§4.4）：开关置为关闭并写入「用户选择」；本会话内不再弹确认框；侧栏开关仍可手动打开，此时再次尝试（可能直接返回 `[]`，按「不可用」处理，**只在面板内提示**、不发 toast，见 C7）。
