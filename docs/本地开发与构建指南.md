# 本地开发与构建指南

本文讲解如何在本地构建、安装、测试本项目，以及如何启动各模块的开发环境。各包的 API 用法见各自的 `skills/`，兼容性约束见 [开发与兼容性规则](开发与兼容性规则.md)。

## 1. 环境准备

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | >= 22 | 根 `package.json` 的 `engines` 要求 |
| pnpm | 11.24.0 | 仓库声明的 `packageManager`，用 `corepack enable` 自动对齐 |
| Python 3 | 仅字体重建需要 | 跑 `scripts/build-demo-fonts.py` 时用，需 `fonttools[woff]` 与 `brotli` |

```bash
corepack enable
pnpm --version   # 应为 11.x
```

首次安装：

```bash
pnpm install
```

依赖装在仓库内的 `.pnpm-store`，这样可以避开只读的 home 目录并保证可复现。

## 2. 仓库结构

```
packages/ofdrw-viewer-engine   渲染引擎：解析、布局、绘制
packages/ofdrw-viewer-crypto   密码：解密、验签、证书
packages/ofdrw-viewer-ui       Web 阅读器：视图、交互、选择
packages/ofdrw-viewer-cli      命令行：转图、info、verify
demo/                          在线演示站（独立 workspace 包）
examples/                      无包管理的示例工程
docs/                          设计文档与契约
scripts/                       构建与校验脚本
```

依赖方向是单向的：`engine` 与 `crypto` 是底座，`ui` 依赖两者，`cli` 与 `demo` 消费它们。**`demo` 只消费已构建产物，不能反向成为库依赖。**

## 3. 构建顺序

**必须先构建 `engine` 和 `crypto`，再处理 `ui` 与 `demo`。** 原因是 UI 的 `tsconfig.json` 通过 `paths` 直接指向：

```
@ofdrw/ofdrw-viewer-engine -> ../ofdrw-viewer-engine/dist/index.d.ts
@ofdrw/ofdrw-viewer-crypto -> ../ofdrw-viewer-crypto/dist/index.d.ts
```

这两个 `.d.ts` 不存在时，`ui` 的类型检查会直接失败。

一键构建全部（按 workspace 拓扑序自动执行）：

```bash
pnpm build
```

只构建某个包：

```bash
pnpm -C packages/ofdrw-viewer-engine build
pnpm -C packages/ofdrw-viewer-crypto build
pnpm -C packages/ofdrw-viewer-ui build
pnpm -C packages/ofdrw-viewer-cli build
```

清理产物：

```bash
pnpm -C packages/ofdrw-viewer-engine clean
```

## 4. 各模块详解

### 4.1 engine（渲染引擎）

```bash
pnpm -C packages/ofdrw-viewer-engine build      # tsup + CDN 产物
pnpm -C packages/ofdrw-viewer-engine test       # 全量单测
pnpm -C packages/ofdrw-viewer-engine test:golden  # 黄金图回归
```

黄金图回归依赖真实样本与 `pdftoppm`（PDF 参考图）。样本缺失或工具不可用时相关用例会 skip，**skip 不等于通过**。批量跑真实样本：

```bash
GOLDEN_RUN_ALL=1 pnpm -C packages/ofdrw-viewer-engine exec vitest run test/e2e/run-all.e2e.test.ts
```

严格基线审计：

```bash
pnpm -C packages/ofdrw-viewer-engine test:audit
```

### 4.2 crypto（密码能力）

```bash
pnpm -C packages/ofdrw-viewer-crypto build
pnpm -C packages/ofdrw-viewer-crypto test
```

测试使用 `test/fixtures/crypto` 下的受保护 OFD 与证书私钥，部分向量需要本机 `openssl` 与 Java 环境；缺失时用例 skip。

### 4.3 ui（Web 阅读器）

```bash
pnpm -C packages/ofdrw-viewer-ui build        # tsup，产出 ESM/CJS/IIFE
pnpm -C packages/ofdrw-viewer-ui test         # vitest（jsdom）
pnpm -C packages/ofdrw-viewer-ui test:watch   # 监听模式
pnpm -C packages/ofdrw-viewer-ui typecheck
```

阅读器在 jsdom 下可跑大部分逻辑测试（文本层、选区、查找、打印导出、签章、来源）。涉及真实浏览器行为的验证请见 §6。

### 4.4 cli（命令行）

```bash
pnpm -C packages/ofdrw-viewer-cli build           # tsc 产出 dist/bin.js
pnpm -C packages/ofdrw-viewer-cli test            # 单测
pnpm -C packages/ofdrw-viewer-cli test:acceptance # 构建后黑盒验收
```

单文件可执行（SEA）打包：

```bash
pnpm -C packages/ofdrw-viewer-cli build:sea
pnpm -C packages/ofdrw-viewer-cli package:sea
```

构建后试跑：

```bash
node packages/ofdrw-viewer-cli/dist/bin.js info samples/doc1File.ofd
node packages/ofdrw-viewer-cli/dist/bin.js convert samples/doc1File.ofd -o out/
```

### 4.5 demo（在线演示站）

```bash
pnpm -C demo dev        # 开发服务器，改动 UI 源码热更新
pnpm -C demo build      # 产物输出到 demo-dist/
pnpm -C demo preview    # 预览构建产物
pnpm -C demo typecheck
```

`demo` 直接引用 `packages/ofdrw-viewer-ui/src` 源码构建，不走 UI 的 `dist`，所以改 UI 代码后刷新即可看到效果；但它通过 UI 的 `tsconfig paths` 引用 engine/crypto 的 `dist`，**因此仍需先构建 engine 与 crypto**。

部署到子路径时必须传 `BASE_PATH`，否则资源路径错位：

```bash
BASE_PATH=/ofdrw-viewer/ pnpm -C demo build
```

根路径部署：

```bash
BASE_PATH=/ pnpm -C demo build
```

字体资源需要重建时：

```bash
python3 scripts/build-demo-fonts.py
```

脚本会输出新的文件哈希名，改完同步更新 `demo/main.ts` 里的常量（脚本会打印新名字）。

### 4.6 examples（示例工程）

`examples/` 下的工程**不参与 workspace 安装**，各自按正式 npm 依赖声明，需要单独安装：

```bash
cd examples/engine-node
npm install
npm run dev
```

含 `engine-node`、`engine-h5`、`viewer-ui-react`、`viewer-ui-vue`。

## 5. 测试

### 5.1 常用命令

```bash
pnpm test                          # engine 单测（根级入口）
pnpm -C packages/ofdrw-viewer-ui exec vitest run        # UI 全量
pnpm -C packages/ofdrw-viewer-engine exec vitest run    # engine 全量
pnpm -C packages/ofdrw-viewer-cli test                  # CLI
```

提交前建议全跑一遍：

```bash
pnpm -r --if-present run typecheck
pnpm -C packages/ofdrw-viewer-ui exec vitest run
pnpm -C packages/ofdrw-viewer-engine exec vitest run
pnpm -C packages/ofdrw-viewer-cli test
```

### 5.2 兼容性卡口

扫描 engine/crypto/ui 的 `dist` 与 `demo-dist`，阻止 Chrome 67 无法解析的语法或不支持的 API 进入产物：

```bash
pnpm check-compat             # 源码级
pnpm check-compat:dist        # 要求产物存在，缺失直接失败
pnpm check-compat:self-test   # 自检规则本身
```

### 5.3 浏览器验证

Playwright 只用于本地开发与调试期间的一次性验证，**测试文件、配置、夹具与产物均不得提交**。规则见 [测试方案 §1.4](测试方案.md)。

验证完成后删除临时文件，把结论（实测数值、事件次数、DOM 结果）写进提交说明或设计文档。

## 6. 常见问题

**类型检查报找不到 `@ofdrw/ofdrw-viewer-engine`**

engine/crypto 尚未构建，`dist/index.d.ts` 不存在。先执行 `pnpm build`。

**`pnpm install` 后依赖不全或锁文件冲突**

用仓库声明的 pnpm 版本：`corepack enable && pnpm install`。不要手改 `pnpm-lock.yaml`，用 `pnpm add` / `pnpm remove` 更新。

**demo 页面白屏或资源 404**

部署到子路径时漏传 `BASE_PATH`；或字体文件哈希与 `demo/main.ts` 中常量不一致，重跑 `scripts/build-demo-fonts.py`。

**黄金图用例大量 skip**

缺少样本、`pdftoppm` 或引擎不可用。skip 表示未验证，不能当作通过。
