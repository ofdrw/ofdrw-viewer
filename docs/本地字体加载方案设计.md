# UI 本地字体加载（Local Font Access）方案设计

本文件是 [`字体配置方案设计.md`](./字体配置方案设计.md) 的补充章节：在原有「`data` / `url` / `path` / `filePath`」四种字体来源之外，增加第五种来源——**浏览器本地字体**（`queryLocalFonts`），让阅读器在宿主没有提供字体文件、或提供的替代字体与原稿差异较大时，尽可能用上用户机器上已安装的同名字体（典型场景：Windows 自带 `宋体`/`SimSun`、`黑体`/`SimHei`、`微软雅黑`/`Microsoft YaHei`）。

设计原则：**默认不生效、失败全回退**。浏览器不支持、用户未授权、被站点策略禁止、本机未安装时，该来源被跳过，其余来源与「未引入本功能」时完全一致。

API 依据：[MDN · Window.queryLocalFonts()](https://developer.mozilla.org/en-US/docs/Web/API/Window/queryLocalFonts)、[MDN · Local Font Access API](https://developer.mozilla.org/en-US/docs/Web/API/Local_Font_Access_API)、[Chrome for Developers · 使用本地字体实现高级排版](https://developer.chrome.com/docs/capabilities/web-apis/local-fonts)。

相关文档：[`渲染字体缺省方案设计.md`](./渲染字体缺省方案设计.md)（引擎侧字体选择与回退链）、[`网络获取委托设计.md`](./网络获取委托设计.md)（IO 分层）、[`packages/ofdrw-viewer-ui/skills/API.md`](../packages/ofdrw-viewer-ui/skills/API.md)。

## 1. 可行性验证（实测）

环境：Linux + Google Chrome 145（headless）+ 真实 Windows 字体目录（`simsun.ttc`、`simhei.ttf`、`msyh.ttc` 等），本地 HTTP（`127.0.0.1`，`isSecureContext === true`）。

### 1.1 能力与权限

| 场景 | 实测结果 | 设计含义 |
| --- | --- | --- |
| API 存在性 | `'queryLocalFonts' in window === true`，`FontData` 可用 | 用特性检测决定是否展示开关 |
| 权限状态 `prompt` + **无用户手势** | 抛 `SecurityError: User activation is required.`，浏览器不弹授权框 | **不能**在 `open()` 里静默申请；授权必须由用户点击触发 |
| 权限状态 `granted` + 无用户手势 | 直接成功返回字体面 | 已授权后刷新页面/重开文档**不再打扰用户** |
| 权限状态 `denied` | **resolve 为 `[]`，不抛错**；`navigator.permissions.query` 为 `denied` | `denied` 与「字体未安装」返回值相同，**必须**用 Permissions API 区分 |
| 未安装的名字 | `resolve([])`，不抛错 | 候选名逐个尝试即可，不需要额外探测 |
| `SecurityError` 其它成因 | 非安全上下文、`Permissions-Policy: local-fonts` 被禁用、不透明源（`file://`） | 统一按「不可用」处理，静默回退 |

### 1.2 返回数据

`FontData` 暴露 `postscriptName`、`fullName`、`family`、`style`，`blob()` 返回 `application/octet-stream` 的**完整 SFNT 字体数据**（TrueType/OpenType），正好是引擎 `FontInput.data` 需要的形式，不存在原设计 §4.1 所述「CSS 分片字体不能给引擎用」的问题。

| 字体面 | `postscriptName` | `family` | `style` | blob 大小 |
| --- | --- | --- | --- | --- |
| 宋体 | `SimSun` | 宋体 | Regular | 15 323 200 B |
| 新宋体 | `NSimSun` | 新宋体 | Regular | 15 323 200 B（同 `simsun.ttc`） |
| 黑体 | `SimHei` | 黑体 | Regular | 9 745 792 B |
| 微软雅黑 | `MicrosoftYaHei` | 微软雅黑 | Regular | 19 704 352 B |
| 微软雅黑 Bold | `MicrosoftYaHei-Bold` | 微软雅黑 | Bold | — |
| 等线 Bold | `DengXian-Bold` | 等线 | Bold | — |
| 楷体 / 仿宋 | `KaiTi` / `FangSong` | 楷体 / 仿宋 | Regular | — |

### 1.3 名字匹配规则（决定了 §3 的别名与变体设计）

`queryLocalFonts({ postscriptNames })` 是**区分大小写的精确匹配**，只有 PostScript 名能命中：

| 输入 | 结果 | 说明 |
| --- | --- | --- |
| `SimSun` | 命中 | 正确写法 |
| `SIMSun` / `simsun` | 不命中 | **大小写敏感** |
| `宋体` / `微软雅黑` | 不命中 | **中文名不能用于查询** |
| `Microsoft YaHei` | 不命中 | **不能带空格** |
| `SimHei-Bold` | 不命中 | 黑体只有 Regular，**变体后缀不能凭空推断** |
| `SimSun-ExtB` | 命中 | ExtB 是独立字体面，可作为生僻字补充候选 |
| `FangSong_GB2312` / `KaiTi_GB2312` | 不命中 | GB2312 后缀字体在 Win10/11 已移除 |
| `FZShuTi` / `FZYaoTi` | 不命中 | 真实 PS 名是 `FZSTK--GBK1-0` / `FZYTK--GBK1-0`，只能靠内置表 |

### 1.4 性能

| 操作 | 实测 |
| --- | --- |
| 首次 `queryLocalFonts({postscriptNames:[...]})` | 约 870–950 ms（一次性初始化开销） |
| 后续 `queryLocalFonts` | 2–4 ms |
| `blob()` + `arrayBuffer()`（单个 10–20 MB 字体） | 60–90 ms（本地磁盘映射） |
| 全量 `queryLocalFonts()` 枚举 | 本机 853 个字体面，全部 `blob()` 出 **2.5 GB / 19 s** |

**结论**：只按名字定向查询，**禁止**无参全量枚举；单次查询的候选名不超过 8 个。

## 2. 定位、目标与非目标

### 2.1 定位

| 层 | 职责 |
| --- | --- |
| engine | 新增只读 API `document.getFontResources()`：返回文档声明的字体清单；消费 `FontInput` 做字形选择 |
| **UI（本文件）** | 权限查询/申请、按文档声明定向查询本机字体、把字体字节注入 `defaultFonts`/`supplementaryFonts`、开关 UI 与状态持久化、授权后的文档重开 |
| site | 在字体档位里新增 `local`（「内置 + 本机字体」，`fonts.localFonts.enabled: true`），便于在演示站上直接试用；能力是否生效仍取决于浏览器支持与用户授权 |

### 2.2 目标

1. 用户开启开关并授权后，文档里声明的「宋体 / 黑体 / 微软雅黑 …」优先使用**本机同名字体**，观感更接近原稿；
2. 授权只需一次：已授权后刷新页面、重开文档都静默生效，不再弹确认框；
3. 授权后自动重开当前文档，并恢复页码、缩放、旋转，用户无感知；
4. 关闭开关立即回退到原有字体来源，不影响其它功能；
5. 浏览器不支持 / 用户拒绝 / 本机未安装时，行为与不引入本功能**完全一致**。

### 2.3 非目标

- 不做全量字体枚举，不提供「选择具体字体」的字体选择器（本设计只按文档声明自动匹配）；
- 不做字体子集化、格式转换、字体文件重写；
- 不改「文字只走字形轮廓、不调用 `fillText`」的渲染约束；
- 不在引擎侧实现本地字体发现（引擎不访问字体来源，见 `网络获取委托设计.md`）；
- 不引入字体热替换（不重开文档的方式替换已加载字体），统一走「重开 + 恢复视图」；
- 站点只新增一个字体档位（`local`）用于演示本能力，不新增独立的授权/字体选择 UI。

## 3. 公共 API 设计

### 3.1 `FontSource` 增加 `local`

```ts
export type FontSource =
  | { readonly data: ArrayBuffer | Uint8Array; readonly family?: string }
  | { readonly url: string; readonly headers?: Record<string, string>; readonly family?: string }
  | { readonly path: string; readonly family?: string }
  | { readonly filePath: string; readonly family?: string }
  | {
      /** 本机字体名：PostScript 名、英文名或中文名；数组按顺序尝试，命中即停止。 */
      readonly local: string | readonly string[];
      /** 覆盖读到的字体面 family；缺省用字体面自身的 family。 */
      readonly family?: string;
    };
```

- `local` 的核心用法是给**文档声明的名字**（`宋体`、`黑体`）做一个「本机优先」占位：UI 用别名表与变体回退链把它转换成真实 PostScript 名（§3.3）；
- 宿主也可以直接写 PostScript 名（`SimSun`）精确指定；
- `local` 与其它来源同层：写在 `default` 里就是默认字体候选，写在 `supplementary` 里就是补字候选。

### 3.2 阅读器选项 `fonts.localFonts`

```ts
export interface ViewerFontOptions {
  readonly default?: readonly FontSource[];
  readonly supplementary?: readonly FontSource[];
  readonly loader?: FontSourceLoader;
  readonly aliases?: FontAliasTable;
  /** 本地字体能力配置；省略等价于「关闭 + 不展示开关」。 */
  readonly localFonts?: LocalFontsOptions;
}

export interface LocalFontsOptions {
  /** 是否展示「使用本机字体」开关；缺省 false，false 时整个能力不可见。 */
  readonly enabled?: boolean;
  /** 宿主默认值：用户从未做过选择时生效；缺省 false。 */
  readonly defaultEnabled?: boolean;
  /** 是否把用户选择记在 localStorage；缺省 true。 */
  readonly remember?: boolean;
  /** 单个文档最多查询多少个文档声明字体；缺省 8。 */
  readonly maxFonts?: number;
  /** 授权确认框文案覆盖（例如内网统一口径）。 */
  readonly consentText?: string;
}
```

生效值解析（开关状态 `enabled`）：

| 条件 | 结果 |
| --- | --- |
| `fonts.localFonts` 未配置 或 `enabled !== true` | 能力不可见，`{ local }` 来源按不支持跳过 |
| 浏览器不支持 `queryLocalFonts` | 不展示开关，`{ local }` 来源按不支持跳过 |
| `remember !== false` 且 localStorage 有用户选择 | 用用户选择 |
| 否则 | 用 `defaultEnabled` |

即「**宿主配置决定默认值，用户选择优先**」。

### 3.3 名字识别与变体回退（新增 `src/local-font-names.ts`）

输入是引擎 `getFontResources()` 返回的声明（`fontName` / `familyName` / `bold` / `italic`），输出是一条有序候选名列表：

```ts
export interface LocalFontCandidates {
  readonly source: string;      // 原始声明，用于诊断
  readonly names: readonly string[]; // 候选 PostScript 名，按尝试顺序
  readonly base?: string;       // 命中内置表时的基础名
}

export function expandLocalFontCandidates(
  input: { fontName: string; familyName?: string; bold?: boolean; italic?: boolean },
  aliases: FontAliasTable,
): LocalFontCandidates;
```

展开顺序（实现口径：变体后缀 → 基础名 → 别名成员 → 原始名）：

1. **变体后缀**：命中内置表时，先按声明的风格词产出带后缀的精确名（`SimSun-Bold`、`SimHei-Light`）；
2. **基础名**：变体不存在时回落到不带后缀的基础名（实测 `SimHei-Bold` 不存在，必须能落到 `SimHei`）；
3. **别名成员**：内置别名组 + `fonts.aliases`（与引擎同一份数据）把 `宋体`/`黑体`/`微软雅黑` 归一到同组名称，挑出其中的 PostScript 写法（纯 ASCII；中文名丢弃）；
4. **文档原始名**：部分文档直接写 PostScript 名（`SimSun`），原样保留作候选，并**为其预留槽位**，避免被别名成员挤出上限（§3.3 候选上限 6）。
   > 该顺序与「先变体、再基础、后原始」一致：保证真实存在的原样声明不会因配额截断而丢失。

**变体回退链**（对应实测「`SimHei-Bold` 不存在」）：

```text
精确名:  <base>-Bold → <base>Bold → <base>-Bd        （粗体）
        <base>Light / -Light / Lt                    （细体）
        <base>-Medium / Medium                        （中粗）
        <base>-Black / Black / -Heavy                  （特黑）
        <base>-Italic / Italic                         （斜体）
基础名:  <base>
原始名:  文档声明的原样字符串
```

变体词来源：先看声明名里的词（`宋体 Bold`、`SimSun-Light`、`黑体 粗体`），再看文档的 `bold`/`italic` 属性；都没有则只尝试基础名。候选名总数上限 6 个，单文档候选字体上限 `maxFonts`（默认 8）。

### 3.5 阅读器方法

（注：`open()` 仍是唯一打开文档的入口；下列方法只影响「是否启用本地字体」与该功能的状态读取。）

```ts
/** 本地字体当前状态。 */
export interface LocalFontsStatus {
  /** 浏览器是否提供 API。 */
  readonly supported: boolean;
  /**
   * 开关是否开启（= 真正生效）。
   *
   * 与浏览器授权状态同步：`用户意向为开 && permission === 'granted'`。权限为 `prompt`
   * 或 `denied` 时恒为 `false`（见 §5.2「核心原则」）。
   */
  readonly enabled: boolean;
  /** 权限状态：未申请 / 已授权 / 已拒绝 / 不支持。 */
  readonly permission: 'prompt' | 'granted' | 'denied' | 'unsupported';
  /** 最近一次读取是否正在进行。 */
  readonly loading: boolean;
  /**
   * 能力是否对用户可见（决定「关于」对话框里是否展示开关）。
   *
   * 与 `enabled` 区分：`visible=false` 表示宿主未配置或浏览器不支持，开关整体不出现；
   * `enabled` 是「用户意向 && 浏览器已授权」算出的生效值，只有在 `visible=true` 时才有意义。
   */
  readonly visible: boolean;
}

class OFDViewer {
  /** 读取本地字体状态。 */
  getLocalFontsStatus(): LocalFontsStatus;
  /**
   * 设置开关并（在需要时）申请授权。
   *
   * `enabled=true` 时应在用户点击事件中直接调用：浏览器只接受用户手势内的权限申请。
   * 返回后如状态从未生效变为生效，内部会重开当前文档并恢复视图。
   */
  setLocalFontsEnabled(enabled: boolean): Promise<void>;
  /** 订阅状态变化；返回退订函数。 */
  onLocalFontsStatusChange(handler: (status: LocalFontsStatus) => void): () => void;
}
```

- 不新增 `open()` 参数：本地字体是否生效由开关状态决定，`open()` 内部照常执行；
- 重开使用现有 `open(source)` 路径（`this.lastOpenSource`），不引入新的字体热替换机制。

### 3.6 引擎新增 API

```ts
export interface DocumentFontResource {
  readonly id: string;
  readonly fontName: string;      // OFD FontName
  readonly familyName?: string;    // OFD FamilyName
  readonly charset: string;        // unicode / prc / big5 / symbol
  readonly serif: boolean;
  readonly bold: boolean;
  readonly italic: boolean;
  readonly fixedSize: boolean;
  readonly fontFile?: string;      // 有内嵌字体时给出
  readonly documentLevel: boolean; // 来自 DocumentRes/PublicRes 时为 true
}

class OFDDocument {
  /** 读取文档声明的字体资源清单；不加载页面、不解析字体。 */
  getFontResources(options?: { signal?: AbortSignal }): Promise<readonly DocumentFontResource[]>;
}
```

- 数据来自打开阶段已解析的 `DocumentResourceIndex.fonts`，**零额外 IO**；
- 只反映「文档声明了什么」，不反映运行时的字体解析/回退结果；
- 关闭后以 `OFD_CLOSED` 拒绝，取消后以 `OFD_ABORTED` 拒绝。

> 本设计与后续实现均以此签名冻结；引擎侧不再增加其它字体相关公开 API。

## 4. 交互流程

### 4.1 首次使用（未授权）

```text
① open()  →  按原有方式加载文档（URL/data 字体照常生效，可能缺字）
                ↓
② 若 supported && enabled && permission === 'prompt' && 本会话未打扰过
                ↓
③ 弹出轻确认框：「使用本机字体」「允许阅读器使用本机已安装的字体，让文档显示更接近原稿。」
   按钮：[允许] [不允许]
                ↓
④ 用户点「允许」→ 在该 click 事件内同步调用 queryLocalFonts()（浏览器弹授权框）
                ↓
⑤ 授权成功后：记录状态 → 自动重开当前文档 → 恢复页码/缩放/旋转
   授权被拒：关闭开关、本会话不再询问、不回退任何内容（文档保持 ① 的结果）
```

要点：

- **不在「加载文档之前」询问**：实测无手势调用必然 `SecurityError`，浏览器授权框也弹不出来；因此改为「先按原有方式打开，再在文档就绪后询问」；
- 重开时必须恢复视图，否则用户翻到第 100 页会被送回首页。

### 4.2 已授权后再打开

```text
open() → 读取字体声明 → 直接定向查询本机字体 → 与 URL 字体一起注入 → 一次性成型渲染
```

不再弹确认框（浏览器侧同样已记住授权，实测无手势调用直接成功）。此时本地字体与 URL 字体的读取并行进行，不额外增加串行等待。

### 4.3 关闭开关

- 清空本地字体缓存，下一次 `open()` 只使用原有来源；
- 立即重开当前文档（同样恢复视图），让画面立刻回退；
- 浏览器授权保持「已授权」，再次开启不会弹授权框。

### 4.4 用户拒绝后

- 开关置为关闭并写入「用户选择」；
- 本会话内不再弹确认框；
- 「关于」里的开关仍可手动打开并再次尝试（浏览器可能直接返回空数组而不弹框，按「不可用」处理并在状态文案里提示）。

## 5. UI 设计

### 5.1 入口：「关于」对话框 + 文档打开时的确认框

用户接触这个能力有**两个入口**，职责不同：

| 入口 | 时机 | 作用 |
| --- | --- | --- |
| **授权确认框**（§5.2） | 文档打开后，若「能力可见 + 用户意向为开 + 浏览器权限仍为 `prompt` + 本会话未问过 + 跨会话未表态」 | 唯一的**首次授权**入口：点「允许」才在用户手势内申请浏览器权限 |
| **开关**（关于对话框内） | 用户主动打开工具栏「更多」→「关于」 | 事后**修改意向**：切换后立即生效并重读字体 |

开关在「关于」对话框里的位置：追加在版本信息（UI/引擎/密码库版本、User-Agent）与「开源软件许可」之后，作为一行 `dt`（标签「使用本机字体」）+ `dd`（`role="switch"` 开关 + 状态文案）。

| 项 | 说明 |
| --- | --- |
| 状态文案 | `未授权`（`prompt`）/ `已启用` / `未获得授权`（`denied`）/ `浏览器不支持`（`supported === false`） |
| 渲染条件 | `LocalFontsStatus.visible === false`（宿主未配置 `fonts.localFonts.enabled: true`）时**整行不渲染** |
| 开关禁用 | 仅浏览器不提供 API 时禁用并隐藏开关，只留原因文案 |
| 点击行为 | 调用 `viewer.setLocalFontsEnabled(!current)`，在同一对话框内立即刷新 `aria-checked` 与状态文案 |

> **为什么不做侧栏「设置」面板**：本机字体属于「环境能力」而非「阅读操作」，侧栏更适合放内容导航（缩略图/大纲/书签/签章/附件）。早期实现曾把开关放在侧栏 `settings` 视图，后按实际使用体验移入「关于」，`SidebarView` 也随之移除该取值（清单只保留五个内容视图）。

任务约定：**不新增工具栏按钮、不加 toast 引导、不在缺字时主动打扰**；授权只在文档打开时问一次，之后由用户在「关于」里自行调整。

### 5.2 确认框

复用内置 `DialogManager`（`UIDialogOptions`），`name: 'localFonts'`：

| 元素 | 内容 |
| --- | --- |
| 标题 | `使用本机字体` |
| 说明 | `允许阅读器使用本机已安装的字体，让文档显示更接近原稿。`（可由 `consentText` 覆盖） |
| 主按钮 | `允许` → 在 click 事件内同步调用权限申请 |
| 次按钮 | `不允许` → 关闭开关、记录本会话已拒绝 |
| Esc / 遮罩 | 视同「不允许」，但**不**写入用户选择（下次仍会询问） |

文案不出现 API 名、不列字体清单、不解释技术细节。

**触发条件**（`maybePromptLocalFontsConsent()`，出现在一次 `open()` 收尾处）：

```text
LocalFontsStatus.supported === true      // 浏览器提供 API
&& config.enabled === true               // 用户意向为开（defaultEnabled 或已记住的选择）
&& localFontsPermission === 'prompt'     // 浏览器权限尚未决定
&& !localFontsNotified                   // 本会话未问过
&& !hasLocalFontsBeenAsked()             // 跨会话未表态过
&& 当前没有其他对话框打开
```

**核心原则：开关状态与浏览器授权状态同步。**

`LocalFontsStatus.enabled` 不是「用户意向」的裸值，而是：

```ts
// viewer.ts：isLocalFontsActive(wanted, permission)
enabled = 用户意向为开 && permission === 'granted'
```

也就是说，**权限为 `prompt` 或 `denied` 时开关一律显示为关**。这样任何「用户拒绝授权」的情形都会让开关自动回到关闭态，用户点一下就能重新发起申请——不会出现「开在那里却不起作用」的假象。

四个状态字段的分工（`LocalFontsStatus`）：

| 字段 | 含义 | 与「开关」的关系 |
| --- | --- | --- |
| `visible` | 宿主是否配置了 `fonts.localFonts.enabled: true` 且浏览器提供 API | 为 `false` 时「关于」里整行不渲染 |
| `supported` | **仅**表示浏览器提供 `queryLocalFonts` | 为 `false` 时开关隐藏并禁用，只留原因文案 |
| `enabled` | 真正生效值：`用户意向 && permission === 'granted'` | **这就是开关的显示状态** |
| `permission` | 浏览器 `local-fonts` 权限：`prompt`/`granted`/`denied` | 决定 `enabled` 与状态文案 |

> 注入路径与显示值同源：`syncLocalFontsToController()` 用同一个条件
> （`config.enabled && permission === 'granted'`）决定是否生成 `{ local }` 来源，因此
> 「开关显示为开」与「字体真的被注入」永远一致。

**三种关闭方式的状态语义**：

| 用户操作 | 开关显示 | localStorage | 下次打开文档 |
| --- | --- | --- | --- |
| 点「允许」且授权成功 | 开 | 写 `{ enabled: true, notified: true }` | 静默生效，**不再询问** |
| 点「不允许」/ 浏览器拒绝授权 | **关** | **清除记录**（`localFontsPreference = undefined`） | **不再自动询问**；用户可点开关重新申请 |
| 按 Esc / 点遮罩 | 关（权限仍为 `prompt`） | **不写任何记录** | **仍会询问**（视为未表态） |

**为什么拒绝后要清除记录而不是写 `enabled: false`？**
写 `false` 会让「用户意向」永久停在关闭，而清除记录后意向回到 `defaultEnabled`——两者都表现为「开关是关的」，但清除记录不会让开关与浏览器实际权限（`denied`）产生分歧，也更便于用户之后重新开启。

**`hasLocalFontsBeenAsked()` 的判据**（满足任一条即**不再自动弹框**）：

1. `localFontsPermission === 'denied'` —— 授权失败过，重新授权必须由用户主动点开关；
2. 存在持久化的用户选择记录 —— 用户点过「允许」或「不允许」。

弹框时**只标记内存态 `localFontsNotified`，不写 localStorage**：`notified` 在弹框之前就会置位，若用它判断会把 Esc 关闭误当成「已表态」，导致用户再也不会被询问。

> `fonts.localFonts.remember === false` 时完全不读写持久化记录，每次打开都会重新询问。

**用户重新授权的路径**（拒绝之后）：
1. 打开「关于」→ 点开关；或调用 `setLocalFontsEnabled(true)`；
2. 阅读器在 click 事件内重新调用 `queryLocalFonts()`；
3. 若浏览器权限仍为 `denied`（用户没在站点设置里改过），Chrome **不会再次弹框**，调用会直接返回空数组或抛 `NotAllowedError`；此时开关保持关闭并显示「未获得授权」；
4. 用户需在浏览器「站点设置 → 本地字体」里改为允许，再点开关才能恢复。

### 5.3 状态与事件

- 状态变化通过 `onLocalFontsStatusChange` 与核心事件 `local-fonts:change`（`event.detail` 为 `LocalFontsStatus`）对外暴露；
- 「关于」对话框与外壳状态同源：两者都读 `UIShell.getState().localFonts`，由 `viewer.onLocalFontsStatusChange` 单向刷新，避免两处显示不一致；
- `LocalFontsStatus.supported` **只表示浏览器是否提供 API**，不混入「宿主是否配置」——否则宿主未启用时会被误报成「浏览器不支持」，把用户的排查方向带偏。能力是否整体生效由 `visible`（宿主显式启用）与 `supported` 共同决定。

## 6. 读取与注入

### 6.0 一次 `open()` 的完整时序

```
open(source)
  ├─① prepareLocalFontsForOpen()
  │    · queryLocalFontsPermission()  ← 纯查询，不申请权限
  │    · syncLocalFontsToController({ enabled: enabled && permission==='granted', maxFonts })
  ├─② resolveFonts()          ← 此时 fontDeclarations 是【上一次】读到的（可能为空）
  │    · 宿主 default/supplementary → fetch / loader
  │    · createLocalFontSources() → 按声明生成 { local }，排在宿主来源之后
  ├─③ openDocument({ ...fonts })                  ← 第一次打开
  ├─④ readFontDeclarations(document)              ← 打开后才有声明
  │    · document.getFontResources()（引擎零 IO）
  ├─⑤ needsLocalFontsReopen()?
  │    · enabled && 声明非空 → 带本机字体重开一次
  │    · 用 localFontsReopening 标志防递归
  └─⑥ refreshLocalFontsPermission() → maybePromptLocalFontsConsent()
       · 权限仍为 prompt 且本会话/跨会话均未表态 → 弹确认框
```

**为什么一次「打开」可能发生 3 次 `openDocument`**（这是设计选择，不是缺陷）：

| # | 时机 | 存在原因 |
| --- | --- | --- |
| ① | 首屏打开 | 声明未知，若尚未授权则无法注入，必须存在这一次 |
| ② | 补注入重开 | ④ 读到声明后，带上本机字体再打开一次 |
| ③ | 授权成功后重开 | 用户点「允许」后权限变为 `granted`，需要重新注入 |

三者语义不同，合并会让时序互相纠缠（早期实现曾因此出现「页面卡在 `opening`」的竞态）；重开使用的是已缓存的本机字体字节，没有网络开销，因此接受这个代价。每次重开都恢复页码、缩放、旋转（§4.1）。

> **约束**：`resolveFonts()` 在 `openDocument()` **之前**执行，而 `fontDeclarations` 只在打开**之后**才能读到。因此不能在 `openWithOptions()` 开头无条件清空 `fontDeclarations`——那样重开时 `{ local }` 来源会恒为空、字体永远注入不进去。跨文档隔离靠「每次打开后重新读取覆盖」保证。

### 6.1 数据流

```text
document.getFontResources()  →  声明清单（最多 maxFonts 个，优先无 fontFile 的）
        ↓ expandLocalFontCandidates(每次查询)
候选 PostScript 名  →  queryLocalFonts({ postscriptNames: [...] })
        ↓ 命中
FontData.blob()  →  readBlobBytes()  →  FontInput { data, family: <文档声明的 FontName> }
        ↓
defaultFonts / supplementaryFonts  →  引擎
```

- `family` 取**文档声明的 FontName**（如 `宋体`），使引擎评分「归一化名精确相等 = 200 分」命中，压过 URL 兜底字体的 0 分；
- 有内嵌 `fontFile` 的声明不参与本地字体查询（内嵌字体本来就优先，查询是浪费）；
- 本机字体**只注入 `defaultFonts`，不进入 `supplementaryFonts`**，且排在宿主配置的 `default` 之后（宿主显式配置优先）。
- 为什么不做双注入：引擎按 `default:N` 与 `supplementary:M` 分别创建 FontFace 且**不跨列表去重**（`font/provider.ts` 的 `loadDefaultFaces` / `loadSupplementaryFaces`，`readInput()` 无字节缓存），同一份 10–20 MB 中文字体被同时注入会解析两次、内存翻倍，回退链里还会出现重复字体面。本机字体是「替代/优先」语义而非「补字」语义，放默认候选即可。

### 6.2 缓存与取消

- 查询结果按「声明名 + 候选名列表」缓存到实例销毁，同一文档重开不重复查询；
- 关闭开关时清空本地字体缓存；
- 查询复用本次 `open()` 的 `AbortSignal`：文档切换后旧查询结果丢弃；
- `blob()` 读取失败只跳过该字体面，不影响其它字体。

### 6.3 失败处理

| 情形 | 行为 | 诊断 |
| --- | --- | --- |
| 浏览器不支持 | 来源跳过 | `W_FONT_MISSING`（与其它来源失败统一走 warning 通道，便于宿主诊断；能力是否可用另见 `getLocalFontsStatus().supported`） |
| 未配置 `fonts.localFonts` 或未开启 | 来源跳过 | `W_FONT_MISSING`（与现有本地来源失败口径一致） |
| 权限未授予（无手势调用） | 不读取，等用户点击确认框 | `W_FONT_MISSING` |
| 本机未安装 | 来源跳过 | `W_FONT_MISSING` |
| 读字节失败 / 空字体 | 跳过该字体面 | `W_FONT_MISSING` |

warning 的 message 只含字体名，不含字体字节、不含本机字体清单。

## 7. 安全与隐私

| 关注点 | 处理 |
| --- | --- |
| 指纹面 | 只做定向查询，不枚举；查询结果只进内存，不写日志、不写缓存存储 |
| 用户同意 | 依赖浏览器 `local-fonts` 权限；UI 额外一层轻确认，解释用途 |
| 持久化 | localStorage 只存一个布尔值与「已告知」标记，不存字体清单 |
| 权限策略 | 站点被 `Permissions-Policy: local-fonts=()` 禁用时按不支持处理 |
| 数据流向 | 字体字节只在内存中交给引擎渲染，不上传、不落盘 |
| 解析 | UI 不解析字体内部结构，交给引擎 fontkit |

## 8. 兼容性

- UI 兼容目标是 Chrome 67（`src/compat.ts`），`queryLocalFonts` 从 **Chrome 103** 起可用，**不需要也不做 polyfill**：能力检测失败即视为不支持；
- Chrome 67 没有 `Blob.prototype.arrayBuffer`，`blob()` 的字节必须经 `compat.ts` 的 `readBlobBytes()` 读取；
- 在 Chrome 67 / Firefox / Safari 上该功能整个不可见，行为与本设计引入前一致。

## 12. 已知边界与风险

1. **仅 Chromium 桌面端**：Firefox / Safari / 移动端永远走原有路径；
2. **首次授权必须由点击触发**：自动弹确认框只是 UI 层，浏览器授权框仍依赖用户点击「允许」；
3. **浏览器可能不持久化授权**：部分浏览器/隐私模式下每次会话都会重新提示，此时用户会在每次打开后收到确认框（可在 `remember` 基础上再让用户选「本次不再询问」）；
4. **同名不同形**：Windows `SimSun` 与 macOS `Songti SC` 字形宽度不同，不同机器观感会有差异；需要严格一致时仍应由宿主提供 `url` 字体；
5. **注入顺序**：宿主显式配置的字体优先于本机字体，避免宿主对版式的明确要求在支持该 API 的浏览器上被本机字体覆盖；
6. **重开代价**：授权/关闭开关会重开文档，大文档有短暂加载；用视图恢复降低体感；
7. **`getFontResources` 不含页级声明**：当前只返回文档级资源，页面级 `PageRes.xml` 中声明的字体不进入清单；
8. **字重变体命中不稳定**：`SimHei-Bold` 这类不存在的变体会落到基础名（SimHei Regular），观感上是「粗体请求用了常规字形」，不做合成加粗。
