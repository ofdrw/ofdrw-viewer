# UI 字体配置方案设计

本文件定义 `@ofdrw/ofdrw-viewer-ui` 的字体配置能力：宿主如何通过 URL 或字节向阅读器提供默认字体与补充字体、UI 如何把字体来源读取为字节后交给引擎、在线演示站（site）默认内置哪些 CDN 中文字体，以及由此带来的跨域、性能与降级口径。

引擎侧的字体来源优先级、评分、逐字形回退与替代字体显式 GID 限制见 [`渲染字体缺省方案设计.md`](./渲染字体缺省方案设计.md)；公共 API 签名见 [`packages/ofdrw-viewer-ui/skills/API.md`](../packages/ofdrw-viewer-ui/skills/API.md)；网络读取分层见 [`网络获取委托设计.md`](./网络获取委托设计.md)。

## 1. 定位、目标与非目标

### 1.1 定位

字体配置分三层职责：

| 层 | 职责 | 现状 |
| --- | --- | --- |
| engine | 消费字体字节，按四层来源选择主字体并逐字形回退 | 已支持 `defaultFonts`/`supplementaryFonts`/`fontProvider`/`aliases` |
| **本文件（UI）** | 把宿主声明的字体来源（URL/字节/loader）读取为 `FontInput[]`，并透传给引擎 | **缺失，本设计补齐** |
| site（在线演示） | 按本设计在浏览器端配置一组 CDN 中文字体 | 未配置，缺字体文档中文不显示 |

引擎的 `FontInput` 只有 `{ data, family? }`，且 `FontLibrary.readInput()` 明确不读取 URL/路径（遇到会报 `W_FONT_MISSING` 并跳过）。因此“用 URL 设置字体”这一能力只能落在 UI 层：UI 是浏览器中唯一的网络读取入口，这一分层与文档字节、根证书字节的现有做法一致。

### 1.2 目标

1. 宿主可以用 `url` 声明默认字体与补充字体，不必自己 `fetch`；
2. 同一份字体配置可通过 `data`（内存字节）或 `loader`（自定义读取，如 `filePath`）表达；
3. 字体读取失败不阻断文档打开，只产生 warning，其他字体来源照常生效；
4. 在线演示站开箱即用：打开缺字体的 OFD 时中文可正常显示，且默认不下载大体积整字体文件；
5. 不改变引擎语义：主字体选择、回退链、显式 GID 限制全部沿用引擎现有规则。

### 1.3 非目标

- 不在 UI 内做字体自动发现（不枚举系统字体、不调用 `queryLocalFonts`）；
- 不做字体子集化、格式转换、字体文件重写；
- 不改变“文字只走字形轮廓、不调用 `fillText`”的渲染约束；
- 不把字体文件打包进 npm 包（字体授权与体积由宿主决定）；
- 不修改 site 的示例文档生成流程。

## 2. 公共 API 设计

### 2.1 字体来源 `FontSource`

与 `CertificateSource` 保持同样的“四态”形态，便于宿主按来源类型复用同一套心智模型：

```ts
/** 单个字体来源。 */
export type FontSource =
  /** 已读好的字体字节。 */
  | { readonly data: ArrayBuffer | Uint8Array; readonly family?: string }
  /** 浏览器 fetch 读取；headers 与阅读器 requestInit.headers 合并，来源优先。 */
  | { readonly url: string; readonly headers?: Record<string, string>; readonly family?: string }
  /** 宿主自定义加载器读取（例如 Node/Electron/小程序）。 */
  | { readonly path: string; readonly family?: string }
  | { readonly filePath: string; readonly family?: string };
```

`family` 只用于诊断与别名匹配，不参与“这个字体能不能用”的判断；缺省时引擎按 `default-<index>` 命名。

### 2.2 阅读器选项 `fonts`

```ts
/** 阅读器字体配置。 */
export interface ViewerFontOptions {
  /** 默认字体：文档字体完全缺省时的替代字体，优先级高于 supplementary。 */
  readonly default?: readonly FontSource[];
  /** 补充字体：主字体存在但缺字时逐字形补齐。 */
  readonly supplementary?: readonly FontSource[];
  /** path/filePath 来源的读取器；未提供时这两类来源被忽略并 warning。 */
  readonly loader?: FontSourceLoader;
  /** 补充字体面别名组；用于让同名/别名文档字体命中补充字体。 */
  readonly aliases?: FontAliasTable;
}

/** 自定义字体加载器。 */
export type FontSourceLoader = (
  source: Extract<FontSource, { path: string } | { filePath: string }>,
) => ArrayBuffer | Uint8Array | null | Promise<ArrayBuffer | Uint8Array | null>;
```

接入点：

```ts
new OFDViewer({
  container: '#viewer',
  source: file,
  fonts: {
    default: [{ url: '/assets/fonts/NotoSerifSC-Regular.otf', family: 'Noto Serif SC' }],
    supplementary: [{ url: '/assets/fonts/NotoSansSC-Regular.otf' }],
  },
});
```

- `fonts` 与 `crypto` 同级：只在实例持有期间生效，修改后需重新 `open()`；
- 只传 `fonts` 不传 `source` 时仍按现有查询参数规则解析来源；
- 一次 `open()` 结束前，字体来源按 `url`/`path` 去重，同一 URL 只请求一次。

### 2.3 与引擎选项的映射

| UI `fonts` | 引擎 `OFDOpenOptions` | 说明 |
| --- | --- | --- |
| `default` | `defaultFonts` | 仅在 `data` 读取成功时传递；读取失败不传该字段 |
| `supplementary` | `supplementaryFonts` | 同上 |
| `aliases` | `aliases` | 原样透传，`FontLibrary` 用它做评分与显式 GID 判定 |
| `loader` | 无 | UI 内部使用，不进入引擎 |

`fontProvider` 不暴露在本设计中：需要“按 FontName 精准匹配”的宿主仍可直接使用引擎 API；UI 的 `fonts` 只覆盖“默认字体 / 补字”这一层简单场景。

## 3. 读取与传递流程

### 3.1 新增 `src/font.ts`

```ts
/**
 * 字体来源解析器：把一个或多个 FontSource 读取为引擎可用的 FontInput。
 *
 * 一个 DocumentController 持有一个实例；同一 URL 在实例生命周期内只读取一次。
 */
class FontSourceResolver {
  constructor(options: { readonly loader?: FontSourceLoader; readonly requestInit?: RequestInit });

  /**
   * 解析一组字体来源。
   *
   * @param sources 字体来源列表；空列表直接返回空数组，不产生任何请求
   * @param signal 取消信号，复用本次 open 的 AbortSignal
   * @returns 读取成功的字体字节；失败的来源被跳过并回调 onError
   */
  async resolve(
    sources: readonly FontSource[],
    signal: AbortSignal | undefined,
    onError: (source: FontSource, error: unknown) => void,
  ): Promise<FontInput[]>;

  /** 释放进行中的请求与缓存。 */
  dispose(): void;
}
```

读取规则：

1. `data`：直接透传（`ArrayBuffer` 转 `Uint8Array` 由引擎完成，UI 不复制）；
2. `url`：`fetch(url, { headers: mergeHeaders(requestInit.headers, source.headers), signal })`，非 `ok` 抛错；与文档 `requestInit` 共用请求头合并逻辑；
3. `path` / `filePath`：调用 `loader`，返回 `null` 视为读取失败；
4. 结果按来源键缓存：`url:<url>`、`path:<path>`、`filePath:<filePath>`；`data` 不缓存；
5. 进行中的请求也按来源键复用同一个 Promise，两个列表都引用同一 URL 时只请求一次；
6. 失败结果**不缓存**：本次 open 内不重试，下次 open 重新尝试。

### 3.2 接入 `DocumentController`

- `DocumentControllerOptions` 增加 `font?: ViewerFontOptions`；
- 在 `openWithOptions()` 中，构造引擎调用参数前先等待字体解析完成：

```ts
const [defaultFonts, supplementary] = await Promise.all([
  this.fonts.resolve(font?.default ?? [], signal, report),
  this.fonts.resolve(font?.supplementary ?? [], signal, report),
]);
```

- 只把**非空**结果作为字段传入，避免空数组触发引擎的多余加载分支；
- 字体解析与文档打开的顺序：先解析字体、再用它打开文档。若想缩短首屏等待，可选并行：同时发起 `openDocument` 与字体解析不可行（引擎入参必须在打开时确定），因此本条选择“串行 + 缓存”，第二次打开同一文档时字体已在缓存中；
- `close()` 不清字体缓存；`destroy()` 调用 `resolve().dispose()`，中止进行中的字体请求；
- 取消：字体请求复用 open 的 `AbortSignal`；`open()` 期间切换到新文档时旧信号被中止，旧字体读取随之取消。

### 3.3 失败与 warning

| 情形 | 行为 | 诊断 |
| --- | --- | --- |
| `url` 返回非 2xx / 网络错误 | 跳过该来源 | `W_FONT_MISSING` |
| `path`/`filePath` 但未配置 `loader` | 跳过该来源 | `W_FONT_MISSING` |
| `loader` 抛错或返回 `null` | 跳过该来源 | `W_FONT_MISSING` |
| `data` 类型非法 | 跳过该来源 | `W_FONT_MISSING` |
| 全部来源失败 | 不向引擎传字体字段 | 引擎随后按无字体处理 |

warning 统一通过阅读器 `onWarning`/`w-failed` 通道上报，`message` 只含来源 URL/路径与错误摘要，不含字体字节。字体读取失败不会中止 `open()`，也不产生 `onError`。

### 3.4 Web Component 与框架适配

- `<ofd-viewer>` 增加 `fonts` property（语义与 `crypto` 一致：实例创建时读取，实例存在后修改不重建）；
- 增加两个简写属性，便于裸 HTML 使用：
  - `font-default="<url>[,<url>]"`：逗号分隔的默认字体 URL；
  - `font-supplementary="<url>[,<url>]"`：逗号分隔的补充字体 URL；
  - 两个属性都是 `observedAttributes`，变更时销毁并按新属性重建实例（与 `src` 一致的行为）；
- React/Vue 适配层通过 `Omit<OFDViewerOptions, 'container' | 'source'>` 自动继承 `fonts`，无需改代码；
- 公共类型导出：`FontSource`、`ViewerFontOptions`、`FontSourceLoader`，并再导出引擎的 `FontInput`、`FontProvider`、`FontMatchRequest`、`FontAliasTable`。

## 4. 字体格式与引擎兼容性

引擎用 fontkit 解析字体字节，fontkit 2.x 内置 brotli，可直接解析 **`woff2`**。这一结论已用工作区 `fontkit@2.0.4` 实测：

| 格式 | 可解析 | 说明 |
| --- | --- | --- |
| `.ttf` / `.otf` | 是 | 完整字体，体积大（CJK 常用 8–20 MB） |
| `.woff2` | 是 | 需为**完整**字体（覆盖全部汉字），体积约为 ttf 的 25% |
| `.ttc` / `.otc` | 是 | 展开为多个字体面参与评分 |
| CSS 子集切片 | **否** | 见 §4.2 |

### 4.1 为什么 UI 不接受 CSS 中文字体方案

主流中文字体 CDN（Google Fonts、fontsource、lxgw-wenkai-webfont 等）提供的 `@font-face` 都是**按 unicode-range 切片的子集**：

| 方案 | 切片数 | 单个切片覆盖 | 结论 |
| --- | --- | --- | --- |
| Google Fonts `Noto Serif SC` | 101 个 `.woff2` | 每片几十到几百字 | 只能用 CSS 交给浏览器排版 |
| fontsource `chinese-simplified` | 1 个完整 CJK 片 + latin/cyrillic 等 | 约 7 900 字 | 可直接下载解析 |
| lxgw-wenkai-webfont | 97 个 | 单片约 90 KB | 只能用 CSS |

切片字体无法直接用作引擎字体输入：任一单独切片只覆盖极小一部分汉字，拼成一组会让 `FontLibrary` 把上百个字体面全部加载进内存并逐一评分。而 CSS 交给浏览器的排版只对 DOM 文本生效，引擎绘制的是字形轮廓，两者不互通。

**结论**：UI 的 `fonts` 只接受**完整字体文件**（单文件覆盖目标字符集），site 使用完整文件的极小体积替代品，见第 5 节。

### 4.2 字体名与评分的关系（实现与文档需注意）

引擎的评分规则是“归一化字体名精确相等 → 200，别名匹配 → 100，其余 0”。在没有精确来源时，`defaultFonts`/`supplementaryFonts` 中评分最高的候选成为主字体，因此**候选真实 family 命中 OFD 声明的 FontName 时会自动成为主字体**，不需要额外配置。

实测候选的真实名（fontkit `familyName`/`postscriptName`）：

| 候选 | 真实 family | 能命中的 OFD 声明的 FontName |
| --- | --- | --- |
| fontsource `noto-serif-sc` | `Noto Serif SC ExtraLight` | `Noto Serif SC`（需归一化后相等）、`Source Han Serif SC` 别名组 |
| fontsource `noto-sans-sc` | `Noto Sans SC Thin` | `Noto Sans SC`、`Source Han Sans SC` 别名组 |
| fontsource `noto-serif-tc` | `Noto Serif TC ExtraLight` | `Noto Serif TC` |
| fontsource `noto-sans-tc` | `Noto Sans TC Thin` | `Noto Sans TC` |
| Google Fonts 整 TTF `NotoSerifSC-Regular.ttf` | `Noto Serif SC` | `Noto Serif SC` |

fontsource 的 CJK 片在子集化时写入了错误的 name 表（`ExtraLight`/`Thin` 后缀），这让它与 `宋体`/`SimSun` 等常见文档字体声明无法精确匹配，只能走别名，或作为“无精确来源”时的主字体。若要精确命中，宿主应通过 `fonts.aliases` 补充别名组，例如：

```ts
fontAliases: [['宋体', 'simsun', 'notoserifscextralight', 'notoserifscextralightregular']]
```

`fonts.aliases` 会**替换**引擎内置别名表还是**追加**，需在实现时确认引擎语义（当前 `FontLibraryOptions.aliases` 缺省使用内置表，传入时整体替换）；为保证不丢失内置组，UI 侧应提供“追加”语义，即在内置表基础上拼接宿主提供的组。此项作为实现约束写入 §8。

排除项：

- `noto-sans-cjk-sc`（NPM）：400 个子集切片 + 8 个字重，合计数十 MB；
- jsDelivr `gh/lxgw/LxgwWenKai`：`fonts/*.ttf` 目录返回 403（文件过大被拒），不可用。

### 5.2 CDN 配置（当前作为本地兜底之后的回落来源，见 §5.5）

优先级：**A → B → C → D**。选择理由：

1. **A/Serif 优先**：OFD 公文常用宋体（衬线），A 的形态最接近 `宋体`/`SimSun`；
2. **A → B**：A 缺字时落到无衬线 B，保证“至少能看”；
3. **C/D 放最后**：繁体字体对部分简俗字反而缺字，且 A/B 已覆盖大部分繁通用字；
4. **E** 作为 `supplementary` 的首位，保证非中文标点字形来自同一字体家族、风格一致；
5. 不把 700 字重放进默认配置：加重体名单会翻倍体积，默认只解决“有没有字”，不解决“像不像”。

`site/main.ts` 目标配置（**历史方案**，CDN 候选调研仍有效，实际实现已改为 §5.5 的纯本地双字体）：

```ts
/** 在线演示站内置字体来源；CDN 不可达时由 UI 报 W_FONT_MISSING，文档其余部分照常显示。 */
const SITE_FONTS: ViewerFontOptions = {
  default: [
    { url: `${FONT_CDN}/@fontsource/noto-serif-sc@${FONT_VERSION}/files/noto-serif-sc-chinese-simplified-400-normal.woff2`, family: 'Noto Serif SC' },
  ],
  supplementary: [
    { url: `${FONT_CDN}/@fontsource/noto-serif-sc@${FONT_VERSION}/files/noto-serif-sc-latin-400-normal.woff2` },
    { url: `${FONT_CDN}/@fontsource/noto-sans-sc@${FONT_VERSION}/files/noto-sans-sc-chinese-simplified-400-normal.woff2` },
    { url: `${FONT_CDN}/@fontsource/noto-sans-sc@${FONT_VERSION}/files/noto-sans-sc-latin-400-normal.woff2` },
  ],
};
```

默认命中路径：示例文档声明 `宋体` → 引擎走别名找到 A → 若无别名命中则 A 作为“无精确来源”的主字体 → 缺字时进入 B。

**首屏成本**：`default` 只有 A（1.44 MB）；`supplementary` 的 B 只有在主字体缺字时才会被逐字形查询，但字体面需在首次解析时加载。若首屏带宽敏感，可把 B 也放进 `default` 的第二位（同层按评分选择，不会抢 A 的主字体资格，但会预加载），或保持现状以“缺字时才值得下载”为原则。

| --- | --- | --- | --- | --- |
| 衬线兜底 | 思源宋体（Noto Serif CJK SC） | `Noto Serif CJK SC` / `NotoSerifCJKsc-Regular` | `site/public/fonts/source-han-serif-sc.<hash>.woff2`，11 109 788 B（约 10.6 MiB） | SIL OFL 1.1 |
| 无衬线兜底 | 文泉驿微米黑 | `WenQuanYi Micro Hei` / `WenQuanYiMicroHei` | `site/public/fonts/wqy-microhei.<hash>.woff2`，1 118 044 B（约 1.07 MiB） | Apache-2.0 |

选择理由：

1. **覆盖真实文档声明**：OFD 普遍声明 `宋体`/`SimSun`（衬线）或 `黑体`/`SimHei`/`微软雅黑`（无衬线）。
   单一字体无法同时贴合两类版式，双字体分别承接；
2. **授权可分发**：思源宋体 OFL、文泉驿微米黑 Apache-2.0，均可随站点分发；
3. **体积权衡**：完整思源宋体 TTC 单面 24 MB、WOFF2 压缩后 16.6 MB；只保留 CJK 基本区
   `U+4E00–9FFF`（20 992 字）+ 标点/全角/基本拉丁/常用符号后为 10.6 MB（22 078 字符 / 39 036 字形，
   实测 `中`/`国`/`来`/`黑` 可渲染）。文泉驿子集 1.07 MB（22 020 字符 / 33 798 字形）。
   ExtA–E 不保留：生僻字仍会 `W_GLYPH_MISSING`，需要时追加 `supplementary`；
4. **可复现**：`scripts/build-site-fonts.py` 负责「TTC 抽面 → pyftsubset 子集化 → woff2」，
   依赖 `fonttools[woff]` + `brotli`；来源、子集范围与重新生成命令记录在 `site/public/fonts/NOTICE.md`。

加载优先级（`site/main.ts` 的 `SITE_FONTS`，路径用 `import.meta.env.BASE_URL` 拼接，兼容 Pages 子路径）：

```ts
// 文件名内嵌 sha256 前 8 位：内容一变文件名就变，可长期强缓存。
const LOCAL_SERIF_FILE = 'fonts/source-han-serif-sc.8d948a48.woff2';
const LOCAL_SANS_FILE = 'fonts/wqy-microhei.cdece858.woff2';

const SITE_FONTS: ViewerFontOptions = {
  default: [{ url: siteAsset(LOCAL_SERIF_FILE), family: 'Noto Serif CJK SC' }],
  supplementary: [{ url: siteAsset(LOCAL_SANS_FILE), family: 'WenQuanYi Micro Hei' }],
  aliases: [
    ['宋体', 'simsun', 'nsimsun', '新宋体', 'notoserifcjksc', 'notoserifsc', 'sourcehanserifsc', '思源宋体'],
    ['黑体', 'simhei', 'heiti', '微软雅黑', 'microsoftyahei', 'wenquanyimicrohei', 'wenquanyimicroheimono', '文泉驿微米黑'],
  ],
};
```

两个字体子集都同时覆盖基本拉丁与常用标点，因此不再配置西文补字来源；站点不引入任何外部 CDN。
代价是本地文件缺失/损坏时中文无法显示（只产生一条 `W_FONT_MISSING`），已在 `site/README.md` 说明。

别名衔接（§8 约束 1：UI 的 `fonts.aliases` 为「内置组 + 追加」）：

- 引擎内置的 `宋体` 组已含 `notoserifcjksc`/`sourcehanserifsc`，思源宋体无需追加也能命中；
  追加组用于把 CDN 回落字体（`notoserifsc`）也并入该组；
- 文泉驿**不在**内置表中，必须通过无衬线组把 `黑体`/`simhei`/`微软雅黑` 与其真实名
  `wenquanyimicrohei` 连起来，否则声明「黑体」的文档只能作为“无精确来源”的主字体参与评分，
  与其他 0 分候选顺序竞争。

验证（真实浏览器 + 真实文档，屏蔽远程字体请求模拟断网）：

| 场景 | 文档 | 结果 |
| --- | --- | --- |
| 本地思源宋体 | `拿来主义_page6.ofd`（只声明宋体、无 FontFile） | 正文可见，深色像素约 40.6 万，无 `W_FONT_MISSING` |
| 本地宋体 404 → CDN | 同上 | 正文可见，仅一条 404 触发的 `W_FONT_MISSING` |
| 不配字体 | 同上 | 整页空白（深色像素 0），`W_FONT_MISSING`：字体缺失 + 资源未加载 |
| 本地文泉驿 | 黑体样本（以 `透明度文字.ofd` 为底改 `Font="6"` 黑体、去内嵌） | 「黑体测试中文」可见（深色像素约 3.3 万），无 `W_FONT_MISSING` |
| 不配字体 | 黑体样本 | 空白（深色像素 0），`W_FONT_MISSING`：`FontName=黑体` |

**已知坑**：

- fontsource `Noto Serif SC` 简中片的真实 family 是 `Noto Serif SC ExtraLight`（子集化时写错了
  name 表），无法与 `Noto Serif SC` 精确匹配，只能走别名或“无精确来源”时的主字体；
  本地思源宋体的 family 为 `Noto Serif CJK SC`，靠内置别名组命中 `宋体`；
- 浏览器在本地字体同样缺失时会回退到系统字体，仅看“有像素”不足以证明本地字体生效；
  验证必须（a）核对字体请求全部命中本地且无 `W_FONT_MISSING`，（b）必要时屏蔽系统字体域名，
  或检查引擎 `getTextContent()` 中 `text.font.family`。

### 5.3 站点交互（可选）

在底部 dock 增加一个“字体”下拉，三档：

| 档位 | 配置 | 说明 |
| --- | --- | --- |
| `auto`（默认） | §5.2 配置 | 默认字体 + 补字 |
| `serif` | 仅 A + A' | 只用宋体，不加粗没有补字 |
| `off` | `fonts: undefined` | 复现“无字体”现象，便于对比问题 |

切换档位需要重建实例（`fonts` 只在实例创建时生效），实现上直接设置组件 `font-default`/`font-supplementary` 属性触发重建，或销毁后重建 `<ofd-viewer>`。

### 5.4 已知边界

- **CORS**：字体 CDN 必须返回 `Access-Control-Allow-Origin`，否则浏览器 `fetch` 失败；jsDelivr 与 Google Fonts 均满足；
- **CDN 可用性**：不可达时只产生 warning，文档其余内容正常显示；文档不内置字体文件回退；
- **`font-display` 无关**：引擎用字形轮廓绘制，不走 CSS 字体加载，因此无需处理字体闪烁（FOUT/FOIT）；
- **体积**：默认配置首屏最多约 2.5 MB 字体（A + latin），在移动网络上可能需要数秒；后续打开文档命中缓存；
- **字形覆盖**：fontsource 简中片约 7 947 字，不含 ExtA（`U+3400–4DBF`）与部首扩展块；生僻字仍会 `W_GLYPH_MISSING`，需要时改用方案 F 的整字体；
- **字体授权**：Noto 系列为 OFL，可在站点中通过 CDN 引用；若宿主离线部署，需自行承担字体文件分发。
- **本地字体**（§5.5）：`site/public/fonts/` 随静态产物发布，不进入 npm 包；本地 404 只产生一次 `W_FONT_MISSING` 后回落 CDN。

## 6. 安全与隐私

- 字体 URL 一律由宿主显式声明，UI 不自动发现、不拼接第三方地址；
- `url` 读取复用 `requestInit.headers`，跨域请求遵循浏览器默认凭据策略（`same-origin`），不会携带 cookie 到第三方 CDN；
- 读取结果只保留在内存，不进缓存 API、不写 IndexedDB；
- 单个字体字节上限沿用引擎 `limits.maxFontBytes`（默认 64 MiB），超限由引擎拒绝并 warning；
- 字体解析异常由引擎捕获，UI 不执行字体文件内的任何数据。

## 8. 实现约束汇总

1. `fonts` 的 `aliases` 采用**追加**语义：内置别名组 + 宿主组，避免宿主配置覆写内置表；
2. 只向引擎传非空 `defaultFonts`/`supplementaryFonts`，不传空数组；
3. URL 去重按完整 URL 字符串（含 query），不按字体名；
4. 字体读取失败只 warning，不抛错、不阻断 `open()`；
5. `DocumentController` 的 resolver 在 `destroy()` 时 `dispose()`，`close()` 时保留缓存；
6. Web Component 的简写属性变更走“销毁重建”路径，与现有 `src` 行为一致；
7. 文档同步：`packages/ofdrw-viewer-ui/skills/API.md`（选项表）、`skills/SKILL.md`（删除“UI 没有字体配置项”的表述）、本文件与 `渲染字体缺省方案设计.md` 的交叉引用。
