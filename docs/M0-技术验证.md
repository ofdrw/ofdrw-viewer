> 任务：T1 工程骨架与跨模块契约冻结（M0 技术冒烟）
> 日期：2026-10-21
> 运行环境：Node v26.10.0 / linux x64 / pnpm 11.24.0
> 脚本：[scripts/spike/m0-smoke.mjs](../scripts/spike/m0-smoke.mjs)
> 产物：`scripts/spike/.artifacts/m0-summary.json`、`scripts/spike/.artifacts/m0-glyph.png`

## 1. 验证目标

在真实 OFD 样本上验证 v1 方案的 4 个高风险技术假设：

1. 能否不整包解压，按 EOCD → 中央目录 → 单条目读取并 inflate；
2. 浏览器/Node 通用的 `DecompressionStream('deflate-raw')` 是否与 `fflate` 回退字节一致；
3. `fontkit` 能否解析 OFD 内嵌 TTF/CFF、以及无 cmap 的剥离子集，并按显式 gid 取轮廓；
4. `@napi-rs/canvas` 能否把字形轮廓稳定画成 PNG，作为 Node 黄金图 harness 的基础。

## 3. 结果

### 3.1 ZIP 随机读取

样本：`ofd_pdf_match/1.ofd`（只读，16,048 bytes）。

| 项 | 结果 |
| --- | --- |
| EOCD 偏移 | 16,026 |
| 中央目录条目数 | 28 |
| 压缩方法 | 0（stored）与 8（deflate） |
| 读取条目 | `Doc_0/Document.xml` |
| 压缩/解压大小 | 299 → 646 bytes |
| `DecompressionStream('deflate-raw')` | 支持，且与 fflate 输出逐字节一致 |

结论：自研 ZIP 读取路径可行；M0 脚本已独立实现 EOCD/中央目录/局部头/raw inflate，不依赖尚未实现的 `ZipReader`。

### 3.2 字体解析与字形轮廓

扫描 `ofd_pdf_match/` 下全部 OFD：共 60 个 `.ttf/.otf/.ttc/.cff` 条目。

| 类别 | 样本身份 | 关键结果 |
| --- | --- | --- |
| 带 cmap TTF | `ano.ofd` → `Doc_0/Res/font_91_91.ttf`（SimSun） | upem=256，28,762 glyphs；`U+4E2D` → gid 1117，34 条路径命令 |
| 无 cmap 剥离子集 | `doc1File.ofd` → `Doc_1/Res/font_1.otf` | 无 cmap；显式 `getGlyph(11)` 取到 11 条路径命令 |
| CFF | `ano.ofd` → `Doc_0/Res/font_84_84.cff`（SimSun） | CFF 解析成功；`U+4E2D` → gid 1117，34 条路径命令 |
| TTC | 55 个样本未发现 | 选面逻辑留待 T4 用合成 fixture 覆盖 |

解析统计：60 个字体条目中 55 个可解析，5 个失败（扩展名与实际内容不符，fontkit 报 `Unknown font format`）：

- `intro-数科.ofd:Doc_0/Res/font_85_85.ttf`
- `intro-数科.ofd:Doc_0/Res/font_128_128.ttf`
- `intro-数科.ofd:Doc_0/Res/font_764_764.otf`
- `signout.ofd:Doc_0/Res/font_3_3.ttf`
- `zsbk.ofd:Doc_0/Res/font_766.ttf`

关键发现：

- 无 cmap 字体不能调用 `glyphForCodePoint`，必须按 `CGTransform.Glyphs` 的显式 gid 取轮廓；`getGlyph(gid)` 在 fontkit 2.x 可用。
- 子集字体中大量 gid 的轮廓为空是正常现象，不能以“轮廓为空”直接判定字体损坏；需结合 `CGTransform` 与 `Glyphs` 判断。
- cmap 可能把汉字映射到 gid 0（notdef）；取字形后必须检查 `glyph.id !== 0`，否则会画出空白。
- 字体扩展名不可信；`OFD_FONT_PARSE`/`W_FONT_MISSING` 必须有降级路径。

### 3.3 Canvas 字形渲染

用 `ano.ofd` 的 SimSun gid 1117 轮廓：

| 项 | 结果 |
| --- | --- |
| 画布 | 320 × 240 |
| 输出 | `scripts/spike/.artifacts/m0-glyph.png` |
| 文件大小 | 3,079 bytes |
| 缩放 | 0.715（按 bbox 适配 70% 画布） |
| 字形 bbox | 宽 194、高 235（字体单位） |

已人工查看 PNG：白色背景上黑色“中”字轮廓正确，无倒置/错位。说明“字体轮廓 → Canvas 路径 → PNG”链路可用。

## 4. 对 v1 实现的结论

1. **ZIP 层**：按需读取方案成立；T2 实现 `ZipReader` 时需覆盖 stored/deflate、data descriptor、CRC 校验、ZIP64 拒绝与限制检查。
2. **解压**：优先 `DecompressionStream('deflate-raw')`，不可用时回退 `fflate.inflateSync`；两者输出一致。
3. **字体层**：T4 必须以“字体资源 ID + 显式 gid”为主路径；cmap 仅作为有 cmap 字体的快速路径；缺字体/缺字形分别告警。
4. **Node 黄金图**：`@napi-rs/canvas` 可作为测试 harness 的画布；引擎核心仍只依赖 `Canvas2DLike`，不直接依赖 Node canvas。
5. **Web 优先**：M0 未引入 DOM；H5 渲染器通过 `createCanvas` 注入，Node 适配后续单独规划。

## 5. 风险与后续验证

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| ZIP64 / 加密 / data descriptor 样本未覆盖 | 真实包可能解析失败 | T2 用合成 fixture 覆盖；不支持时抛 `OFD_UNSUPPORTED_COMPRESSION`/`OFD_ENCRYPTED` |
| 5 个字体条目扩展名与内容不符 | 字体加载失败 | T4 捕获 `OFD_FONT_PARSE`，回退补充字体并上报 `W_FONT_MISSING` |
| 无 cmap 字体依赖 CGTransform | 文字可能整段缺失 | T4/T10 联调时用真实样本回归；缺 gid 时报 `W_GLYPH_MISSING` |
| TTC 未验证 | 部分文档字体失败 | T4 增加 TTC 合成 fixture，验证选面与 `fontIndex` |
| `@napi-rs/canvas` 与浏览器 Canvas 行为差异 | 黄金图与 Web 渲染偏差 | QA 用同一 DisplayList 双端渲染对比；差异记入测试方案 |
| 字体/图片缓存内存压力 | 大文档 OOM | 按 `DEFAULT_CACHE_OPTIONS` 做 LRU；回归时监控峰值 |
