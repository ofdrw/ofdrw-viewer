## 1. 重构前白盒事实

### 1.2 重构前选区链路的四条破坏路径

| 路径 | 代码依据 | 后果 |

| ① 端点页整页清空 | `text-layer.ts:303-307` → `replaceChildren`（`:1132`） | 原生 Selection 折叠；跨页复制少一整页 |

## 2. 目标架构（摘要）

权威定义见 [`页面缓存与文本层生命周期设计.md`](页面缓存与文本层生命周期设计.md) §4~§7；实施要点：

```text
页级缓存单元 = canvas + span + content/rows
构建：settle 150 ms 后启动；流水线 取文本 → specs(6.0ms) → rows(8.2ms) → 分帧 append(700 span/8ms) → ready
淘汰：viewer.trimCache() 唯一入口；页数 max(10, 2n+1)+pinPageCount；span 预算 B+pinnedSpans；单页上限 10 万
滚动：ready 页零 DOM；滚动帧零 getBoundingClientRect
选区：SelectionSnapshot 负责复制/高亮正确性；pin 只钉端点页（保 Shift 扩选）
      中间页被淘汰不影响快照；copy 事件用快照文本覆盖原生复制
```

| 机制 | 关键点 |
| --- | --- |
| 页状态机 | `idle / loading / splitting / building / paused / ready / failed`（权威文档 §4.1） |
| 构建时机 | 滚动中不构建首次访问页；停止 150 ms 后构建；pointerdown 优先（权威 §4.2） |
| 分帧 | 每帧 8 ms 预算、约 700 span；`DocumentFragment` 批量插入 |
| 单 span 成本 | ≤10 次 DOM 写（`cssText` + 2 dataset） |
| pin | 端点页 `{startPage, endPage}`；不可见时释放 canvas、保留 span/content |
| 快照 | 文本 + 每页行矩形 + 端点节点；< 0.1 MB/选区；矩形为 96 DPI 页坐标，**缩放/旋转不重算** |
| 布局变化 | 只更新图层变换/尺寸，不改 DOM、不清快照（§4.3） |
| 抑制 | 改 DOM 期间置 `suppressSelectionChange`，微任务后解除；禁止无条件忽略（§4.4 红线） |

## 3. 构建性能设计

### 3.1 单 span 成本：27~28 → 6~7 次 DOM 写

| 写项 | 现状（`text-layer.ts:138-175`） | 目标 |
| --- | --- | --- |
| `createElement` | 1 | 1 |
| `className` | 1 | 1 |
| `textContent` | 1 | 1 |
| 内联样式 | **18** | **1**（`cssText`：left/top/width/height/font-size/line-height/transform） |
| dataset | **6~7** | **1~2**（itemIndex；字符级再加 charIndex） |
| 插入 | 1（逐 span 插活 DOM） | 1（fragment 批量） |
| 合计 | **27~28** | **6~7** |

落地规则：

- 不变样式进 CSS：`.ofd-text-item` / `.ofd-text-char` 设 `position:absolute; transform-origin:0 0; margin:0; padding:0; border:0; white-space:pre; color:transparent; caret-color:transparent; cursor:text;`。
- `user-select` 上移到图层（`:1027-1030` 已具备），删除 `applyFeatureStates()` 的逐 span 循环（`:1160-1163`）。
- **恒等 transform 跳过写入**（`matrix(1,0,0,1,0,0)` / `rotate(0rad)`）。
- 删除 `dataset.pageNumber`（由图层 `data-page-number` 推导，`:1025`）与 `dataset.x/y/size/angle`。
- **legacy 复制路径改读内联样式**（`selection.ts:445-448`）：`parseFloat(span.style.left/top/fontSize)`，角度由 `style.transform` 的 `rotate(...)`/`matrix(a,b,...)` 解析。
- 页级属性（`data-page-number`、`data-dpi`、`data-selectable`、图层尺寸/transform）只在布局键变化时写一次。

### 3.2 分帧

- 每帧 **8 ms** 预算、约 **700 span**；单行 span 超过预算时按行整块处理（最密行 187 span）。
- dense 页 8331 span / 146 行 → 约 **12 帧**（每帧约 12 行）。
- 构建中 `append-only`：已建 span 永不移除，用户可选中已建部分。

| 方案 | 单帧 DOM 写 | 帧耗时量级（估算） | 首帧长任务 |
| --- | --- | --- | --- |
| 现状：同步整页、逐 span 插活 DOM | 22.5 万 | 30~75 ms + 一次大范围样式重算 | 有 |
| 同步整页 + fragment（不分帧） | 22.5 万 | 25~60 ms | 有 |
| 分帧 700 span + 27 写 | 1.89 万 | 2.5~6 ms | 无 |
| **分帧 700 span + ≤7 写** | **0.49 万** | **1~3 ms** | 无 |

> 估算假设：分离节点单次样式属性写 0.2~0.5 µs、`cssText` 单次 2~5 µs，未计首次布局。
> 必须用 §8 第 3 条的 `PerformanceObserver` 实测替换。

### 3.3 行划分 14.2 ms 拆分

- 现状 `buildTextRows()` 内先 `buildTextLayerSpecs()`（`geometry.ts:684-685`），同一任务 14.2 ms。
- 设计目标：拆为两个任务：`buildTextLayerSpecs(content)`（6.0 ms）+ `buildTextRowsFromSpecs(specs, content)`（推得 8.2 ms），每个 <16 ms。
  **实施偏离**：最终仍合并执行，理由见 §12 第 5 条；dense 样本合并耗时约 14.0 ms，低于 16 ms 预算。
- 顺带去重（不改变算法）：
  1. `shouldSplitChars()` 每 item 只算一次（现于 `geometry.ts:336, 622` 重复）；
  2. `spanNormalHeight()` 复用（现于 `:688, 694` 各算一次）；
  3. 去掉 `spans.map(...)` 中间数组（`:688, 690-695`）。

### 3.4 引擎 143 ms 的取舍

| 问题 | 结论 |
| --- | --- |
| 是否阻塞主线程 | **是**，`collectTextPageMm()` 同步执行（`engine/document.ts:1376-1430`） |
| 是否 Worker 化 | **本次不做**：引擎无 worker 入口，中间模型跨线程序列化会扩大改动面（引擎不在本任务范围） |
| 是否预取 | **不做主动预取**：只是把 143 ms 移到空闲时，仍可能撞上用户阅读/拖选 |
| 降低重复成本 | 设计预留 `textCachePages`（默认 = `pageCacheSize`）透传引擎 `cache.textPages`；**尚未实现**，见 §12 第 8 条 |
| 接受项 | 每页首次访问一次约 143 ms 长任务，列入已知限制与验收排除项 |

### 3.5 滚动帧成本对照

| 场景 | 现状 | 目标 |
| --- | --- | --- |
| 页内滚动（已建满） | 遍历全部行（`:944`）+ 1 次 `getBoundingClientRect()`（`:894`）+ 查找/选区同步（`:332-333`） | 直接跳过 |
| 两页交界 | 2 页各跑差量 + 2 次强制布局 | 2 次集合判断 |
| 页建满后 | 每帧仍有差量与测量 | 零 DOM、零测量 |

### 4.3 布局变化（缩放/旋转）的选区保护

t4 实测的“缩放/旋转丢选区”与滚动丢选区同源（§1.2 路径 ④），本设计用两道措施覆盖：

1. **结构消除**：页级构建后 `reflow()` 只改图层尺寸/变换（`applyLayerScale()`，`text-layer.ts:108-127`），
   **不再行增删**。因此缩放（1→1.5→2、2→1.5→1）与旋转（0/90/180/270）都不会移除锚点 span，
   原生 Selection 不再因我们的重建而折叠。
2. **快照兜底**：布局变化不是用户取消——**不失效、不重建快照**。矩形是 96 DPI 页坐标
   （`SelectionBox`），选区层与文本层同挂 `view.surface`，由同一缩放变量与 `surface` 旋转带动，
   因此**不需要坐标重映射**：
   - 缩放：只更新图层尺寸/变换；
   - 旋转：无操作（`surface` CSS `rotate()` 自动带动选区层）；
   - 手势预览：页元素 transform 带动整个 surface，无需重算。
   结论：**保留原坐标系投影，不重算矩形**。

**降级边界**：若某次布局变化确实无法保留几何（例如未来引入“页内坐标重排”，当前不存在），
降级顺序固定为：① 复制内容必须保留（快照文本不受影响）；② 高亮按“清空并在布局稳定后
用快照矩形重绘”处理；③ 原生选区可能失效，但下一次点击会建立新快照。绝不允许表现为
“复制静默少字”。

### 4.4 抑制窗口红线（禁止走捷径）

实现者**不得**用“无条件忽略 `selectionchange`”来掩盖丢选区问题。允许忽略的条件必须同时成立：

1. 事件由**本模块自己**改动了选区所在页的 DOM 引起（`releaseTextLayer` / append 构建 / 淘汰页）；
2. 处于该次改动的**微任务窗口**内（`queueMicrotask` 解除）；
3. 有明确的开启/结束边界，且窗口期间未发生显式用户取消信号。

以下事件**永远不得被抑制**：`pointerdown`（无 Shift，开始新选择/点击空白）、`Escape`、
方向键/可打印键的 `keydown`、宿主调用 `clearSelection()`、新选区非折叠（替换重建）、
文档切换、功能关闭。布局变化也**不进入抑制窗口**（页级构建后布局变化不改 DOM）。

同时，**折叠的 `selectionchange` 本身不得作为清空快照的依据**：它可能来自淘汰页改 DOM，
也可能来自浏览器选区归一化；清空只能由上述显式意图事件触发。这样既不会误清，也不会吞取消。

## 6. 迁移步骤（每步独立可验收）

### 步骤 A：页级构建，取消行增删

- 删除：`applyRowDiff()`（`:918-982`）、`WINDOW_MARGIN_LINES`（`:53`）、`HOLD_LINES`（`:56`）、
  `buildRangeOf()`（`:872-909`）、`wholePageRange()`（`:1539-1542`）、`lastRowBottomOf()`（`:1515-1527`）、
  `builtCoverageOf()`（`:1044-1062`）、`draggingPage` 与三个 document 监听（`:203, 241-283`）。
- 新增：`buildPageTextLayer()` —— `DocumentFragment` 整页构建（本步同步，不分帧）。
- 保留：`rows`/`content`/几何查询/选区层/查找层。
- `applyTextLayerGeometry()` 简化为“图层框 = 纸面尺寸 / 布局倍率”，删除 coverage 分支。
- **验收**：span 数 = `buildTextLayerSpecs().spans.length`；滚动 10 帧 span 增删 = 0；同页选区滚动后文本不变。

### 步骤 B：页级保留与统一淘汰

- `page-view.ts`：`releaseTextLayer()`、`get textSpanCount()`（`childElementCount`）。
- `viewer.ts`：`renderOrder` → cacheOrder；`trimCache()` 增加 span 维度与页数公式；
  `releaseCachedPage()` 同时释放两种产物；`handlePagesReleased()` 通知文本层。
- `text-layer.ts`：删除“不可见即清空”；`paused`/恢复构建；`handlePagesReleased()` 清数据/图层。
- `options.ts` + `document-controller.ts`：`textCachePages` → 引擎 `cache.textPages`（设计预留，**尚未实现**）。
- **验收**：离开可见区 ±1 页的页 canvas 与 span 同时保留；来回滚动 20 次 `getTextContent` 次数不增长。

### 步骤 C：选区快照 + 端点 pin

- `selection.ts`：`SelectionSnapshot`、快照构建、copy 拦截、失效判定、抑制窗口、端点 pin 上报、

## 9. 风险（实施层）

| 风险 | 应对 |
| --- | --- |
| 构建中用户开始拖选，快照只含已建行 | 快照随每次 `selectionchange` 重建；append-only 保证已选内容不被破坏；行建满后新选择自然完整 |
| **布局变化（缩放/旋转）再次破坏锚点** | 页级构建后布局变化不改 DOM；矩形用 96 DPI 页坐标不重算；验收 18~21 覆盖 |
| **抑制窗口被写成“无条件忽略 selectionchange”** | §4.4 红线：仅本模块改 DOM 的微任务窗口内允许；显式取消信号永远优先；t12 审查核对 |
| 抑制窗口过长吞掉真实取消 | 抑制仅在“我们改 DOM”的微任务内；`pointerdown`/`Escape` 显式取消优先 |
| copy 拦截与宿主自定义复制冲突 | 仅在快照存在且选区在阅读器内时 `preventDefault()`；否则不干预 |
| 引擎 143 ms 长任务 | settle 后构建、缓存对齐；列为已知限制 |
| 端点页 pin 仍可能被失败释放 | 快照仍可复制；扩选不可用；下次点击重建（权威 §7.6） |
| 测试重写掩盖回归 | 几何/行划分纯函数测试不动；先落计数器断言；保留 t4 的 13 条浏览器用例作基线 |

### 12.2 与设计不一致的必要偏离

1. **竖排/旋转页不设“整页特例”**：页级构建后所有页都按整页构建，90°/270° 不再走单独的
   整页分支；行主轴仍由 `getAxisRowRad()` 决定。原因是行级裁剪已删除，旋转页不存在可见区
   行窗口，特例失去意义。
2. **settle 阈值取 150 ms**：滚动停止 150 ms 后才构建首次访问页，滚动中只登记需求；
   该值为体验/抖动折中，不是引擎限制，`TextLayerServiceOptions.settleMs` 可覆盖。
3. **pin 预算取桌面 50,000 / 移动 20,000 span**：与滚动预算 30,000 / 12,000 分账；
   `selectionPinSpanBudget` 可配置，超限清空选区并告警而不是无限冻结。
4. **单页 span 上限取 100,000**：对齐 pdf.js `MAX_TEXT_DIVS_TO_RENDER`；超限先降级为 item 级，
   仍超限则按阅读顺序截断并上报 `W_TEXT_LAYER_CAP`；截断页的缺失几何由 `incompletePages`
   兜底，不返回部分文本。
5. **`buildTextRows` 未拆成两个调度任务**：`renderPageText()` 在同一任务内执行
   `buildTextLayerSpecs()` 与 `buildTextRowsFromSpecs()`。dense 样本合并约 14.0 ms，低于
   16 ms 帧预算；再拆一帧会增加首屏构建延迟，故保留合并执行。
6. **快照拦截 copy 的边界**：只在快照存在且复制目标不是可编辑控件时覆盖剪贴板；所有
   `INPUT/TEXTAREA/SELECT/contentEditable` 一律放行（无论是否在阅读器根内），避免把旧选区
   文本写进输入框的复制。宿主其它文本的复制不命中快照条件时不干预。
7. **旧行级 e2e 实施期被误删后曾按新架构重写**；最终按用户裁决整体移除
   `packages/ofdrw-viewer-ui/test/e2e`、`test/acceptance`、根 `test/acceptance` 与 Playwright
   依赖，回归改由 vitest/jsdom 承担。engine/CLI 的 vitest e2e 不受影响。
8. **`textCachePages` 未实现**：设计曾计划新增 UI 选项并透传引擎 `cache.textPages`；全仓代码
   不存在该选项，本轮在文档中统一标记为“设计预留、尚未实现”，`skills/API.md`/`SKILL.md`
   也不得把它列为可用选项。
9. **`W_TEXT_LAYER_LIMIT` 已重命名为 `W_TEXT_LAYER_CAP`**：工作区在任务开始前已从
   `UI_WARNING_CODES` 删除旧码，本轮按约束不擅自恢复；旧码与新码不是并存关系，按码过滤的
   下游需同步迁移。该变更列入公开码表破坏性变更（见 §12.4）。
10. **页数上限实现取 `max(1, pageCacheSize, 2n+1) + pinnedPages.size`**：`pageCacheSize`
    默认桌面 10、移动 4，与设计 `max(10, 2n+1)` 在默认配置下等价；显式调小 `pageCacheSize`
    时以用户配置为准，这是有意的可配置性，不是另一个缓存公式。

### 12.3 已确认的交互决策

1. **点击选区内部即取消选中**：与浏览器默认行为一致，由 `pointerdown`（非 Shift、非右键）
   作为显式意图清空快照。保留四个例外：拖动滚动条、Shift 点击扩选、右键、输入控件内点击。
   理由：不引入“点选区内部保持选中”的非标准交互，避免宿主与用户预期分叉。
2. **非指针失焦不自动清空快照**：窗口失焦、地址栏夺焦等场景不清空快照，优先保证内容仍可
   复制；接受可能的高亮残留与原生选区不一致。用户下一次显式点击/按键会按 §7.5 规则清理。

### 12.4 已知限制与破坏性变更

- **F7 病态行重叠**：t20 修复后，正常行间 1 px 缝隙全部由下行顶边让出；若字形盒本身重叠
  超过下半行高度，相邻行矩形在病态情况下仍可能相交。正常文本不触发，不修改
  `BAND_MERGE_RATIO`/行划分阈值来掩盖该边界。
- **`textCachePages` 未实现**：首次回看仍可能重新执行引擎文本构建（约 143 ms/密集页）；
  Worker 化与引擎缓存透传均列为后续。
- **“整本全选”为非目标**：Ctrl+A 只覆盖已构建页；不为全选加载全部页 `TextContent`。
- **`W_TEXT_LAYER_LIMIT` → `W_TEXT_LAYER_CAP` 是公开码表破坏性变更**：旧码已从工作区
  `UI_WARNING_CODES` 删除，本轮不恢复；按码过滤的下游需同步。兼容性规则建议的
  `@deprecated` 别名本轮未补，原因是任务明确要求不得擅自恢复旧码，且旧码语义（5000 节点
  截断）已不存在；若后续发布需要过渡期，应在下一个 minor 以别名常量补回并在发布说明标注。
- **复制拦截与宿主冲突**：仅当快照有效且目标非输入控件时拦截；宿主自定义 copy 监听若在
  捕获阶段先 `preventDefault`，本模块按 `defaultPrevented` 让行。
