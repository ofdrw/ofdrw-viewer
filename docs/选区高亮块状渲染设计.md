## 1. 背景与目标

### 1.1 问题

文本层 span 是绝对定位的透明文字，选中高亮当前由浏览器原生 `::selection` 绘制（`src/style.css` 的 `.ofd-text-item::selection` / `.ofd-text-char::selection`）。高亮背景色为半透明 `--ofd-selection`，由此产生两个可见缺陷：

1. **同一行相邻 span 横向重叠**：span 的 `left/width` 直接取自 OFD item 的覆盖区，相邻 item 边界常互相咬住若干 px，两块半透明矩形在交集处 alpha 叠加，颜色变深。
2. **上下相邻行纵向重叠**：浏览器按“行框高度 = `max(line-height, 内容高)`”（即字号）绘制选中背景，而 OFD 文档的行距常常小于字号，导致相邻两行的高亮带在纵向互相压住，重叠处再次叠色变深。

纯 CSS 无法修复：`::selection` 背景框的几何由浏览器按块级/原子内联盒决定，CSS 只能改颜色；不透明色会完全遮盖画布上的文字（文字层 span 本身 `color: transparent`，可见文字由下方 canvas 绘制）；`mix-blend-mode` 对 `::selection` 不生效。

### 1.2 目标

选中高亮视觉上呈现为**每行一块、块间保留均匀缝隙**的结果，任何两个高亮块之间不重叠，因此不存在叠色变深的交集。

### 1.3 非目标

- 不改变浏览器原生 Selection 的**交互行为**（拖选、双击选词、Shift 扩展、键盘扩展仍由浏览器维护）。
- 不改变文本层 span 的定位与 DOM 结构。
- 不引入 OCR 或任何新的文字几何来源。

### 1.4 关联问题：跨行复制与斜向拖选

选区高亮与选区文本抽取共用同一套几何数据，且当前文本抽取存在独立缺陷：跨行复制换行符错乱，斜向拖选时中间行内容错误。两者必须一并修复，否则会出现“高亮显示一行、复制却分行”的不一致。详见第 6 章。

## 2. 设计依据：engine 已提供逐字符几何

`@ofdrw/ofdrw-viewer-engine` 的 `getTextContent()` 在 `includeChars: true`（默认值，UI 侧已开启）时，为每个字符返回 `TextChar`（`packages/ofdrw-viewer-engine/src/api/ui-types.ts`）：

| 字段 | 单位 | 用途 |
|---|---|---|
| `quad` | px | 字符单元四点（左上、右上、右下、左下），随 `CharDirection` 旋转；**高亮矩形的数据源** |
| `advance` | px | 字符推进量；缺字为 0，此类字符不产生几何 |
| `rect` | px | `quad` 的轴对齐包围盒 |
| `origin` | px | baseline 起点 |
| `approximate` | — | 是否由多字形 run 近似得到 |

`docs/text-content-api.md` 明确该几何供 UI 选择/高亮消费，并声明 UI 自行决定高亮交互。因此高亮几何无需插值，直接使用 `chars[].quad`。

## 3. 总体架构

> **实施状态：已实施。** 选区块图层位于文本层与查找层之间，按第 4 章算法绘制；实现中新增 `getAxisRowRad()` 查询，见第 12 章。

### 3.1 图层结构

```
PageView.surface
├─ canvasWrapper                    ← canvas，承载可见文字
├─ ofd-page__text-layer             ← 透明 span，只负责选择行为
├─ ofd-page__selection-layer        ← 新增：选区块（z-index: 2，pointer-events: none）
├─ ofd-page__find-layer             ← 查找高亮（z-index: 3）
└─ ofd-page__signature-layer
```

选区块位于 canvas 之上、查找高亮之下，使用**半透明色**，不遮挡画布文字。

### 3.2 职责划分

| 模块 | 职责 |
|---|---|
| `text-layer.ts` | 持有页文本内容与行划分缓存；按字符引用返回 quad 与行标识；管理 `ofd-page__selection-layer` 的创建、定位与绘制 |
| `selection.ts` | 监听 `selectionchange`；构建 `SelectionModel`（第 6 章）；抽取文本；驱动选区重绘 |
| `geometry.ts` | 纯几何：字符 quad → 行内并集区间 → 高亮矩形 |

### 3.3 字符几何的取用方式

`TextLayerService` 内部已按页缓存 `content`（`PageTextState.content`）与行划分（`PageTextState.rows`）。为 `SelectionManager` 新增两个查询方法：

```ts
/** 返回指定字符在 96 DPI 文本层坐标系中的四边形。 */
getCharQuads(pageNumber: number, refs: readonly CharRef[]): (TextQuad | null)[];

/** 返回指定字符所属行的稳定标识；无法判定时返回 null。 */
getRowIdOf(pageNumber: number, ref: CharRef): string | null;

/** 返回指定页的行主轴方向，单位弧度；用于填充 SelectionFragment.axisRowRad。 */
getAxisRowRad(pageNumber: number): number | null;
```

- `CharRef` 为已有类型 `{ itemIndex, charIndex }`。
- `getAxisRowRad()` 是实现中追加的查询：`SelectionFragment` 需要该字段，避免每个片段重复从 `content.items` 计算主轴。
- 方法通过 `ViewerTextLayerServiceLike` 接口暴露，由 `attachTextModule` 注入给 `SelectionManager`。
- 不使用 span 的 `data-*` 属性承载几何：item 级 span 对应多个字符，无法用单值表达，会退回插值并损失精度；行标识同理，`data-row-id` 对 item 级 span 同样无法表达。
- `getRowIdOf()` 沿用以 `(itemIndex, charIndex)` 匹配 `TextRow.spans` 的方式（现为 `rowIdOfRef()`），不引入新的行查询结构。

## 4. 核心算法

> **实施状态：已实施。** `projectQuad()`、`mergeFlowIntervals()`、`applyRowGap()`、`unprojectRect()` 已落地，BAND_MERGE_RATIO 保持 0.5。

输入：一个 `Range`（可跨 span、跨行、跨页）。
输出：每页若干互不重叠的高亮矩形。

### 4.1 第一步：Range → 字符引用

本步复用第 6.3 节的 `buildSelectionModel()`：选区解析（相交过滤、字符级偏移、行归属）统一在该函数内完成，高亮只消费其输出的 `fragments`。

每个 `fragment` 携带 `text`、`pageNumber`、`rowId`、`quad` 与 `axisRowRad`。字符级 span（`.ofd-text-char`）与 item 级 span（`.ofd-text-item`）的差异在模型构建阶段已消除，高亮侧无需区分。

**此步不涉及矩形计算**，仅确定“选中了哪些字符、它们属于哪一行”。

### 4.2 第二步：字符 quad → 投影区间

对每个选中的字符，取其在 96 DPI 坐标系中的四点 `quad`（由 `cssScaleForDpi(dpi)` 换算），投影到页主轴：

```
flow(p)          =  cos(axisRowRad) * p.x + sin(axisRowRad) * p.y   // 阅读推进方向
perpendicular(p) = -sin(axisRowRad) * p.x + cos(axisRowRad) * p.y   // 行法向
```

得到该字符在主轴坐标系中的矩形 `[flowMin, flowMax] × [perpMin, perpMax]`。

四个投影分量都取自实际 `quad` 顶点，因此旋转与竖排文字自动正确，无需特判。

### 4.3 第三步：按行分组并求并集

使用已有的 `TextRow`（`buildTextRows()` 产出，行内 span 已按阅读顺序排序）：

1. 把选中字符按其所属 span 归属到行。
2. 行内按 `flowMin` 升序排序。
3. 线性扫描合并：若下一字符的 `flowMin` 与当前段的 `flowMax` 相差不超过 `FLOW_MERGE_EPSILON`（0.5 px，含恰好相等），并入当前段，并更新 `flowMax = max(flowMax, flowMax')`。
4. 每段输出一个矩形：
   - `flow` 方向：段的 `[flowMin, flowMax]`；
   - `perp` 方向：该段内全部字符 `perpMin` 的最小值与 `perpMax` 的最大值。

**并集操作消除了同一行内的横向重叠**：相邻字符、相邻 span 覆盖的字符统一进入同一区间，不产生两个矩形。

### 4.4 第四步：行间留缝

相邻两行（主轴法向上相邻的行）的矩形之间保留固定缝隙：

```
ROW_GAP_PX = 1
```

- 取相邻两行矩形的 `perp` 区间 `[bottomUpper, topLower]`；
- 若 `topLower - bottomUpper < ROW_GAP_PX`，缝隙**全部由下行矩形的顶边让出**，上行矩形底边保持原始字符范围不变，使两者之间恰好为 `ROW_GAP_PX`；下行每个矩形顶边收缩量不超过**自身高度的一半**，矮矩形自动少收缩，绝不把矩形压成零高；整行极薄时缝隙可小于 `ROW_GAP_PX`；
- 若本身已有更大间距，保持原状。

该步骤保证正常文本的任意两个高亮矩形在纵向不重叠。**已知边界（F7）**：若字形盒本身重叠
超过下半行高度，按“下行顶边让出、最多让出自身高度一半”的规则仍无法完全消除重叠，病态情况下
相邻行矩形可能相交；正常文本不触发，调整该边界需要改行划分/`BAND_MERGE_RATIO`，属独立议题。

### 4.5 第五步：输出与坐标系转换

主轴坐标系中的矩形 `[flowMin, flowMax] × [perpMin, perpMax]` 反变换为页面坐标：

```
x = flow * cos(axisRowRad) - perp * sin(axisRowRad)
y = flow * sin(axisRowRad) + perp * cos(axisRowRad)
```

- `axisRowRad` 为 0（水平文字）时退化为轴对齐矩形，直接写入 `left/top/width/height`；
- `axisRowRad` 非 0 时，输出矩形中心点 + 宽高 + `rotate(${axisRowRad}rad)`。

### 5.3 刷新时机

页级生命周期落地后，刷新不再由“文本层重建/滚动”驱动，而是由 **`SelectionSnapshot`** 驱动：
快照保存完整文本与每页已合并的行矩形，DOM 是否还存活不影响复制与高亮。

| 时机 | 动作 |
|---|---|
| `selectionchange`（非折叠、在阅读器内） | 重建快照并重绘；快照是后续复制/高亮的唯一数据源 |
| `selectionchange`（折叠） | **不据此清空**；可能是我们淘汰/构建 DOM 导致，交给显式意图（pointerdown/Escape/keydown）处理 |
| 页被 LRU 淘汰后重新进入可见集 | **不重算快照**；页重建后直接按 `snapshot.rectsByPage` 补绘该页矩形，端点页由 pin 保护 |
| 缩放 / 旋转 / 容器尺寸变化 | 不重建快照、不清空；仅由 `applyLayerScale` 同步选区层几何，矩形仍是 96 DPI 页坐标 |
| 快照存在时按 Ctrl+C | 直接 `setData(snapshot.text)` 并阻止默认复制；不重绘 |
| 清空选区 / 功能关闭 / 文档切换 | 清空所有页选区层与快照（按 §7.5 显式意图/生命周期） |
| `pinnedSpans > P` 或 `incompletePages` 非空 | 清空快照与高亮，分别上报 `W_SELECTION_UNPINNABLE` / `W_SELECTION_EVICTED` |

## 6. 选区文本抽取修复

> **实施状态：已实施。** `buildSelectionModel()` 已是选区几何唯一入口；D3/D4/D5 已修复，D1/D2 为回归保持项。extraction 的 `SelectionFragment` 另追加 `itemIndex`/`charIndex` 可选字段，详见第 12 章。

### 6.1 现状缺陷

当前文本抽取位于 `src/text/selection.ts`：`collectFragments()` 逐 span 取选中文本与 `span.dataset.x/y`，再由 `joinFragments()` 用固定阈值判断片段是否属于同一行。经诊断用例复现，确认存在三个缺陷：

| 编号 | 缺陷 | 复现现象 |
|---|---|---|
| D3 | 紧排文档中行距小于旧阈值 | 行距 9 px、字号 16 px 时两行黏连，换行丢失；而 `buildTextRows()` 判 2 行 |
| D4 | 阈值取 `max(previous.size, fragment.size)` | 字号小的在上、大的在下（框间距 8 px、`data-y` 差 18 px ≤ 19.2 px）时标题与正文被并为一行 |
| D5 | 行判定与文本层行划分使用不同阈值 | 字号 20 px、`data-y` 差 11 px 时：`buildTextRows()` 阈值 10 px 判 2 行，`joinFragments()` 阈值 12 px 判 1 行 |

三个缺陷方向一致：旧阈值 `0.6 × max(size)` **恒大于**行划分阈值 `0.5 × max(span 高度)`（同字号同高时 0.6 > 0.5），因此旧逻辑只会**少插换行**，不会多插换行。凡是“两片段距离 > 0.6 × size”的情形，行划分必然也判为两行，两者结论一致。

以下三条经实测确认**不是缺陷**，实施时作为回归项保持：

- **D1（已否决）**：`boundaryOffset()` 对非端点节点返回整段。标准文本节点选区是文档序上的单一连续区间，严格位于 `startContainer` 与 `endContainer` 之间的节点必然整体落在选区内，因此“整段计入”语义正确；端点所在 span 已由 `container === node` 分支正确取偏移。实测斜向选区输出 `乙丙丙\n丁丁丁丁\n戊戊` 已符合 §6.7 目标行为。字符级 `comparePoint()` 仅作为加固手段（见 6.4），不得为“修复 D1”而改变该输出。
- **D2（已否决）**：同字号下两个 item 基线相差 10 px 时被插入换行。该场景在 `buildTextRows()` 中同样判为 2 行（阈值 8 px < 10 px），新旧逻辑结论一致，不存在可翻转的差异；实测 offset 6/8 px 为 1 行、9/10/12/16 px 为 2 行，与行划分阈值吻合。基线抖动被切分成两行属**行划分灵敏度**问题（`BAND_MERGE_RATIO = 0.5`），会影响高亮与查找，属独立议题，不在本设计范围内。按 §6.2 的权威口径，此场景期望输出即 `一二\n三四`。
- **D4 方向（已修正）**：大字号在上、小字号在下时阈值为 `0.6 × 大字号`，反而更容易越过阈值而正常换行；缺陷只在“小字号在上、大字号在下”时成立。原文档将场景方向写反，已按实测修正 D4 行。

此外，`collectFragments()` 按 `querySelectorAll` 的 DOM 顺序遍历，斜向拖选时 DOM 顺序与视觉阅读顺序不一致，拼接出的文字顺序可能错乱。

根因：复制路径只持有 span 左上角坐标，无法得知字符的真实几何与行归属，只能用距离阈值推测。而“某字符属于哪一行”在文本层中已是确定事实（`buildTextRows()` 产出的 `TextRow`），高亮与查找均已使用，唯独复制路径未使用。

### 6.2 修复原则

> 用“查表”替代“猜测”：两个字符属于同一 `TextRow` 即为同一行，不再使用任何距离阈值。

该原则一次性消除 D2、D3、D4、D5：行归属与字号、行距无关，且与高亮共用同一份行划分。

### 6.3 统一选区模型

新增 `buildSelectionModel(range)` 作为选区几何的唯一入口：

```ts
/** 选区几何模型；复制与高亮共同消费。 */
export interface SelectionModel {
  /** 选区片段，按阅读顺序排序。 */
  readonly fragments: readonly SelectionFragment[];
  /** 抽取模式；legacy 表示回退到旧逻辑。 */
  readonly mode: 'vector' | 'legacy';
  /** 选区页区间内没有 span 或没有文本数据的页码；非空表示模型不完整。 */
  readonly incompletePages?: readonly number[];
}

/** 单个选区片段。 */
export interface SelectionFragment {
  /** 被选中的文本。 */
  readonly text: string;
  /** 页码，1-based。 */
  readonly pageNumber: number;
  /** 所属行的稳定标识；无法判定时为 null。 */
  readonly rowId: string | null;
  /** 字符在 96 DPI 坐标系中的四边形；缺失时无高亮。 */
  readonly quad: TextQuad | null;
  /** 主轴方向，单位弧度。 */
  readonly axisRowRad: number;
  /** 字符所属 TextItem 下标；为后续选区快照追加。 */
  readonly itemIndex?: number;
  /** 字符在 TextItem 内的下标；item 级片段为 null；为后续选区快照追加。 */
  readonly charIndex?: number | null;
}

/** 完整选区快照：与 DOM 存活性解耦，复制/高亮唯一数据源。 */
export interface SelectionSnapshot extends SelectionModel {
  /** 规范化后的完整选区文本。 */
  readonly text: string;
  /** 每页已合并、留缝的高亮矩形（96 DPI 页坐标）。 */
  readonly rectsByPage: ReadonlyMap<number, readonly SelectionBox[]>;
  /** 每页行主轴方向，单位弧度。 */
  readonly axisByPage: ReadonlyMap<number, number>;
  /** 选区覆盖页（升序，1-based）。 */
  readonly pageNumbers: readonly number[];
  /** 选区页区间内不可用的页；非空表示模型不完整。 */
  readonly incompletePages?: readonly number[];
  /** 端点页（1-based），用于 pin 与扩选判定。 */
  readonly startPage: number;
  readonly endPage: number;
  /** 建立快照时的原生锚点/焦点节点与偏移。 */
  readonly anchorNode: Node | null;
  readonly focusNode: Node | null;
  readonly anchorOffset: number;
  readonly focusOffset: number;
  /** 快照版本号；每次建立/失效递增。 */
  readonly version: number;
}
```

- **复制**：按 `fragments` 顺序，依据 `rowId` 拼接文本。
- **高亮**：按 `fragments` 的 `quad` 与 `rowId` 合并矩形。

一份模型、两个消费者，杜绝再次分叉。`incompletePages` 是模型完整性兜底：若选区页区间内
存在无 span/无文本数据的页（页被淘汰、截断页或异常窗口），模型不得返回部分文本，必须清空
并上报 `W_SELECTION_EVICTED`。

### 6.4 字符级精确偏移（已实施）

`boundaryOffset()` 对非端点节点返回整段，这在标准文本节点选区下是**正确**的（见 6.1 的 D1 说明），因此本节属于**加固**，不是缺陷修复。实现已采用字符级 `Range.comparePoint()`，并保持 D1 输出不变。

加固方式：对每个与 Range 相交的 span，用 `Range.comparePoint()` 确定每个字符位置相对选区的归属：

```ts
/** 判定单个字符位置相对选区的归属。 */
function charInRange(range: Range, node: Text, index: number): -1 | 0 | 1 {
  // -1 = 在选区起点之前；0 = 落在选区内；1 = 在选区终点之后
  return range.comparePoint(node, index) as -1 | 0 | 1;
}
```

- 起止偏移取“首个不早于选区起点”与“末个不晚于选区终点”的字符下标；
- 性能剪枝：先用 `range.intersectsNode(textNode)` 过滤，只对相交的 span 逐字符判定。一页上万字符时，相交 span 通常仅数个至数十个，开销可忽略；
- **约束**：加固前后 `getSelectedText()` 的输出必须完全一致，斜向选区仍为 `乙丙丙\n丁丁丁丁\n戊戊`。若实现无法保证，应放弃本节、保留现有 `boundaryOffset()`。

### 6.5 行归属查表

对每个选中字符，用 `(itemIndex, charIndex)` 反查所属 `TextRow.id`。查法沿用既有 `(itemIndex, charIndex)` 匹配方式（实现为 `geometry.ts` 的 `rowIdOfRef()`）：在 `rows` 中查找包含该字符的 span。

拼接规则：

```text
上一个字符的 rowId ≠ 当前字符的 rowId  →  插入 '\n'
否则                                    →  按 CJK/拉丁规则决定是否插入空格
```

不涉及任何距离计算，与字号、行距无关。D2、D3、D4、D5 由此修复。

### 6.6 阅读顺序排序

`fragments` 排序键：

```text
(页码, 行的法向序号, 行内 flow 位置)
```

三项均由 `TextRow` 与既有 `axisRowRad`（`src/text/geometry.ts` 的 `perpendicularOf()` / `flowOf()`）提供，不引入新算法。斜向拖选时片段顺序与视觉阅读顺序一致，文字顺序错乱由此修复。

### 6.7 斜向拖选的目标行为

起点位于第 1 行中部、终点位于第 3 行中部时：

- 第 1 行只输出起点之后的字符；
- 第 2 行整行输出（全程在选区内）；
- 第 3 行只输出终点之前的字符。

结果形如 `AAAAA\nBBBBBBBBBB\nCCCCC`。

## 7. 兜底策略

选区层与字符级抽取在以下情况**不接管**，回退到旧逻辑：

- 浏览器不支持 `Range.intersectsNode`；
- 页文本内容缺失（`content` 未就绪）或字符引用无法解析；
- `chars[]` 缺失（引擎返回 `includeChars: false`）；
- 计算过程抛出异常。

回退时：

- **高亮**：页元素写 `data-selection-mode="native"`，CSS 恢复原生高亮；
- **复制**：`SelectionModel.mode = 'legacy'`，沿用旧的距离阈值拼接。

```css
.ofd-page[data-selection-mode='native'] .ofd-text-item::selection,
.ofd-page[data-selection-mode='native'] .ofd-text-char::selection {
  background: var(--ofd-selection);
}
```

默认（`vector` 模式）下原生 `::selection` 背景置为透明。回退路径保证功能可用，不保证缺陷 D1~D5 的修复效果。

## 11. 验收标准

1. **单行多字符**：选中一行内相邻的多个 span，选区层中矩形数量为 1。
2. **跨行**：选中 2~3 行，矩形数量等于行数，任意两矩形不相交，相邻矩形纵向间隙为 1 px（在 100% 缩放下的 CSS px）。
3. **跨页**：每页各自渲染矩形，且不跨页合并。
4. **旋转与竖排**：页面旋转 90°/180°/270° 及文档内竖排文字，矩形随文字方向旋转且仍不重叠。
5. **缩放**：50% / 100% / 150% / 200% 下矩形始终与文字对齐，不相交。
6. **兜底**：模拟 `content` 缺失时，页元素进入 `native` 模式并显示原生高亮。

文本抽取验收项（缺陷 D3~D5 为修复目标，D1/D2 与斜向顺序为回归保持项）：

7. **紧排行距（D3）**：行距为字号 0.85 倍的两行，跨行选取时保留换行（当前输出黏连）。
8. **同行基线偏移（D2，回归保持）**：同字号两个 item 基线相差 10 px 时，输出 `一二\n三四`（两行）。该场景行划分本就判为两行，改动前后必须一致；不得为追求“同一视觉行”而改变行划分阈值。
9. **混排字号（D4）**：小字号在上（10 px）、大字号在下（32 px）、`data-y` 差 18 px 时判定为不同行（当前被并为一行）；另需保证大字号在上的场景仍正常换行。
10. **斜向拖选（回归保持）**：起点在第 1 行中部、终点在第 3 行中部时，首尾行仅输出选中部分，中间行整行输出，结果顺序与视觉阅读顺序一致。该行为当前已正确（`乙丙丙\n丁丁丁丁\n戊戊`），改动后必须保持不变，顺序错乱场景需通过 DOM 顺序与视觉顺序不一致的构造用例覆盖。
11. **行判定一致性（D5）**：同一选区下，高亮划分出的行数与文本抽取插入的换行数一致。
12. **常规回归**：`getSelectedText()` 在标准行距、单行、跨页场景下的结果与改动前一致。
13. **跨页存续（页级淘汰）**：跨 3~5 页选中后，滚动使中间页被淘汰，`getSelectedText()` 仍逐页完整，
   每页选区层矩形仍在；端点页 pin 保 Shift 扩选。
14. **布局变化存续**：缩放 1→1.5→2、缩小 2→1.5→1、旋转 0→90→180→270，每一步
   `getSelectedText()` 与矩形数量不变，快照对象不被清空/重建。
15. **显式取消不被吞**：抑制窗口外点击空白、Esc、方向键/可打印键都能清空快照与高亮；
   折叠的 `selectionchange` 单独不会清空。
16. **pin 预算兜底**：端点页分帧增长使 `pinnedSpans > selectionPinSpanBudget` 时，选区与高亮清空，
   `W_SELECTION_UNPINNABLE` 只报一次。
17. **不完整模型兜底**：`incompletePages` 非空（淘汰/截断）时清空并上报 `W_SELECTION_EVICTED`，
   不返回部分文本。
