## 1. 设计源 §8 三个待确认点的裁决

### 1.1 裁决一：选区边缘 margin 策略

**裁决**：采用**分级预算 + 拖选期间整页（仅当前页）**，不接受“永久牺牲拖选体验”。

具体规则：

| 触发条件 | 构建范围（目标行集合） |
| --- | --- |
| 默认（无选区） | 见 §2.1“基础窗口” |
| 拖选锚点落在某页文字层内（`pointerdown`，命中 `.ofd-page__text-layer`），或 `selectionchange` 后选区非空且锚点/焦点落在本页文字层内 | **该页整页**（目标行集合 = 全部行） |
| 锚点页之外的其它可见页 | 仍按默认窗口（不因拖选放大） |

结束条件（恢复默认窗口）：`pointerup`/`pointercancel` 后下一帧；或 `selectionchange` 后选区不可折叠且锚点与焦点都不在本页文字层内；或 `documentclose`/`destroy`。

实现约束：

1. `pointerdown` 监听挂在 `host.getRoot()` 返回节点所属的 `ownerDocument` 上，用**单个**委托监听，不逐页挂：
   ```ts
   const doc = view.textLayer.ownerDocument;
   doc.addEventListener('pointerdown', handler, true); // 捕获阶段，先于浏览器建立选区
   ```
   通过 `event.target.closest('.ofd-page__text-layer')` 判定是否落在文字层内，再用 `closest('.ofd-page')` 的 `data-page-number` 得到页码；目标不在文字层内时直接忽略。`getRoot()` 不可用时退化为 `view.textLayer.ownerDocument`。
2. `pointerup`/`pointercancel` 监听同样只挂一次（挂在 ownerDocument 上），在回调里于**下一帧**恢复（`scheduleFrame`），保证浏览器先完成选区收尾。
3. “整页”只是把目标行集合改为全部行，**不新增其它路径**：仍走 §2.2 的差量构建，不在拖选结束后立即删除——拖选结束后回到默认窗口由下一次差量自然收敛（`HOLD_LINES` 生效）。
4. 极端情形（用户把鼠标拖到视口外很远）沿用设计源 §5.1 第 3 条：允许拖出后的区域暂时选不中，停止拖选后补建。
5. 该能力属于**第三步**交付（设计源 §7 第三步“选区进行中临时提升 margin 的适配”）；第一步/第二步不得提前实现、也不得做与它冲突的结构（例如把“目标行集合”硬编码成只依赖可见矩形）。

**可测判据**：见 §5.4 第三步 V3-2、V3-3。

### 1.2 裁决二：行划分主轴判定规则

**裁决**：**主行轴 + 垂直方向的“重力行带”二次归并 + 阅读方向排序**。不用几何聚类的通用算法，规则固定如下，纯函数落在 `geometry.ts`：

1. **主行轴（页级）**：取该页 `TextContent.items` 中 `shouldSplitChars(item) === false` 的 item 的 `quad` 上边（`quad[0] → quad[1]`）方向角 `θ`（弧度，用 `atan2` 计算，与 `shouldSplitChars()`、`span.angle` 同源）。
   - 以“水平轴（θ≈0）”为起点，每 15° 一个扇区（24 扇区，`sector = round(归一化 θ / (π/12)) mod 24`），**按 span 数量加权**取众数扇区；平票时取更接近 0（水平）的扇区。
   - 页内没有任何非拆分 item（整页都是竖排/逐字旋转）时，退化为**全部 item** 的加权众数。
   - 主轴方向取该扇区中心角：`axisRowRad = sector * π/12`；`axisFlowRad = axisRowRad`（flow 方向是**页面内的阅读推进方向**，与页旋转 `0/90/180/270` 无关）。
   - 页内没有任何 item（空页）时返回空行表，不抛错。
2. **行内/行间判定**：对每个 span，用其 `TextSpanSpec.left/top/width/height/angle` 投影到主轴：
   - `rowAxis = (cos(axisRowRad), sin(axisRowRad))`，`flowAxis = (-sin(axisRowRad), cos(axisRowRad))`；
   - `perp(s) = -sin(axisRowRad) * s.left + cos(axisRowRad) * s.top`（与 [`selection.ts`](../packages/ofdrw-viewer-ui/src/text/selection.ts) `joinFragments()` 的 `perpendicular` 公式**同式**，便于两处行为一致）；
   - `spanHeight(s) = |sin(s.angle) * s.width| + |cos(s.angle) * s.height|`（旋转后包围盒在主法向上的高度，单位 px）；char 级 span 的 `width/height` 已是旋转后包围盒且 `angle` 为字符方向，同一公式适用；
   - **行带高度 `H_band`** = 该页全部 span 的 `spanHeight` 的**中位数**（单位 px），下限取 1：`H_band = max(1, median(spanHeight))`。
3. **重力行带归并**：按 `perp` 升序对 span 排序后线性扫描，维护 `currentBand`：若 `span.perp - currentBand.perpFirst ≤ 0.5 * max(currentBand.spanHeight, span.spanHeight)`，并入 `currentBand`（**同一个 item 的所有 span（含全部 char 级 span）一律强制并入同一行**，不受阈值影响），否则开新行带。这样：
   - 同一文本行内 item 与 char span 混排（`shouldSplitChars()` 为真/假相邻）仍归为一行；
   - 竖排（主轴 ≈ 90°）与逐字旋转仍按“垂直方向的 band”成行，不需要另一套算法。
4. **行内排序（阅读方向）**：行内按 `flow(s) = cos(axisFlowRad) * s.left + sin(axisFlowRad) * s.top` 升序；`flow` 相等的 char 级 span 按 `charIndex` 升序；仍相等按 `itemIndex` 升序。行与行之间按 `perp` 升序排列（主轴法向正方向视为阅读向下）。
5. **行 ID**：`id = "${该行最小 itemIndex}:${行在页内的序号}"`（序号为 0-based，按行 `perp` 升序）。行 ID 只要求**同一页内跨调用稳定**（同一 `TextContent` 两次划分结果相同），不要求跨 DPI/重构稳定。
6. **行的上下边界**：`top = 行带内 span 的 perp 最小值`，`bottom = 行带内 span 的 (perp + spanHeight) 最大值`；若为主轴水平（`|sin(axisRowRad)| < 1e-6`），`perp` 即 `span.top`，`top/bottom` 即该行的 96 DPI y 区间，**保证 0° 页面与现状 `TextSpanSpec.y` 语义一致**。
7. **验收覆盖的排版清单**（“是否有已知的复杂排版需要纳入验证”的回答，全部要出现在测试里）：
   - 横排多行、多 item 凑一行；
   - 同一页混排行内 item 级 + char 级 span（`shouldSplitChars` 一真一假）；
   - 竖排（`angle = π/2` / `-π/2`）；
   - 逐字旋转（每字 `angle` 不同）；
   - `PageView` 的四个 `rotation` 取值 `0/90/180/270`（旋转只影响可见矩形换算，**不影响行划分**，因为行划分在 96 DPI 坐标系内完成）。

**可测判据**：见 §5.2 第一步 V1-1~V1-3。第一版**只需要**处理这 5 类；额外的复杂排版（表单域、批注文本、跨栏混排）登记为“已知未覆盖”，不得因此修改行划分规则。

### 1.3 裁决三：`HOLD_LINES` 是否保留及取值

**裁决**：**保留**，`HOLD_LINES = 8`（单位：行），定义为 `text-layer.ts` 内的模块级常量（`const HOLD_LINES = 8;`，不导出、不做选项）。

规则：

1. 已建行只在其行区间与“**扩充窗口**”相交时保留；扩充窗口 = 基础窗口（§2.1）在主轴方向上、**向两侧各外扩 `HOLD_LINES × H_band` px**。
2. 进入基础窗口的行立即创建；离开基础窗口但仍在扩充窗口内的行**保留不动**（不重算 span 坐标，只保留 DOM）。
3. 超出扩充窗口的行移除其 span。
4. **抖动判据**：同一行在同一次连续滚动（从一个滚动位置单调滚到另一个位置、过程中不回滚）中，`createTextSpan` 的调用次数 ≤ 1；行 ID 集合的差量在每一帧只包含新增或移除之一。
5. 选区/查找/复制读取一律基于 `querySelectorAll('.ofd-text-item, .ofd-text-char')`，因此保持窗口内的行对选区是“意外收益”，但**不得**把它写进文档对外承诺（只有基础窗口 + 拖选整页是对外承诺）。

理由（供评审判断，不入代码）：`HOLD_LINES = 8` 约为 A4 在 100% 缩放下 8 行正文，能覆盖一次滚轮与惯性滑动的回摆；取设计源建议区间 5~10 的中间值，且不引入任何跨页缓存。

**可测判据**：见 §5.3 第二步 V2-4。

## 2. 公共实现契约（`geometry.ts` / `text-layer.ts` 的接口形状）

本节定义**三步共用**的数据结构与函数签名，implementer 不得擅自改名；verifier 以本节为接口核对依据。

### 2.1 可见矩形与基础窗口（纯几何，`geometry.ts`）

```ts
/** 页在 96 DPI 坐标系中的可见区间；主轴方向的上下界，单位 px。 */
export interface VisibleRange {
  /** 可见区在主轴方向的起点（含）。 */
  readonly top: number;
  /** 可见区在主轴方向的终点（含）。 */
  readonly bottom: number;
}

/**
 * 由页元素在屏幕上的包围盒反解 96 DPI 坐标可见区间。
 *
 * @param pageRect 页元素 `getBoundingClientRect()` 的结果（屏幕 px）。
 * @param viewportRect 滚动容器可见矩形（屏幕 px）。
 * @param page 页在 96 DPI 坐标系中的尺寸，单位 px。
 * @param rotation 页旋转角度：0/90/180/270。
 * @param axisRowRad 行划分主轴（弧度，见 §1.2）。
 * @returns 主轴可见区间；无交集时返回 null。
 */
export function visibleRangeOf(
  pageRect: { left: number; top: number; width: number; height: number },
  viewportRect: { left: number; top: number; width: number; height: number },
  page: { width: number; height: number },
  rotation: 0 | 90 | 180 | 270,
  axisRowRad: number,
): VisibleRange | null;
```

坐标系约定：设 96 DPI 页面未旋转尺寸为 `Pw × Ph`。`rotation ∈ {0,180}` 时 `W = Pw, H = Ph`；`rotation ∈ {90,270}` 时 `W = Ph, H = Pw`（宽高交换）。记 `u = (x / W) - 0.5`、`v = (y / H) - 0.5`（`-0.5..0.5`，左上为原点，单位：页内相对坐标），则旋转 `r` 后页元素包围盒内的相对位置为：

```text
r = 0°    : rx =  u,  ry =  v
r = 90°   : rx = -v,  ry =  u
r = 180°  : rx = -u,  ry = -v
r = 270°  : rx =  v,  ry = -u
```

再由 `sx = rx + 0.5`、`sy = ry + 0.5` 得到屏幕点：`px = pageRect.left + sx * pageRect.width`，`py = pageRect.top + sy * pageRect.height`。该约定与 [`page-view.ts`](../packages/ofdrw-viewer-ui/src/page-view.ts) 的 `surface` 变换（`translate(-50%,-50%) rotate(rotation deg)`，`transform-origin: center`，CSS 正角度为屏幕顺时针）对偶。

反解（求 `pageRect` 四点映射回 96 DPI 的包围盒）等价于：把 `pageRect` 的四个角点换算成 `(sx, sy) ∈ {(0,0),(1,0),(1,1),(0,1)}` 对应的 `(rx, ry)`（`rx = sx - 0.5`，`ry = sy - 0.5`），再按**同一张表的逆**得到 `(u, v)`，最后 `x = (u + 0.5) * W`、`y = (v + 0.5) * H`。四点得到的 `x/y` 包围盒再投影到主轴：

```text
perp(点) = -sin(axisRowRad) * x + cos(axisRowRad) * y
top    = min(perp(四个映射角点))
bottom = max(perp(四个映射角点))
```

`axisRowRad` 为 0 时 `top/bottom` 即 96 DPI 的 y 区间。`pageRect` 与 `viewportRect` 无交集（`pageRect.right <= viewportRect.left` 等任一条件成立）时返回 `null`。

**基础窗口**（构建哪些行）：

```text
WINDOW_MARGIN_LINES = 2                        // 上下预渲染带，单位：行
H_span = 该页行带高度的中位数（见 §1.2，单位 px）
基础窗口 = [visible.top - WINDOW_MARGIN_LINES * H_span, visible.bottom + WINDOW_MARGIN_LINES * H_span]
行入选  ⇔ 行.bottom >= 基础窗口.top && 行.top <= 基础窗口.bottom
保留窗口 = 基础窗口向两侧各外扩 HOLD_LINES * H_span（§1.3）
```

**退化规则**：`页元素或滚动容器不可测量`（`getBoundingClientRect` 使 `pageRect.width/height` 为 0 或 `viewportRect.width/height` 为 0，含 jsdom 默认 0 尺寸）时，基础窗口退化为**整页**（`top = 0, bottom = 页高`）。这条保证第一/第二步在任何 jsdom 单测与旧用例中行为等价于“整页构建”。

### 2.2 行差量与调度（`text-layer.ts`）

```ts
/** 文字行：与可见区判定的最小构建单位。 */
interface TextRow {
  /** 稳定行标识；`${首个 itemIndex}:${行序号}`。 */
  readonly id: string;
  /** 行在主轴上的起始位置，单位 px（96 DPI）。 */
  readonly top: number;
  /** 行在主轴上的结束位置，单位 px（96 DPI）。 */
  readonly bottom: number;
  /** 行内 span，按阅读方向排序。 */
  readonly spans: readonly TextSpanSpec[];
}

/** 页文字层状态：只记录数据与已建行，不记录整页生命周期。 */
interface PageTextState {
  /** 引擎文本内容（含行划分），构建后保留。 */
  content: TextContent | null;
  /** 行划分结果；null 表示尚未划分。 */
  rows: readonly TextRow[] | null;
  /** 行带高度中位数，单位 px；用于 margin/HOLD 换算。 */
  bandHeight: number;
  /** 已建行：行 ID → 该行的 span 元素。 */
  built: Map<string, HTMLSpanElement[]>;
  /** 生成代次，用于丢弃迟到的异步结果。 */
  generation: number;
  /** 取消信号。 */
  abort: AbortController | null;
  /** 是否加载失败（离开可见页后重置，允许重试）。 */
  failed: boolean;
}
```

排队与执行：

1. `scheduleRefresh()` 改 rAF：`requestAnimationFrame` 可用时用它，否则回退 `setTimeout(cb, 0)`（复用 `scheduleFrame` 或内联同逻辑）；**`runMicrotask` 不再用于文本层刷新**。`refresh()` 仍为同步执行入口（`ViewerTextLayerService.refresh()` 契约）。
2. 每帧一次遍历：对 `visiblePageNumbers()` 得到的目标页，`getPageView()` 取 `view`，`measure` 可见矩形 → 目标行集合 → 与 `state.built` 做差集 → 仅新增/移除变化的行。
3. 插入顺序：新行 span 按行 `top` 升序插入；同一行内 span 追加到该行末尾。`textLayer` 的 `childElementCount` **只用于**判断“是否有内容”（`syncPageTextLayerGeometry()` 与清空逻辑），不得用于判断是否已构建整页。
4. **空 DOM 页跳过**：一页没有任何行入选时，`textLayer` children 为 0，且**不**写 `data-dpi`/`data-selectable`（与现状 `clearPageTextLayer()` 的形态一致）。
5. `state.built` 字段删除，改为“`rows !== null` 即已就绪”；`failed` 保留（离开可见页后重置）。
6. 拖动/缩放中的行为：与现状一致（手势预览期 `PageView` 自身打 `data-preview` 隐藏文字层），本方案不新增拦截逻辑。

## 8. 实施后勘误（追加，不改写正文）

本节记录**实施阶段**相对正文的已确认偏离，供后续维护与评审追溯。正文（§0–§7）保持需求阶段原貌，**以本节为准**；偏离均已在实现、测试与验收（t15 实施、t24 最终复验）中对齐并留痕。

### 8.1 §2.1：`visibleRangeOf()` 未实现，改为 `visibleYRangeOf()`

- **正文**：`visibleRangeOf(pageRect, viewportRect, page, rotation, axisRowRad)`，返回主轴区间，需投影到 `axisRowRad` 法向。
- **实际**：`geometry.ts` 导出 `visibleYRangeOf(pageRect, viewportRect, page, rotation)`（四参，无 `axisRowRad`），返回 **96 DPI 页内 y 区间** `{ top, bottom } | null`；另有 `isRectUnmeasurable(rect)` 判空、`windowRangeOf(visible, bandHeight, marginLines)` 做正向外扩（三参）。
- **理由**：行按页内 `y` 分组（行划分主轴取页级众数，但主轴仅为水平/近似水平），可见区只需换算为页内 y 区间即可完成行级裁剪；旋转 90°/270° 下直接返回页内 y 全幅（整页），由 `text-layer.ts` 按整页构建。`axisRowRad` 传入只会增加一条恒等映射的分支，无行为收益。
- **影响**：§5.3 的 V2-1 用例文件 `test/unit/text/visible-rect.test.ts` 未创建；四向旋转换算与窗口判定并入 `test/unit/text/geometry.test.ts`（可见区间用例 7 条，含四向旋转、非整数倍率、不可测量）与 `test/unit/text/text-layer.test.ts`（四向旋转裁剪、jsdom 退化整页）。

### 8.2 §2.1 / §2.2：`axisRowRad` 未进入 `PageTextState`，拖选状态字段落地为 `draggingPage`

- **正文**：`PageTextState` 含 `bandHeight`，并隐含 `axisRowRad`（§2.1 参数、§1.2 行划分输出）。
- **实际**：`TextRowLayout` 返回 `{ rows, axisRowRad, bandHeight }`，但 `PageTextState` 只保留 `content / rows / bandHeight / built / generation / abort / failed`；`axisRowRad` 已在行划分阶段用于计算 `TextRow.top/bottom`，运行期不需要。选择页提升用 `draggingPage: number | null` 记录“拖选中的页”，由 `ownerDocument` 上 capture 阶段的 `pointerdown`（命中 `.ofd-page__text-layer` 时设置）/`pointerup`/`pointercancel` 单一委托驱动。
- **理由**：减少运行期状态；拖选提升只需一个页号即可判定“该页整页、其余页保持基础窗口”。

### 8.3 §1.1 / §3.3 附带：拖选提升的触发收窄为 `pointerdown` 单点

- **正文**：§1.1 写了两个触发条件（`pointerdown` 命中，或 `selectionchange` 后选区非空且锚点在页内）。
- **实际**：只实现 `pointerdown` 委托（命中页文字层时该页整页、松开 `pointerup`/`pointercancel` 后回落到基础窗口）；未订阅 `selectionchange`。拖选整页期间不删除任何已建行（`holdRange` 取无穷）。
- **理由**：`selectionchange` 在浏览器里异步且会与差量刷新争用同一帧；`pointerdown` 单点在浏览器实测覆盖了“从页内开始拖选”的全部路径，且能保证在浏览器扩展选区之前完成标记（capture 阶段）。已知边界：仅用键盘/程序化扩展选区不会触发整页提升。

### 8.4 §3.2：滚动容器识别规则宽化为“任一方向可滚动”

- **正文**：§3.2 规则 1 要求 `overflowY ∈ auto|scroll|overlay`。
- **实际**：向上取第一个“内容超出可视区（`scrollHeight > clientHeight || scrollWidth > clientWidth`）且 `overflowX` **或** `overflowY` 属于 `auto|scroll|overlay`”的祖先；可视矩形按布局盒（`offsetWidth/offsetHeight` + padding/border − 滚动偏移）换算，与页元素 `offsetTop` 同源，布局盒不可测量时才回退 `getBoundingClientRect()`。
- **理由**：横向滚动容器（`overflowX: auto`）同样是“可视区”的裁切者；混合方向只判纵向会出现找不到容器而误退化为窗口的情形。

### 8.5 §3.1 / §5.2：差量插入改为“插到行序锚点之后”，并按阅读顺序断言 DOM

- **正文**：§3.1 要求“新行 span 按行 `top` 升序插入；同一行内 span 追加到该行末尾”；§5.2 的 V1-4 断言“DOM 顺序：行按 `top` 升序，行内按 span 顺序”。
- **实际**：`applyRowDiff()` 以“图层最后一个子节点对应的已建行”为插入锚点，把新行插到行序最近的已建行之后（锚点丢失时改插入末尾），使 DOM 顺序始终与**阅读顺序**一致；行内 span 按 `buildTextRows()` 给出的阅读方向顺序创建。主轴取页级众数，混合旋转排版下“按行序插入”与“按 `top` 升序插入”在滚动回插场景可能不等价。
- **影响**：`test/unit/text/text-integration.test.ts` 与既有用例仅调整 rAF 时序与“DOM 顺序 = 阅读顺序”的假设，断言语义等价于 V1-4。
