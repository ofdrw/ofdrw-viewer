# 网络与文件获取委托设计

OFD 查看器的 engine 只消费已经可读的字节，不发起网络请求，也不读取本地文件。浏览器、Node CLI 和小程序宿主各自负责把 URL、路径或临时文件变成 engine 可消费的来源；crypto 只在需要密码能力时复用同一个字节源。

本文描述当前实现的责任边界、宿主接入方式和验证要求。具体 API 签名见 [engine API](../packages/ofdrw-viewer-engine/skills/API.md)、[UI API](../packages/ofdrw-viewer-ui/skills/API.md)、[CLI 文档](../packages/ofdrw-viewer-cli/skills/SKILL.md) 与 [crypto API](../packages/ofdrw-viewer-crypto/skills/API.md)。

## 1. 定位、目标与非目标

### 1.1 目标

- engine 保持平台无关：不导入 `fetch`、`node:fs`、`node:path`、`wx.*` 或任何宿主 I/O。
- 浏览器 URL 获取、HTTP Range、鉴权头、进度与取消由 UI 负责。
- 本地文件随机读取由 CLI 或 Node 宿主负责；小程序临时文件由小程序宿主负责。
- 字体等附属资源由宿主读取成字节后注入；engine 不解析 URL 或文件路径。
- engine、UI、crypto 在同一次打开流程中共享同一个字节源，避免重复下载或重复探测。

### 1.2 非目标

- engine 不实现 HTTP 客户端、Range 协商、重试、缓存、Cookie、代理或鉴权流程。
- engine 不读取 `file://`、本地路径、微信临时文件或任何宿主文件系统。
- crypto 不实现网络策略、Range、重试、缓存或代理；但它接收的 `CryptoSource.url` 会在包内通过全局 `fetch` 读取完整响应，调用方也可改用 `byte-source` 自行获取并传入字节。
- UI 不实现本地文件系统；`path`/`filePath` 必须由宿主加载器读取。
- CLI 不实现网络下载；它只接受本地文件路径。
- 本文不定义 UI 交互细节、CLI 命令输出字段或 crypto 的密码算法。

## 2. 职责边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| engine | `OFDSource` → `ByteSource` 适配、ZIP 容器、按需读取、资源上限、取消透传 | 网络、文件、临时文件、鉴权、Range |
| UI | URL 字符串/`{url, headers}` 规范化、`HttpByteSource`、HEAD/Range、200/206/416 处理、请求头合并、进度、取消、关闭 | OFD 解析、密码算法、CLI 退出码 |
| CLI | 参数解析、本地文件路径、`NodeFileByteSource`、字体预读、根证书读取、输出与退出码 | 网络下载、浏览器交互 |
| 小程序宿主 | `wx.downloadFile`、`wx.getFileSystemManager`、临时文件生命周期、字体字节 | engine 内部实现、crypto 内部实现 |
| crypto | 接收 `CryptoSource`、检测/解密/验证、密码报告 | 网络策略、文件系统、UI/CLI 展示 |

核心决策：**谁实现 I/O，谁负责错误、取消和资源释放**。engine 只把底层读取错误映射为统一的 `OFDError`；crypto 只把来源错误映射为 `CryptoError`；UI/CLI 把错误映射为自身错误类型和用户文案。字节源所有权按接口契约移交：engine 的 `custom` 来源交给容器，crypto 的 `byte-source` 只被隔离读取、不被 crypto 关闭。

## 3. engine 侧

### 3.1 来源类型

engine 公开的文档来源只有三种：

| `kind` | 字段 | 语义 |
| --- | --- | --- |
| `arraybuffer` | `data: ArrayBuffer \| Uint8Array` | 已完整读入内存的字节 |
| `blob` | `blob: Blob` | 浏览器 `Blob`/`File`；由 engine 按需切片读取 |
| `custom` | `source: ByteSource` | 宿主实现的随机读字节源 |

`url`、`node-file`、`wechat-file` 不是当前 `OFDSource` 的合法变体。运行期传入旧变体时，engine 的适配层会拒绝并给出宿主侧读取指引；类型系统也不接受这些字段。

### 3.2 `ByteSource`

`ByteSource` 是 engine 唯一认识的随机读接口：

```ts
interface ByteSource {
  readonly size: number;                 // 总字节数，byte
  read(offset: number, length: number): Promise<Uint8Array>;
  ready?(): Promise<void>;               // 异步探测大小/可用性
  close?(): Promise<void> | void;        // 释放资源，幂等
}
```

约定：

- `size` 是总字节数，单位 byte；异步探测完成前允许为 0，`ready()` 用于等待探测结束。
- `read()` 返回 `[offset, offset + length)`，越界由实现截断或抛错；返回字节归调用方。
- `close()` 由拥有字节源的容器调用；实现必须幂等。
- 读取失败应抛 `OFDError`，不要返回伪造数据。

### 3.3 适配与容器

`openByteSource()` 只做纯适配：

- `arraybuffer` 包装为内存字节源，空字节直接报 `OFD_INVALID_PACKAGE`；
- `blob` 包装为按需切片源，空 Blob 直接报错；
- `custom` 直接使用宿主实现，要求存在 `read()`；
- 旧变体在运行期被识别并拒绝，不会静默降级为 `arraybuffer`。

`openZipVirtualContainer()` 是默认 ZIP 容器入口。它接受 `OFDSource`，把来源适配为 `ByteSource`，按 ZIP 中央目录读取条目；容器 `close()` 关闭其拥有的字节源。容器可以是 raw package container（`encrypted=true`）或明文容器（`encrypted=false`），由包内容决定，不改变来源适配规则。

### 3.4 字体与附属资源

- `FontInput` 只接受已经读好的 `data`（`ArrayBuffer`/`Uint8Array`）和可选 `family`。
- `defaultFonts` 与 `supplementaryFonts` 都是 `FontInput` 数组；engine 不读取 URL 或路径。
- 需要按需获取字体时，实现 `FontProvider.match()`，在 `match()` 内完成读取并返回 `FontInput`；这是 engine 的字体 I/O 入口。
- 字体解析仍由 fontkit 完成，engine 不解析字体文件之外的宿主资源。

### 3.5 engine 的错误边界

| 情况 | engine 行为 |
| --- | --- |
| 来源字段缺失/类型非法 | `OFD_INVALID_PACKAGE` |
| 旧来源变体 | 拒绝并提示由宿主读取后传 `arraybuffer` 或 `custom` |
| ZIP 结构损坏 | `OFD_INVALID_PACKAGE` |
| 条目缺失 | `OFD_ENTRY_NOT_FOUND` |
| 条目/解压超限 | `OFD_LIMIT_EXCEEDED` |
| 取消 | `OFD_ABORTED` |
| 容器已关闭 | `OFD_CLOSED` |

engine 不把 HTTP 状态码、文件系统 errno 或小程序错误码暴露为公共 API；这些由宿主在适配时转换。

## 4. UI 侧

### 4.1 来源规范化

UI 的 `ViewerSource` 支持字符串 URL、`{ url, headers }`、`ArrayBuffer`、`Uint8Array` 和 `Blob`/`File`。规范化规则：

| 输入 | 输出 `OFDSource` | 说明 |
| --- | --- | --- |
| URL 字符串 | `{ kind: 'custom', source: HttpByteSource }` | 空 URL 报 `OFD_INVALID_OPTION` |
| `{ url, headers }` | 同上 | `headers` 与全局 `requestInit.headers` 合并，来源对象优先 |
| `ArrayBuffer`/`Uint8Array` | `{ kind: 'arraybuffer', data }` | 空字节报错 |
| `Blob`/`File` | `{ kind: 'blob', blob }` | 空 Blob 报错；`File` 同时保留文件名用于 `origin` |

URL 文档不会生成 `sourceKind='url'`。`document:open:start.sourceKind` 取 engine 来源的 `kind`，因此浏览器 URL 文档为 `custom`；若要展示原始 URL，应使用 UI 的 `origin` 或文档命名信息，而不是 `sourceKind`。

UI 还接受页面查询参数作为来源入口：`?file=` 按 URL 解析（http(s) 绝对地址，或以当前页面为 base 的相对路由），`?base64=` 解码为内存字节（支持纯 Base64、URL-safe、缺 padding 和 `data:...;base64,...`）。优先级为显式 `open(source)` > 构造 `source` > 查询参数；`file` 与 `base64` 同时存在时 `file` 优先并产生 `W_QUERY_SOURCE`。解码后默认上限 64 MiB，非法或超限以 `OFD_INVALID_OPTION` 拒绝；没有任何来源时 `ready` 以 `OFD_INVALID_OPTION` 拒绝。查询参数只读 `location.search`，与 `updateHash` 的 hash 状态互不覆盖。详细规则见 [UI 设计方案](ofdrw-viewer-ui设计方案.md)。

### 4.2 `HttpByteSource`

`HttpByteSource` 是浏览器 URL 的随机读字节源：

- 构造时保存 URL、请求头、取消信号、进度回调和可选的 `fetch` 实现。
- 首次 `ready()` 探测大小：先 `HEAD`；`HEAD` 失败或不提供长度时，用 `Range: bytes=0-0` 的 `GET` 探测 `Content-Range` 总长度。
- `read(offset, length)` 使用 `Range: bytes=start-end` 读取；`206` 校验 `Content-Range` 起点与总长度。
- 服务器忽略 Range 返回 `200` 时，整包读取并缓存到内存，后续读取从缓存切片；可通过选项禁用整包回退。
- `416` 在探测阶段表示空文件/服务器拒绝 `0-0`，在读取阶段表示起点越界；读取阶段返回空字节。
- 响应带 `Content-Encoding`（gzip/br 等）时，Range 偏移不可信；实现改为整包下载、解压后切片。
- `206` 的 `Content-Range` 总长度与已探测 `size` 不一致时，也改为整包读取，避免拼接错误。
- 请求头由 UI 合并：全局 `requestInit.headers` 先写入，来源对象的 `headers` 覆盖同名项；`Range` 由字节源自行添加。
- `close()` 中止进行中的请求并移除外部取消监听；重复调用安全。关闭后读取抛 `OFD_CLOSED`。

### 4.3 取消、进度与关闭

- UI 把调用方的 `AbortSignal` 传给 `HttpByteSource`；外部取消会中止当前 `fetch`，并向 engine 表现为 `OFD_ABORTED` 或中止错误。
- `onProgress(loaded, total)` 在整包读取时按块上报；`total` 来自 `Content-Length`，响应有内容编码或缺失时为 `undefined`。
- UI 在文档关闭时关闭 `HttpByteSource`；关闭顺序与 engine 容器关闭一致，避免请求悬挂。
- 同一个 `HttpByteSource` 同时交给 engine 和 crypto；crypto 只创建隔离视图，不关闭它。这样加密检测、解密和渲染不会重复下载。

### 4.4 UI 责任边界

- URL 鉴权通过 `headers` 或调用方自定义 `fetch` 完成，UI 不实现登录流程。
- CORS、TLS、CDN 缓存和重试策略由部署方/浏览器决定，UI 只负责把失败映射为 UI 错误。
- UI 不把完整 URL（可能含 token）写入错误消息或日志。
- UI 不解析 OFD 包；资源大小、ZIP 条目与密码结构由 engine/crypto 处理。
- 交互、加载状态和错误文案以 [`ofdrw-viewer-ui设计方案.md`](./ofdrw-viewer-ui设计方案.md) 为准。

## 5. CLI 侧

### 5.1 本地文件来源

CLI 使用 `NodeFileByteSource` 打开本地 OFD：

- `NodeFileByteSource.open(path)` 以只读方式打开文件句柄，读取文件大小，并确认目标是普通文件。
- `read(offset, length)` 使用 `FileHandle.read()` 随机读取；`FileHandle` 允许短读，实现循环读取直到满足请求长度或 EOF。
- 越界读取截断；`offset >= size` 或 `length === 0` 返回空字节。
- `close()` 关闭文件句柄，重复调用安全；容器关闭时释放。
- 文件不存在/不可读映射为 CLI 路径错误，退出码为使用错误；非普通文件报 `CLI_INPUT_NOT_FILE`。

CLI 把该字节源包装为 `{ kind: 'custom', source }` 交给 engine；不把文件读成整包 `arraybuffer`，以便大文件和按需读取。

### 5.2 字体与根证书

- 字体通过 `loadFontInputs()` 逐个读取文件，得到 `{ data }` 后注入 `supplementaryFonts`；单个字体读取失败产生 `W_FONT_MISSING`，不中止整个转换。
- 系统字体发现受数量上限（6）和总字节预算（96 MiB）约束；预算按已选字体累计。
- 根证书通过 `readTrustRoots()` 读取每个文件，再交给 crypto 的 `certificatesToDer` 转为 DER；CLI 不自行解析 PEM/Base64。
- 字体和根证书都是本地文件读取，不属于 engine 的网络职责。

### 5.3 CLI 边界

- CLI 只接受本地输入路径，不接受 URL 下载；需要远程文件时由调用方先下载。
- CLI 不实现 HTTP Range、鉴权或重试。
- 退出码、错误文案和输出字段由 CLI 设计定义；crypto 的 `CryptoError` 由 CLI 映射，不直接暴露底层 cause。
- 详细命令与参数见 [`CLI设计方案.md`](./CLI设计方案.md) 与 [CLI 文档](../packages/ofdrw-viewer-cli/skills/SKILL.md)。

## 6. 小程序宿主

当前仓库不提供小程序适配包；小程序宿主按下述契约接入：

- 用 `wx.downloadFile` 获取 OFD 文件，或用 `wx.getFileSystemManager()` 读取已有临时文件。
- 将完整字节以 `{ kind: 'arraybuffer', data }` 传给 engine；大文件或需要随机读时，用 `FileSystemManager.read()` 实现 `ByteSource`，以 `{ kind: 'custom', source }` 传入。
- 字体用 `FileSystemManager.readFile()` 读成 `ArrayBuffer`，以 `{ data }` 注入 `supplementaryFonts` 或在 `FontProvider.match()` 中返回。
- 临时文件的生命周期由小程序宿主管理；engine 不删除临时文件，也不持有文件路径。
- 小程序没有 DOM/浏览器 `fetch` 时，crypto 的 `url` 来源不可用；应按需使用 `arraybuffer` 或 `custom`。
- 取消由宿主的中止机制映射到 `ByteSource.read()` 的拒绝；engine 会把取消表现为 `OFD_ABORTED`。

## 7. 安全、取消与限制

### 7.1 安全规则

- **不落明文临时文件**：UI 的 HTTP 字节源直接在内存/流中读取；解密后的 OFD 明文由 crypto 保存在内存容器，不写磁盘。
- **URL 不进入错误**：包含 token、签名参数的 URL 不应出现在错误消息、日志或报告中；UI/CLI 只输出必要的域名/状态。
- **Base64 进入地址栏**：`?base64=` 会把文档内容放进页面 URL，可能进入浏览器历史、服务器日志和 Referer；敏感文档应改用 `?file=` 或宿主直接传 `source`。
- **Cookie 与凭据**：UI 不主动设置 Cookie 头，但 `fetch` 默认 `credentials=same-origin`，同源请求可能携带浏览器已有 Cookie。阅读器的 `requestInit.credentials` 当前不转发，不能通过该选项改成 `omit`；UI 的 `ViewerSource` 也不接收自定义 `ByteSource`。需要禁用同源 Cookie 时，只能在直接使用 engine/crypto 的宿主中自行实现 `ByteSource`，并在 `fetch` 时显式传 `credentials: 'omit'`。
- **Range 正确性优先**：遇到内容编码、总长度不一致或服务器忽略 Range 时，宁可整包读取，也不拼接错误字节。
- **资源上限**：engine 按 ZIP 条目数、单条目大小、解压总量限制；crypto 另有输入包和 ASN.1/XML 上限；UI 不应绕过这些限制直接构造超大数组。
- **所有权按接口移交**：engine 的 `custom` 来源归容器所有，容器 `close()` 调用其可选 `close()`；crypto 的 `byte-source` 只创建隔离视图，不关闭调用方 `ByteSource`；UI/CLI 创建的字节源必须支持幂等关闭，以承受 engine/UI 的重复关闭。engine 不关闭调用方注入的 `container`，只清引用。

### 7.2 取消语义

| 层 | 取消方式 | 表现 |
| --- | --- | --- |
| UI | `AbortSignal` 传入 `HttpByteSource` | 中止 fetch；engine 报 `OFD_ABORTED` |
| engine | 容器读取的 `signal` | 读取边界检查；关闭容器也会中止后续读取 |
| CLI | 进程信号/宿主中断 | 关闭文件句柄，退出码由 CLI 决定 |
| 小程序 | 宿主请求/文件读取中断 | `ByteSource.read()` 拒绝，engine 映射为中止 |

取消不是失败：UI 不把用户取消显示为“文档损坏”，CLI 不把取消当成解析错误。

### 7.3 当前限制

- 没有内置 HTTP 缓存、断点续传、重试、代理、Cookie 管理或请求超时；超时由调用方通过 `AbortSignal` 或自定义 `fetch` 控制。
- `HttpByteSource` 的整包回退会把文档读入内存；超大文件应由部署方保证支持 Range，或由宿主实现自定义 `ByteSource`。
- engine 的 `arraybuffer`/`blob` 来源仍需要可寻址的完整字节；流式顺序读取不在当前接口内。
- 阅读器当前不转发 `requestInit.credentials`，`ViewerSource` 也不接收自定义 `ByteSource`；同源 Cookie 或自定义 fetch 只能在直接使用 engine/crypto 的宿主中控制。
- 小程序适配需要宿主自行实现，仓库不提供 `wx.*` 封装。
- 字体按需加载依赖 `FontProvider.match()`；没有 provider 时只能使用已注入的 `defaultFonts`/`supplementaryFonts` 或文档内嵌字体。

## 8. 验证方式

### 8.1 engine

- 验证 `openByteSource()` 接受 `arraybuffer`/`blob`/`custom`，拒绝旧变体并给出可诊断错误。
- 验证 `openZipVirtualContainer()` 对三种来源返回一致的条目列表和读取结果。
- 验证容器关闭后读取报 `OFD_CLOSED`；容器关闭时调用 `custom` 字节源的 `close()`，重复关闭保持幂等。
- 验证字体只接受 `{ data }`，`FontProvider.match()` 是按需读取入口。

### 8.2 UI

- `test/unit/source/http-byte-source.test.ts` 覆盖 HEAD/Range 探测、206/200/416、内容编码回退、总长度不一致、取消与关闭。
- `test/unit/core/source-normalization.test.ts` 覆盖 URL → `HttpByteSource`、`origin` 保留、请求头合并优先级。
- `test/integration/source.test.ts` 覆盖 URL 只规范化一次、engine 与 crypto 共用同一字节源、`sourceKind='custom'`、加载事件与关闭。
- 验证 `HttpByteSource` 关闭后不泄漏请求，取消不被误报为包损坏。
- `test/unit/source/query-source.test.ts` 与 `test/integration/query-source.test.ts` 覆盖 `?file=`/`?base64=` 解析、优先级、URI 解码、大小上限与错误码。

### 8.3 CLI

- `test/unit/node-file-source.test.ts` 覆盖随机读、短读循环、越界、关闭与错误映射。
- `test/unit/fonts.test.ts` 覆盖字体目录扫描、数量/字节预算、读取失败 warning。
- `test/verification/cli-info-verify.test.ts` 覆盖本地文件打开与验证链路。
- 验证 CLI 不发起网络请求，根证书经 `certificatesToDer` 转换后才进入 crypto。

### 8.4 小程序宿主

- 宿主自测应覆盖 `wx.downloadFile` 成功/失败、临时文件读取、`ByteSource` 短读、取消和临时文件清理。
- 用同一份 OFD 分别以 `arraybuffer` 与 `custom` 打开，页面/条目结果应一致。
- 字体字节通过 `FileSystemManager.readFile()` 读取后注入，缺字体时应有可诊断 warning。

### 8.5 验收口径
