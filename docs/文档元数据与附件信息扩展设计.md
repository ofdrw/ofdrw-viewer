# 文档元数据与附件信息扩展设计

## 1. 背景与目标

当前 engine 的 `getMetadata()` 只读取 `OFD.xml` 的 `DocInfo` 节点，返回 13 个字段；UI 由 `ViewerState.document.metadata` 直接透传该结构，文档属性对话框只展示 11 行；CLI 的 `info --json` 是 engine 字段的手抄子集。

与此同时存在三类缺口：

1. **已解析但未暴露**：`DocInfo/DocUsage` 在模型层（`packages/ofdrw-viewer-engine/src/model/doc-info.ts`）已解析，但从未映射进 `DocumentMetadata`。
2. **完全未解析**：`OFD@DocType`、`Document.xml` 的 `DocumentHeader`、`DocBody/MaxUnitID` 等包级属性当前被解析器整体跳过。
3. **附件能力单薄**：仅有 `getAttachments()` 返回元信息与 `getAttachmentData()` 返回整块字节，缺少按名称/格式查询、流式保存、字段完整性，UI 也没有任何附件入口。

本文定义本轮扩展的目标形态：engine 元数据补齐包级属性、UI 提供文档信息聚合接口与附件侧栏、CLI 同步新字段、附件查询与下载能力端到端可用。

## 2. 范围

### 2.1 包含

- engine `DocumentMetadata` 增加可选子对象：`docUsage`、`docType`、`documentHeader`、`packageInfo`、`commonData`。
- 新增 `Document.xml` 头部解析（`DocumentHeader`）。
- engine 附件接口扩展：按名称/格式查询、流式保存、大小查询，`AttachmentInfo` 字段补齐。
- 新增错误码 `OFD_NOT_OPENED`。
- UI 新增 `getDocumentInfo()` 与自有的 `ViewerDocumentInfo` 聚合结构。
- UI 新增附件侧栏 tab：列表展示、单个下载、批量 ZIP 导出、大附件确认、安全限制。
- UI 文档属性对话框按分组完整展示基础信息。
- CLI `info --json` 与文本输出同步新字段。
- 四份文档（engine API、UI API、UI 使用的引擎 API、跨包契约）同步更新。

### 2.2 不包含

- 不新增 outline/bookmark/signature 等统计计数字段（已明确排除）。
- 不把新字段铺进 `ViewerState.document`；`getDocumentInfo()` 按需调用。
- 不修改文档属性（只读能力，不涉及写入）。
- 不移除或改变现有 13 个 `DocumentMetadata` 字段的语义。
- 不在 UI 中执行任何附件内容（HTML/JS/脚本一律不渲染）。

## 4. engine 设计

### 4.1 `DocumentMetadata` 扩展

保持 13 个原字段不变，新增 5 个可选字段，全部 optional，向后兼容：

```ts
export interface DocumentMetadata {
  // —— 原有字段，语义不变 ——
  version: string;
  pageCount: number;
  packageSize?: number;
  title?: string;
  author?: string;
  subject?: string;
  abstract?: string;
  creationDate?: string;
  modDate?: string;
  creator?: string;
  creatorVersion?: string;
  keywords?: readonly string[];
  docId?: string;
  customData?: Readonly<Record<string, string>>;

  // —— 新增字段 ——
  /** DocInfo/DocUsage。 */
  docUsage?: string;
  /** OFD@DocType，例如 `OFD`/`Render`/`None`。 */
  docType?: string;
  /** Document.xml 头部声明。 */
  documentHeader?: DocumentHeader;
  /** OFD 包级结构信息。 */
  packageInfo?: OfdPackageInfo;
  /** CommonData 摘要。 */
  commonData?: CommonDataSummary;
}
```

设计取舍：

- **收敛成子对象而非平铺**：包级结构（Header、Package、CommonData）属性数量多、来源文件不同，平铺会让 `DocumentMetadata` 膨胀到 30+ 个同级字段，难以分辨来源。
- **不改 `getMetadata()` 的 IO 契约**：所有新字段均在 `open()` 阶段的既有解析过程中产生，`getMetadata()` 仍然只读内存缓存，不做额外包内读取。
- **缺失即省略**：与现有可选字段一致，解析不到时不出现 key，不填 `undefined` 占位。

### 4.2 新增子类型

```ts
/** Document.xml 头部声明；几何单位 mm，同时保留 XML 原文。 */
export interface DocumentHeader {
  /** Document@DocID。 */
  docId?: string;
  /** Document@Version。 */
  version?: string;
  /** Document@MaxUnitID。 */
  maxUnitId?: number;
  /** 页面区声明。 */
  pageArea?: DocumentPageArea;
  /** PublicRes 包内路径。 */
  publicRes?: string;
  /** DocumentRes 包内路径。 */
  documentRes?: string;
  /** TemplatePageRes 包内路径。 */
  templatePageRes?: string;
  /** DefaultCS 颜色空间 ID。 */
  defaultCs?: string;
  /** Document@DocUsage。 */
  docUsage?: string;
}

/** 页面区三组矩形；几何单位 mm，原文同时保留。 */
export interface DocumentPageArea {
  /** 物理页面区。 */
  physicalBox?: Box;
  /** 显示区。 */
  applicationBox?: Box;
  /** 出血区。 */
  bleedBox?: Box;
}

/** OFD 包级结构信息。 */
export interface OfdPackageInfo {
  /** 选中文档根目录，包内绝对路径，已去掉前导 `/`。 */
  docRoot: string;
  /** DocBody@MaxUnitID。 */
  maxUnitId?: number;
  /** OFD.xml 声明的 DocBody 数量。 */
  docBodyCount: number;
}

/** CommonData 摘要。 */
export interface CommonDataSummary {
  /** 公共页面区，mm。 */
  pageArea?: DocumentPageArea;
  /** 默认颜色空间 ID。 */
  defaultColorSpaceId?: string;
  /** Document.xml@Version。 */
  documentVersion?: string;
  /** 数据目录，包内路径。 */
  dataDir?: string;
}
```

约束：

- 所有几何字段使用 `Box`（mm），与 `PageInfo`、`SignatureStampInfo` 的坐标约定一致。
- 包内路径统一经 `resolvePackagePath` 规范化，去掉前导 `/`。
- 非法数值降级为省略并上报 `W_METADATA_FIELD`，不阻断打开。

### 4.3 解码层改动

| 文件 | 改动 |
| --- | --- |
| `src/model/decode.ts` | `decodeOfdRoot` 读取 `OFD@DocType` 与各 `DocBody@MaxUnitID`，返回类型 `OfdRootInfo` 增加 `docType`、`maxUnitIds` |
| `src/model/decode.ts` | `decodeDocument` 解析头部节点，结果写入 `DocumentModel.header` |
| `src/model/document-header.ts` | 新增：`decodeDocumentHeader(node, options): DocumentHeader` |
| `src/model/types.ts` | `DocumentModel` 增加可选 `header?: DocumentHeader` |
| `src/api/document.ts` | 打开阶段把上述结果并入 `metadata` |

`decodeDocumentHeader` 复用现有 `attr`/`child`/`childText`/`parseBoxChild` 工具，不新增 XML 遍历原语。

### 4.4 错误码

新增 `OFD_NOT_OPENED`：

- 语义：调用方在文档未打开（或 UI 未加载文档）时请求文档级信息。
- 使用方：UI `getDocumentInfo()`。
- 与 `OFD_CLOSED` 的区别：`OFD_CLOSED` 表示已打开后又被关闭；`OFD_NOT_OPENED` 表示从未成功打开。

涉及文件：`src/errors.ts`（错误码注册）、`src/errors.ts` 的 `OFDErrorCode` 联合类型、`docs/CONTRACTS.md` §错误注册表。

## 5. engine 附件能力扩展

### 5.1 `AttachmentInfo` 字段补齐

在现有 `id`、`name`、`format`、`size`、`creationDate`、`modDate`、`visible`、`usage` 基础上新增：

```ts
/** MIME 类型；由 Attachment@ContentType 或 format 推断，未声明时省略。 */
contentType?: string;
/** Attachment@Desc。 */
description?: string;
/** Attachment@SubmissionDate 原文。 */
submissionDate?: string;
/** 是否加密存储；未声明时省略。 */
isEncrypted?: boolean;
```

### 5.2 新增方法

```ts
/** 按名称精确查找；重名时返回第一个并上报 W_DUPLICATE_RESOURCE。 */
getAttachmentByName(
  name: string,
  options?: { signal?: AbortSignal },
): Promise<AttachmentInfo | undefined>;

/** 按格式（大小写不敏感）筛选，保持 XML 顺序。 */
getAttachmentsByFormat(
  format: string,
  options?: { signal?: AbortSignal },
): Promise<readonly AttachmentInfo[]>;

/** 流式写出附件内容；返回写入字节总数。 */
saveAttachment(
  attachmentId: string,
  sink: (chunk: Uint8Array) => void | Promise<void>,
  options?: { signal?: AbortSignal },
): Promise<number>;

/** 读取声明的大小；未声明时 undefined。 */
getAttachmentSize(
  attachmentId: string,
  options?: { signal?: AbortSignal },
): Promise<number | undefined>;
```

设计取舍：

- **sink 采用回调式**：附件可能是数十 MB 的 PDF/图片，返回整块 `Uint8Array` 会让主线程同时持有容器副本与解码副本；回调式允许宿主流式落盘或分块入 Blob。
- **`saveAttachment` 失败语义**：sink 抛错时原样向上抛，已写入的字节不回滚，由调用方决定是否清理；引擎仅保证不再继续读取。
- **保留 `getAttachmentData`**：既有调用方不受影响，新代码优先使用 `saveAttachment`。

### 5.3 资源限制

- 单附件大小上限复用 `limits.maxAttachmentBytes`（若未配置则回退 `maxResourceBytes`）。
- 超限时抛 `OFD_LIMIT_EXCEEDED`，不返回部分数据。
- sink 收到的 chunk 顺序严格等于包内字节顺序。

## 6. UI 设计

### 6.1 `getDocumentInfo()`

```ts
/**
 * 读取当前文档的完整信息快照。
 *
 * 需文档已打开；未打开时抛 OFD_NOT_OPENED。
 */
getDocumentInfo(): Promise<ViewerDocumentInfo>;
```

```ts
export interface ViewerDocumentInfo {
  /** 引擎完整元数据。 */
  metadata: DocumentMetadata;
  /** 总页数。 */
  pageCount: number;
  /** 全部页尺寸。 */
  pageInfos: readonly PageInfo[];
  /** 权限声明。 */
  permissions: DocumentPermissions;
  /** 附件元信息列表。 */
  attachments: readonly AttachmentInfo[];
  /** 签章条目数。 */
  signatureCount: number;
  /** 大纲顶层条目数。 */
  outlineCount: number;
  /** 书签条目数。 */
  bookmarkCount: number;
  /** 打开来源；内存字节打开时省略。 */
  origin?: ViewerOrigin;
}
```

约束：

- **按需调用**：不铺进 `ViewerState.document`，避免状态快照变重、避免每次 `patchDocument` 都触发订阅者重渲染。
- **一次性聚合**：内部并发调用 `getMetadata()`、`getPermissions()`、`getAttachments()`、`getSignatureEntries()`、`getOutline()`、`getBookmarks()`，全部命中引擎缓存。
- **未打开**：抛 `OFD_NOT_OPENED`，而非返回空壳，避免调用方误判为“文档没有元数据”。
- **与 `getPermissions()` 的关系**：`getPermissions()` 在未打开时返回宽松默认值，保持现状；`getDocumentInfo()` 是严格接口。

### 6.2 附件侧栏 tab

#### 6.2.1 位置与开关

- 与现有 `thumbnails`/`outline`/`bookmarks`/`signatures` 并列，新增 `attachments` 侧栏视图。
- 接入现有 feature gate，新增能力项 `attachments`；关闭时 tab 不渲染、`openSidebar('attachments')` 无效。
- 无附件或文档未打开时不渲染 tab。

#### 6.2.2 列表

| 列 | 内容 | 缺失时 |
| --- | --- | --- |
| 名称 | `AttachmentInfo.name` | 必填，不存在即跳过该条 |
| 格式 | `AttachmentInfo.format` | 显示 `-` |
| 大小 | `AttachmentInfo.size` 格式化为 KB/MB | 显示 `-` |
| 日期 | `AttachmentInfo.modDate`，缺失回退 `creationDate` | 显示 `-` |
| 操作 | 单个下载按钮 | — |

#### 6.2.3 下载

- **实现**：`saveAttachment()` 分块收集 → `Blob` → `URL.createObjectURL` → 隐藏 `<a download>` 触发 → `revokeObjectURL` 释放。
- **文件名**：优先 `name`，其次 `id`；过滤路径分隔符与控制字符。
- **大附件确认**：单附件大小超过阈值（默认 **50 MB = 52428800 byte**）时先弹确认框；用户取消则不读取。
- **错误处理**：读取失败上报 `W_ATTACHMENT_RESOURCE` 并 toast 提示；不抛到宿主。

#### 6.2.4 批量导出

- 顶部提供“导出全部”按钮，将全部附件打包为 ZIP 下载。
- ZIP 条目名使用附件 `name`，重名追加序号后缀。
- 部分附件读取失败时跳过并汇总提示，不影响其余条目。

#### 6.2.5 安全约束

| 约束 | 行为 |
| --- | --- |
| 不执行附件内容 | 一律不插入 DOM、不使用 `innerHTML`、不使用 `srcdoc` |
| 未知格式 | 只提供下载，不提供预览 |
| 单附件大小上限 | 超过限制拒绝读取并提示，不上传、不缓存 |
| 文件名 | 去除 `/`、`\`、`..` 与控制字符，避免路径穿越 |

#### 6.2.6 国际化

新增 `attachments.*` 词条组，命名对齐现有 `properties.*`：

- `attachments.title`（侧栏标签）
- `attachments.name` / `attachments.format` / `attachments.size` / `attachments.date`
- `attachments.download` / `attachments.exportAll`
- `attachments.empty`（空状态提示）
- `attachments.confirmLarge`（大附件确认文案，含 `{name}`、`{size}` 占位）
- `attachments.error`

### 6.3 文档属性对话框

按分组完整展示，任一分组内全部字段缺失时隐藏该分组：

| 分组 | 字段 |
| --- | --- |
| 文档属性 | 标题、作者、主题、摘要、关键字、文档用途、文档 ID、创建时间、修改时间、创建工具 |
| 包信息 | OFD 版本、文档类型（`docType`）、DocRoot、MaxUnitID、DocBody 数、页数、包大小 |
| 页面设置 | 物理页面区、显示区、出血区（宽×高 mm + 原点） |
| 颜色与资源 | 默认颜色空间、公共资源、文档资源、模板资源、数据目录 |
| 安全与结构 | 权限 6 项、打印份数、签章数、附件数、大纲条目数、书签数 |
| 附件清单 | 名称、格式、大小、日期（只读，不做下载入口） |

## 7. CLI 设计

### 7.1 `info --json`

`CliDocumentInfo` 平铺同步全部新字段：

```ts
export interface CliDocumentInfo {
  // —— 原有 ——
  version: string;
  pageCount: number;
  pageSizes: readonly CliPageSize[];
  title?: string;
  author?: string;
  // ……
  customData?: Readonly<Record<string, string>>;
  // —— 新增 ——
  docUsage?: string;
  docType?: string;
  documentHeader?: DocumentHeader;
  packageInfo?: OfdPackageInfo;
  commonData?: CommonDataSummary;
}
```

- 子对象整体平铺为 `documentHeader`/`packageInfo`/`commonData`，不展开到顶层，避免与 `version` 等字段混淆。
- 缺失字段省略策略与 engine 保持一致。

### 7.2 文本输出

在现有行之后按有值才显示的原则补充：

- `文档用途: …`（`docUsage`）
- `文档类型: …`（`docType`）
- `文档根: …`（`packageInfo.docRoot`）
- `附件: 3 个`（`attachments.length`，需新增一次 `getAttachments()` 调用）

`info` 仍为只读查询，不新增 `attachments` 子命令（待后续按需扩展）。
