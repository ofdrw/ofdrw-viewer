## 5. 仍开放的 major（非本次架构 blocker，T11 风险）

### M01 Pattern `patternId` 仍未在样式层填写

**证据**：

- `src/style/paint.ts:75-88` 的 `toPatternSpec` 仍不填 `patternId`；
- `src/render/prepare.ts:545` 注释明确“样式层只产出带 cell 的 PatternSpec，没有 patternId”；
- `src/render/prepare.ts:558` 用 `PATTERN_CELL_IDS` 反查补齐，`PATTERN_CELL_IDS` 是 `WeakMap<PageBlock, ResourceId>`，只在 prepare 内可用；
- 契约 `docs/CONTRACTS.md:331` 仍要求“样式层 resolvePaint() 填 patternId”。

**影响**：默认 `drawPage` 路径可画（wrapper 补偿），但把 `PatternSpec` 直接交给自定义 binder/custom renderer 时仍拿不到资源 ID；与 §7.3 公共流程不一致。若后续允许同一 cell 对应多个 Pattern ID，cell 反查也不足以区分。

**结论**：功能闭环，**契约未闭环**；不属于架构门禁 blocker。**Owner**：dev-model（style `resolvePaint` 上下文传 Pattern ID）＋ dev-pipeline（`toPatternSpec` 填写/兜底策略）；契约由 architect 裁决。

### M02 模板加载失败后按位置回退

**证据**：`src/render/page.ts:187-197`：

```ts
const model = byId.get(ref.id) ?? templates[index];
```

`prepare` 加载失败的模板被丢弃后，`templates` 数组会缩短；若 A 失败、B 成功，ref A 回退到 `templates[0]=B`，ref B 又按 ID 找到 B，B 被画两次、A 被错误替换。测试目前未覆盖“A 失败、B 成功”的组合。

**影响**：模板缺文件/坏 XML 时不是跳过 A，而是画错/重复；页尺寸回退和 A08 顺序都可能错误。

**修复**：只按 ID 匹配；缺失时跳过并 warning，禁止 positional fallback；若要保留失败占位，`PreparedPageBundle.templates` 改为 `(PageModel | undefined)[]` 或 `Map<ResourceId, PageModel>`。**Owner**：dev-pipeline＋dev-api。

### M03 composite cacheKey/嵌套样式

**证据**：

- `src/render/prepare.ts:366`：`cacheKey: composite:${id}`；
- `src/render/prepare.ts:339-340`：`blocks.get(id)` 直接复用，未区分 `styleRoot`/DrawParam；
- `compositeStyles` (`prepare.ts:318-330`) 每个资源 ID 只保留第一个样式；
- `buildComposite` 嵌套调用 (`prepare.ts:378-379`) 使用父 `styleRoot`；pattern cell 内 composite 使用 `defaultStyle` (`prepare.ts:413-414`)。

**影响**：同一 CompositeGraphicUnit 在同一页不同父样式/DrawParam 下复用时，第二次复用第一次的显示列表；嵌套复合/底纹内复合的样式可能丢失。设计 §11.7/设计 1576 要求 cacheKey 含资源 ID、内容哈希、styleRoot 哈希、DrawParam 哈希。

**修复**：按设计生成 cacheKey；`blocks` 按 variant key 区分或在 bundle 中记录 variant；`resolveComposite` 传入嵌套对象在父 styles 中的结算样式；pattern cell 用 cell styles。需 architect 决定 bundle key 形态（资源 ID 兼容层或 `blocks` + variant 映射）。**Owner**：dev-pipeline。

### M04 Pattern RelativeTo=Page 未接线

**证据**：`src/render/paint.ts:508-520` 只在 `context.objectToPage` 存在时算逆矩阵；`src/render/page.ts:77-91` 的 `createPaintBinder` 未传 `objectToPage`；全仓仅 `test/render/paint/paint.test.ts:300` 单测有该字段。

**影响**：所有 `RelativeTo="Page"` 的 Pattern 都走 fallback `W_UNSUPPORTED_PAINT` 并按 Object 处理；设计 13.4/A15 的 Page 参考点不完整。

**修复**：`drawPage`/`drawObject` 维护当前对象→页面矩阵（`M_page⁻¹ × objectMatrix`），通过 binder context 闭包传给 `resolvePattern`；补 Page-relative Pattern 集成测试。**Owner**：dev-pipeline。

### M05 deferred substitution mode 丢失

**证据**：`src/render/object.ts:84-87` 的 `DeferredImagePlan` 只有 `object/role`；`:491` 构建期固定 `substitutionMode: 'never'`；`:224-245` 的 `resolveDisplayImage` 仍按 `dpi>200` 选替换图。CONTRACTS §7.9/§7.12 要求 resolver 决定 auto/always/never。

**影响**：独立块/注释/复合对象里 `always`/`never` 不生效；低 dpi 强制替换图或高 dpi 强制主图会选错。直接 `drawImageObject` 路径有单测，块路径没有。

**修复**：plan 记录 mode（或构建期把 resolver 决策固化）；`createDeferredImageHandle` 增加 mode；`resolveDisplayImage` 用 plan.mode；补块内 always/never 测试。**Owner**：dev-pipeline。

### M06 公开 block/annotation 回放无 resolver

**证据**：

- `src/render/block.ts:222` `replayDisplayList(renderer, displayList)` 无 resolver；
- `src/render/block.ts:258` `drawIndependentBlock({ renderer, binder, onWarning }, block)` 无 resolver；
- `src/render/annotation.ts:107` 同类函数也无 resolver；
- 页面主路径 `object.ts:626/633` 有 resolver，所以主路径暂时未暴露。

**影响**：调用公开 `drawIndependentBlock`/`drawAnnotationBlocks` 绘制含图片的注释/复合块时，deferred 占位句柄会到达 H5 renderer 并抛 `OFD_RENDERER_UNSUPPORTED`；与“任何公开回放路径必须先物化”的契约冲突。

**修复**：两函数增加可选 `resolveImage?: DisplayListImageResolver`；无 resolver 且列表含占位句柄时显式 warning/拒绝，不静默；合并 `block.ts` 与 `annotation.ts` 的重复 `drawAnnotationBlocks`。**Owner**：dev-pipeline。
