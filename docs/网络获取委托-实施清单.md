## 0. 结论先行（供 captain 排期）

1. **阻断性差异（必须先解决）**：UI 现在对同一个 URL 会调用两次 `normalizeViewerSource()`——`crypto/service.ts:261` 一次、`document-controller.ts:282/298` 一次。若只把 `url` 改成 `custom ByteSource`，会创建两份 `HttpByteSource`、发两轮探测请求，直接违反设计 §13“同一 URL 文档只建立一份字节源”。见 `[DEC-1]`。
2. **删除 `node-file`/`wechat-file` 会连带破坏 UI 编译**：`packages/ofdrw-viewer-ui/src/export/filename.ts:59-64` 直接分支这两个变体（`export/host.ts:17-27` 把 `source` 透传给该逻辑）；同时 `resolveDocumentName()` 依赖 `source.kind === 'url'` 取文件名，改为 `custom` 后无标题的 URL 文档导出名会退化为 `document`。设计 §5.2 要求“保留 origin”，但未指定落点，需决策。见 `[DEC-2]`。
3. **取消信号目前没有真正到达引擎/网络**：`viewer.open()` 有 `abort.signal`，但 `document-controller.ts:310-349` 创建了自己的 `AbortController`，既没把外部 signal 传给 `OFDDocument.open`（引擎支持 `OFDOpenOptions.signal`），也没传给未来的 `HttpByteSource`。设计 §5.6 的“取消打开”无法仅靠现有结构实现。见 `[DEC-3]`。
4. **加密 URL 文档的字节源归属未实现**：UI 只跟踪 `decryptedContainer`，没有跟踪 `HttpByteSource`；设计 §5.4 要求加密路径由 UI 关闭、明文路径由 engine 关闭，必须引入“本次打开创建的字节源”引用与幂等关闭。见 `[DEC-4]`。
5. **CLI 字体匹配语义可能漂移**：现在把所有字体以 `supplementaryFonts: [{path}]` + `loadInput` 交给 engine，由 engine 读取全部字体并按真实 family 评分；改成 `FontProvider` 后，若只返回“名字命中的一个字体”，会丢失原有回退与 TTC/OTC 多字体面行为；即使返回全部候选，engine 也会按 `scoreFace` 对 provider 候选排序（`provider.ts:382`），与 supplementary 的配置顺序不同。建议 `NodeFontProvider` 返回全部候选并按路径缓存，同时用改造前后转换输出对比兜底；若对比失败，由 captain 在“严格按设计用 provider”与“CLI 直接读成 `{data}` 传 supplementaryFonts（行为最等价但偏离设计）”之间决策。见 `[DEC-5]`。
6. **基线不是全绿**：engine 全量测试有 1 个性能用例稳定失败（见 §7 `[B-1]`）；UI/CLI 的个别超时是并行负载导致的假失败（隔离运行全绿）。验收时必须按 §7 的“隔离运行”方式判定。
7. **工作区已有 18 个已修改文件 + 2 个既有未跟踪文件**（本清单文件是第 3 个未跟踪文件，不属保护对象），其中部分正在被其他工作流继续修改（核对期间 `more-menu.ts`、`output.spec.ts` 的 mtime 仍在变化）。本团队禁止修改/暂存/提交这些路径，详见 §8。

### 3.2 `OFDSource` 新契约（实现者可直接照此写）

```ts
export type OFDSource =
  | { kind: 'arraybuffer'; data: ArrayBuffer | Uint8Array }
  | { kind: 'blob'; blob: Blob }
  | { kind: 'custom'; source: ByteSource };
```

`openByteSource()` 行为：

| 输入 | 行为 |
|---|---|
| `arraybuffer` 且非空 | 包装 `ArrayBufferSource` |
| `blob` 且 `Blob` 存在、size>0 | 包装 `BlobSource` |
| `custom` 且 `read` 为函数 | 原样返回（engine 后续按需调用 `ready()`/`read()`/`close()`） |
| `url` | 抛 `OFD_INVALID_PACKAGE`，message 带“旧 → 新”迁移指引（设计 §8 明确要求） |
| `node-file`/`wechat-file` | 抛 `OFD_RENDERER_UNSUPPORTED`（保持现有错误码），message 提示改用 `custom` |
| 其他未知值 | 抛 `OFD_INVALID_PACKAGE`，message 含实际 `kind` |

### 3.3 字体委托新契约

- `FontInput` 只表示字节；`defaultFonts`/`supplementaryFonts` 遇到非 `data` 输入时 warning 并跳过，不抛错、不中断打开。
- `FontProvider.match()` 是字体按需读取的唯一入口；provider 返回 `{ data }`，engine 不发起任何 fetch/文件读取。
- `maxFontBytes`（默认 64 MiB/字体）继续在 `FontLibrary.readInput()` 校验；超限 warning `W_FONT_MISSING` 并跳过。
- `family` 保留，仅用于诊断/别名匹配；真实 family 仍以字体文件内表为准。

### 4.3 取消、进度与加密共享（实现要点）

- **取消**：`viewer.open()` 的 `abort.signal` 传入 `HttpByteSource`；同时把 `signal` 传给 `OFDDocument.open`，避免“UI 已放弃但 engine 仍在读”。`document-controller` 不再创建与外部无关的孤立 AbortController。
- **进度**：整包回退时通过 `response.body.getReader()` 读流并回调 `onProgress`；Range 模式只回调已读字节、`total` 可为 `undefined`。加载态仍以 `document:open:start/end` 为准，不新增 UI 事件。
- **加密共享**：`toCryptoSource(custom)` → `byte-source`；crypto 的 `isolateByteSource()` 不转发 `close`，因此 crypto 容器关闭不会误关 UI 的源。解密完成后 UI 可提前关闭 HttpByteSource（或等容器关闭后关闭），但必须保证 `close()` 幂等。
- **明文共享**：同一 `custom` 源先被 crypto inspect 读取，再交给 engine；engine 在 `doc.close()` 时调用 `closeByteSource()`。UI 不额外关闭明文源。
- **打开失败**：若 `prepareOpen` 或 engine 打开失败，viewer 的 catch/finally 必须关闭本次新建的 HttpByteSource（engine 已关闭的情况由幂等 close 兜底）。
