# 开发与兼容性规则

本文件规定所有已发布包在演进时必须遵守的兼容性约束。适用于 `@ofdrw/ofdrw-viewer-engine`、`@ofdrw/ofdrw-viewer-crypto`、`@ofdrw/ofdrw-viewer-ui`、`@ofdrw/ofdrw-viewer-cli` 的公开入口。

## 1. 适用范围

以下内容一旦出现在发布版本中，默认视为公开契约：

- 导出的变量、函数、类、类型、枚举成员
- 选项对象的字段与默认值语义
- 事件名与事件负载字段
- 诊断码（`UI_WARNING_CODES` 等码表成员）
- CLI 参数名、退出码、输出字段

内部模块（未从包入口导出）不受本规则约束，但仍建议保留迁移余地。

## 2. 核心原则

1. **向后兼容优先**。删除、重命名、改变语义是最后手段，必须给出理由与迁移路径。
2. **优先扩展而非修改**。新增可选字段、新增参数、新增重载、扩展联合类型，都优于改动既有定义。
3. **保留而非移除**。即使功能下线，也优先留下空实现或转调新 API，让旧调用不报错。

## 3. 禁止与允许

禁止（除非有明确批准并附带迁移方案）：

- 删除或重命名已导出的符号
- 修改既有参数名（破坏解构与文档引用）
- 把可选参数改为必填，或收紧既有类型
- 改变默认值从而改变既有行为
- 从公开码表中移除已有码值
- 改变同名选项的单位或坐标系

允许且无需特别审批：

- 新增可选字段或可选参数
- 新增导出、新增事件、新增重载
- 扩展联合类型（只增不减）
- 修正文档、补充注释、补充测试

## 4. 过时标记

过时接口必须保留，并标注 `@deprecated`。注释中必须写清两件事：**为什么过时**、**用什么替代**。没有替代方案时，明确写「调用无效」或「不再生效」。

```ts
/**
 * @deprecated 自 0.2.0 起改为按页淘汰，该上限不再生效。
 * 请使用 {@link textLayerMaxSpans}。
 */
export const MAX_TEXT_LAYER_NODES = 100000;
```

规则：

- **过时接口不会被移除**。标注 `@deprecated` 只表示不建议继续使用，不承诺任何移除时间；不要在注释、文档或发布说明里写「计划在某版本移除」。长期保留兼容层是本项目的既定选择，移除会破坏调用方。
- 运行时如需提示，使用诊断码发出告警，不要用 `console.warn`。
- 过时项不得静默改变行为；确需失效时，在注释与发布说明中写明失效方式。
- 若某个过时项确实必须移除，那属于破坏性变更，按第 7 章的流程处理，并且不能以「已标过 `@deprecated`」为由省略迁移方案。

## 5. 兼容层

当旧接口能用新实现等价或近似表达时，**旧接口内部转调新 API**，外部签名与行为保持不变。这样既完成内部演进，又不破坏调用方。

```ts
/** @deprecated 使用 {@link setTextSpanBudget}；此处保留等价行为。 */
export function setMaxTextNodes(limit: number): void {
  setTextSpanBudget(limit);
}
```

无法等价实现时，退化为近似实现并在注释中说明差异；不得直接抛错。

## 6. 测试与回归

公开 API 的正确性必须由可执行的用例保证，不能只靠文档描述。

- **新增或变更公开 API 时附带用例**：覆盖输入、输出、默认值、边界与错误分支，用例应能独立验证该 API 的契约。
- **修复缺陷必须补回归用例**：先写出能复现失败的用例，再修到通过，用例保留。没有复现用例的修复视为未验证。
- **兼容层要验证等价**：过时接口转调新 API 后，保留原有用例并通过；必要时补「新旧两条路径结果一致」的断言。
- **改变行为前先证明覆盖**：删除、收紧或改变语义前，确认现有用例能反映该行为；覆盖不足则先补用例，再动手改。
- **用例只依赖公开契约**：通过公开 API 与确定性输入验证，不依赖内部实现细节、执行顺序或时序巧合。
- **命名与失败信息可定位**：用例名标明契约点，失败输出包含入参、期望值与实际值。

缺陷类用例还应记录问题现象与发现方式，便于日后判断是否复发。测试目录、夹具与命令见 [测试方案](测试方案.md)。

## 7. 破坏性变更流程

确需破坏兼容时，必须全部完成：

1. 在发布说明中单独列出，标注 **Breaking**，说明影响范围与迁移方式
2. 同步更新对应包的 `skills/API.md`
3. 若跨包可见，更新 `docs/CONTRACTS.md`
4. 提供旧写法 → 新写法的代码片段
5. 保留一个版本的过渡期（兼容层或告警）

## 8. 反例

本项目真实发生过一次：`W_TEXT_LAYER_LIMIT` 被从公开码表中静默删除并改名为 `W_TEXT_LAYER_CAP`，从 `HEAD` 到工作区只少了一行，既无 `@deprecated` 过渡，也无迁移说明。后果是按码过滤告警的下游直接失效，且排查时无从对照。

同类风险还包括：把 `data-*` 属性换成 `dataset` 合并写入、把多个内联样式合并为 `cssText`——这些都不改变对外行为，属于允许的内部优化；但一旦**删除对外可观察的属性或码值**，就落入本文件约束范围。
