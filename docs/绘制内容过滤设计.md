# 绘制内容过滤（页级白名单）设计方案

## 1. 背景与目标

当前引擎只能整页绘制；宿主无法在不重新解析文档的前提下，只显示背景、正文、前景、模板或某一类注释。需求是增加一个**页级绘制配置参数**：

- 控制每一层是否绘制：背景、正文、前景、自定义；
- 控制每一层里是否绘制页面自身内容、是否绘制模板内容；
- 控制是否绘制注释，以及绘制哪些类型的注释（多选）；
- 控制是否绘制签章；
- **不传参数 = 全部绘制；传了参数 = 只绘制参数指定的内容（白名单）**。

目标是：

1. 过滤只发生在绘制/文本收集阶段，**不触发重新准备、不重新解码字体和图片**，切换显示层只重绘。
2. 绘制、图片导出、文本层三处的过滤语义完全一致，避免“画面上看不见但还能选中文字”。
3. 参数按页传入；引擎不保存“当前过滤”，旧调用方不传参数时行为与现在完全一致。

非目标：

- 对象级可见性（`Visibility`/`Alpha`）已由样式结算处理，本参数不替代它。
- 文档级默认过滤：参数只作用于单次页级调用，不在 `OFDOpenOptions` 上配置。
- 页面范围/视口裁剪、阅读器缩放旋转。
- 阅读器 UI 的菜单与交互（本文只给接入建议，见 §7）。

## 2. 需求映射

| 用户说法 | OFD 模型 | 现有代码位置 |
| --- | --- | --- |
| 背景 | 页面 `Layer/@Type=Background`；模板 `Template/@ZOrder=Background` | `LAYER_TYPES`、`resolvePageDrawOrder` |
| 正文 | `Layer/@Type=Body`；模板 `@ZOrder=Body` | 同上 |
| 前景 | `Layer/@Type=Foreground`；模板 `@ZOrder=Foreground` | 同上 |
| 自定义层 | 页面 `Layer/@Type=Custom`；模板没有 Custom 归属 | 同上 |
| 模板 | `Template/@ZOrder` 决定插入到背景/正文/前景哪一层 | `TemplateRef.zOrder`、`resolveTemplates` |
| 注释 | 分页注释 `Annot` 的 `@Type` + `Appearance` | `Annotation.type`、`prepared.page.annotationBlocks` |
| 签章/印章 | `StampAnnot` + `Seal.esl`，**不是** `Annot` | `prepared.signatureBlocks` |

模板按 `Template/@ZOrder` 归属过滤，**不按模板页内部的 `Layer/@Type` 过滤**：

例如模板引用 `ZOrder="Background"`，模板页内部可能有 `Body` 图层；用户只画“背景模板”时，整个模板都画，不会因为模板内部有 Body 图层而被拆散。页面自身图层则直接按 `Layer/@Type` 过滤。

## 3. 现状与改造点

### 3.1 现有绘制链路

```
page.render(params)
  └─ OFDDocument.renderPage
       ├─ preparePage（按 DPI 缓存 bundle：字体/图片/模板/注释块）
       └─ drawPage
            ├─ resolvePageDrawOrder：页面/模板图层顺序
            ├─ drawObjects：页面与模板图层
            ├─ prepared.page.annotationBlocks：注释外观
            └─ prepared.signatureBlocks：签章外观
```

`resolvePageDrawOrder` 同时被 `collectTextPageMm`（文本层）复用，这是保证“画面顺序 = 文本顺序”的关键。因此过滤要加在**共享的展开函数**里，而不是只加在 `drawPage`。

### 3.2 改造点清单

| 位置 | 改动 |
| --- | --- |
| `src/render/content-filter.ts`（新增） | 公共过滤类型、常见注释类型常量、规范化、缓存签名 |
| `src/render/page.ts` | `DrawPageOptions` / `PageDrawOrderOptions` / `resolvePageDrawOrder` / `drawPage` 增加过滤；页面层看 `page`、模板看归属层 `templates`；注释/签章循环跳过 |
| `src/model/types.ts` | `IndependentBlock` 增加可选 `annotationType`（内部字段） |
| `src/render/annotation.ts` 或 `prepare.ts` | 构建注释块时写入类型 |
| `src/render/text-content.ts` | 文本收集传入过滤，注释文本同样按类型过滤 |
| `src/api/types.ts` | `PageRenderParameters`、`PageImageExportOptions` 增加 `contentFilter`，并 re-export 公共过滤类型 |
| `src/api/ui-types.ts` | `TextContentOptions` 增加 `contentFilter` |
| `src/api/document.ts` | 渲染/导出/文本透传；文本缓存键加入过滤签名 |
| `src/api/page.ts` | `render` 参数透传（无需改动逻辑，仅类型） |
| `src/index.ts` + `skills/API.md` | 导出新类型并同步文档 |

## 4. 公共 API 设计

### 4.1 类型

新增 `PageContentFilter`、`DrawLayerOptions`、常见注释类型常量：

```ts
/** OFD 规范中的常见注释类型。 */
export const KNOWN_ANNOTATION_TYPES = Object.freeze([
  'Link',
  'Path',
  'Highlight',
  'Stamp',
  'Watermark',
] as const);

/** 常见注释类型。 */
export type KnownAnnotationType = (typeof KNOWN_ANNOTATION_TYPES)[number];

/** 注释类型：常见类型有字面量提示，同时允许宿主自定义扩展。 */
export type AnnotationType = KnownAnnotationType | (string & {});

/** 单个内容层的白名单配置；字段缺省表示不绘制该来源。 */
export interface DrawLayerOptions {
  /** 是否绘制该层中页面自身的内容，缺省 false。 */
  page?: boolean;
  /** 是否绘制该层中的模板内容，缺省 false；Custom 层没有模板归属，忽略。 */
  templates?: boolean;
}

/** 页级绘制内容白名单；不传 filter 表示全部绘制。 */
export interface PageContentFilter {
  /**
   * 各内容层配置。出现即参与白名单；未出现的层不绘制。
   * 布尔 true 等价于 { page: true, templates: true }，false 等价于不绘制。
   */
  layers?: {
    background?: boolean | DrawLayerOptions;
    body?: boolean | DrawLayerOptions;
    foreground?: boolean | DrawLayerOptions;
    custom?: boolean | DrawLayerOptions;
  };
  /**
   * 是否绘制注释，缺省 false。
   * 为 false 时 annotationTypes 被忽略。
   */
  annotations?: boolean;
  /**
   * 只绘制这些注释类型；出现时即使 annotations 未显式 true，也按白名单绘制。
   * 空数组表示不绘制任何注释。
   */
  annotationTypes?: readonly AnnotationType[];
  /** 是否绘制签章戳记，缺省 false。签章不是注释，单独控制。 */
  signatures?: boolean;
}
```

语义要点：

- **不传 `contentFilter`**：全部绘制，与现在完全一致。
- **传 `contentFilter`**：只有出现的、启用的项绘制；未出现的层/注释/签章一律不画。
- 层值 `true` 画整层（页面 + 模板），`false` 或 `{}` 不画该层。
- 层对象 `{ page: true }` 只画该层页面内容，`{ templates: true }` 只画该层模板内容，两者可同时为 `true`。
- `annotations` 与 `annotationTypes`：
  - 都不出现：不画注释；
  - `annotations: true`：画全部注释；
  - `annotationTypes: [...]`：只画列出的类型（`annotations` 显式 `false` 时不画）；
  - `annotationTypes: []`：不画注释。
- `signatures: true` 才画签章；不出现或 `false` 不画。
- 注释类型匹配使用 `Annotation.type` 原值，区分大小写；常见值由 `KNOWN_ANNOTATION_TYPES` 提供，宿主可传任意字符串扩展。

`DrawLayerOptions` 不再需要 `enabled`：层是否出现就是总开关，`page`/`templates` 是来源开关。

### 4.2 参数位置

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `PageRenderParameters.contentFilter` | `PageContentFilter` | 全部绘制 | 单次页面渲染 |
| `PageImageExportOptions.contentFilter` | `PageContentFilter` | 全部绘制 | 单次页面导出 |
| `TextContentOptions.contentFilter` | `PageContentFilter` | 全部绘制 | 单次文本内容查询 |
| `OFDOpenOptions` | 不增加 | — | 引擎不保存文档级过滤，参数按页传入 |

不设置文档级默认，也不做“文档默认 + 单次覆盖”的合并：

- 每次调用独立，传什么画什么；
- 未传就是全画，传空对象 `{}` 就是空白页（白名单里没有任何内容）；
- 导出/文本层不自动继承上一次 `render` 的过滤；UI 需要一致时显式传同一个对象（见 §7）。

### 4.3 示例

```ts
// 1. 全画：不传 contentFilter
await page.render({ canvasContext, viewport }).promise;

// 2. 只画正文页内容 + 签章
await page.render({
  canvasContext,
  viewport,
  contentFilter: {
    layers: { body: true },
    signatures: true,
  },
}).promise;

// 3. 只画背景模板，不画页面自身背景内容
await page.render({
  canvasContext,
  viewport,
  contentFilter: {
    layers: { background: { templates: true } },
  },
}).promise;

// 4. 只画正文页面内容，外加印章类注释，不画签章
await page.render({
  canvasContext,
  viewport,
  contentFilter: {
    layers: { body: { page: true } },
    annotationTypes: ['Stamp'],
  },
}).promise;

// 5. 导出与显示保持一致
await page.exportImage({
  dpi: 144,
  contentFilter: {
    layers: { body: true },
    signatures: true,
  },
});
```

## 5. 内部实现

### 5.1 规范化模块

新增 `src/render/content-filter.ts`，纯函数、无 I/O：

```ts
/** 规范化过滤配置；未传返回“全画”。 */
export function resolveContentFilter(
  filter?: PageContentFilter,
): ResolvedContentFilter;

/** 判断页面自身的某个内容层是否绘制。 */
export function isPageLayerVisible(
  filter: ResolvedContentFilter,
  layer: 'Background' | 'Body' | 'Foreground' | 'Custom',
): boolean;

/** 判断归属某个内容层的模板是否绘制。 */
export function isTemplateLayerVisible(
  filter: ResolvedContentFilter,
  layer: 'Background' | 'Body' | 'Foreground',
): boolean;

/** 判断注释类型是否通过白名单。 */
export function isAnnotationTypeVisible(
  filter: ResolvedContentFilter,
  type: string | undefined,
): boolean;

/** 判断签章是否绘制。 */
export function isSignatureVisible(filter: ResolvedContentFilter): boolean;
```

内部结构：

```ts
/** 规范化后的过滤结果；不导出。 */
export interface ResolvedContentFilter {
  /** 未传 filter，全部绘制。 */
  all: boolean;
  /** 每层白名单；all=true 时无意义。 */
  layers: Record<
    'Background' | 'Body' | 'Foreground' | 'Custom',
    { page: boolean; templates: boolean }
  >;
  /** 是否绘制注释。 */
  annotations: boolean;
  /** 注释类型白名单；null 表示全部类型。 */
  annotationTypes: ReadonlySet<string> | null;
  /** 是否绘制签章。 */
  signatures: boolean;
  /** 稳定签名，供文本缓存与 UI 重绘判断。 */
  key: string;
}
```

`key` 格式稳定、与字段书写顺序无关（`b`/`o`/`f`/`c` 依次为 background/body/foreground/custom，每层两位表示 `page`/`templates`，Custom 没有模板位）：

```
all
none
layers=b:10,o:11,f:00,c:00;annotations=1;types=Highlight,Stamp;signatures=0
```

未传 filter 固定为 `all`；传 `{}` 固定为 `none`。UI 的缓存键在未配置过滤时保持 `all`，不会因升级产生无谓重绘。

### 5.2 图层过滤

`resolvePageDrawOrder` 增加 `contentFilter?: PageContentFilter`：

- 页面图层：`isPageLayerVisible(filter, layer.type)`；
- 模板图层：`isTemplateLayerVisible(filter, templateZOrder(template.ref))`，**不是** `layer.type`，模板内部图层类型不参与过滤；
- `layerOrder='document'` 与 `'type'` 两种模式都应用同一判定。

伪代码：

```ts
const pushLayer = (layer, template?) => {
  if (layer.children.length === 0) return;
  const visible = template
    ? isTemplateLayerVisible(filter, templateZOrder(template.ref))
    : isPageLayerVisible(filter, layer.type);
  if (!visible) return;
  entries.push({ ... });
};
```

`PageDrawEntry.layerType` 保持现在的含义（模板内部图层类型，用于文本项元信息），不改成归属层，避免破坏文本层字段。

注释 entry 的追加也在 `resolvePageDrawOrder` 内完成：

```ts
if (options.includeAnnotations && filter.annotations) {
  for (const block of prepared.page.annotationBlocks) {
    if (!isAnnotationTypeVisible(filter, block.annotationType)) continue;
    entries.push({ kind: 'annotation', block });
  }
}
```

这样文本层只要复用 `resolvePageDrawOrder`，就自动得到与绘制一致的注释过滤。

### 5.3 注释类型过滤

注释块在准备阶段构建，模型里已有 `Annotation.type`，但 `IndependentBlock` 没带类型。方案：

1. `IndependentBlock` 增加可选字段 `annotationType?: string`（`source === 'annotation'` 时填充）；
2. `prepare.ts` 的 `buildBlock` 回调写入 `annotationType: annotation.type`；
3. 绘制时：

```ts
for (const block of prepared.page.annotationBlocks) {
  if (!isAnnotationTypeVisible(filter, block.annotationType)) continue;
  // 原有绘制逻辑
}
```

4. 文本收集时，`collectTextPageMm` 通过 `resolvePageDrawOrder` 已过滤掉非白名单注释，隐藏的注释文字不会进入文本层。

不使用 `block.id` 反查注释类型，因为 `Annot/@ID` 可能缺失或重复，`IndependentBlock.annotationType` 更直接，也不改变块缓存键。

白名单模式下 `annotationType` 缺失视为不匹配（不绘制）；只有 `annotations: true` 且未限制类型时才画全部注释。

### 5.4 签章过滤

`drawPage` 的 `signatureBlocks` 循环前加：

```ts
if (!isSignatureVisible(filter)) {
  // 跳过整个签章循环
}
```

签章不参与文本收集，无需其他改动。

### 5.5 文本层

`TextContentCollectOptions` 增加 `contentFilter?: PageContentFilter`，`collectTextPageMm` 用它构造 `resolvePageDrawOrder` 的过滤参数。

`OFDDocument.loadTextContent`：

- `TextBuildConfig` 增加 `contentFilterKey: string`；
- `textCacheKey` 加入该字段（过滤不同的文本结果不能复用同一缓存）；
- 直接规范化 `options.contentFilter`，不与任何文档级默认合并。

默认 `includeAnnotations=false` 不变；即使用户打开注释文字，也要再过一遍注释类型白名单。

### 5.6 导出

`OFDDocument.exportPage` 把 `exportOptions.contentFilter` 放进内部 `renderPage` 的 `PageRenderParameters`。导出仍然复用同一个 `PreparedPageBundle`，不重新准备。打印走导出图片链路，自动继承调用方传入的过滤。

导出默认**不记忆**“页面最近一次 render 用的过滤”，不传就全画；UI 层导出时应显式传当前过滤（见 §7）。

### 5.7 一致性

所有“某层/某注释类型/签章是否绘制”的判断只放在 `content-filter.ts`。`page.ts`、`text-content.ts`、`document.ts` 都调用同一组函数，禁止各写一套 `if`。每个入口各自调用 `resolveContentFilter`；纯函数成本可忽略，不做跨入口缓存。

## 6. 缓存与重绘

### 6.1 prepare 缓存

`preparedBundles` 仍按 DPI 校验（每页只缓存最近一次准备结果）。过滤是绘制期的纯判定，切换过滤不需要重新读取字体/图片/模板/注释。代价是：即使 `annotations=false`，注释外观块仍会在 prepare 阶段构建。v1 接受这个成本（构建一次、多次切换），换取缓存简单和切换无延迟。

后续如果需要优化“始终不显示注释”的场景，可以给 `preparePage` 增加 `buildAnnotations?: boolean`，并让 bundle 缓存键变成 `dpi + 注释开关`；这属于可选优化，不进入 v1。

### 6.2 文本缓存

`textCache` 键加入 `contentFilterKey`。过滤变化时文本层会重新收集，不能复用旧的 mm 布局，否则会出现“画面上隐藏了正文，文本层仍然能选中正文”。

### 6.3 UI 重绘

引擎不保存当前过滤。UI 若要动态切换，需要：

- 在 UI state 保存当前 `PageContentFilter`；
- `renderKey()` 加入规范化后的 `filter.key`，否则已渲染页不会重绘；
- `setContentFilter()` 后清空页面/缩略图渲染缓存并重新排队可见页；
- 文本层 `viewer-bridge` 把当前过滤传给 `getTextContent`，并清空查找/选择缓存；
- 导出/打印显式传当前过滤。

## 7. UI 接入建议（第二阶段）

本期先落 engine API；UI 接入建议单独排期：

1. `OFDViewerOptions.contentFilter?: PageContentFilter` 作为 UI 初始显示状态（不是引擎文档级默认），默认全画。
2. 实例方法 `setContentFilter(filter)` / `getContentFilter()`，行为：
   - 保存 UI 状态；
   - `renderKey` 变化后重绘当前可见页和缩略图；
   - 更新文本层；
   - 派发 `contentfilterchange` 事件。
3. 工具栏“显示”菜单（可放更多菜单）：
   - 背景、正文、前景：每层一个总开关，下挂“页面内容”“模板内容”两个子开关；
   - 自定义：总开关 + “页面内容”子开关（没有模板）；
   - 注释：总开关 + 类型多选（用 `KNOWN_ANNOTATION_TYPES` 生成常见项，同时允许宿主追加自定义类型）；
   - 签章：独立开关。
4. 缩略图默认跟随主视图过滤；如需“缩略图始终显示全貌”，给缩略图单独传 `contentFilter: undefined`。
5. 导出/打印默认传当前过滤，允许导出选项覆盖。
6. 无障碍：菜单项使用 `role="menuitemcheckbox"`，多选注释类型时保持菜单不关闭；层总开关关闭时，其页面/模板子开关用 `aria-disabled` 表达。
7. i18n 增加对应文案键（中/英）。

注意：UI 的菜单状态是全画还是白名单，需要映射成完整对象。例如用户只关掉背景时，UI 传：

```ts
{
  layers: {
    background: false,
    body: true,
    foreground: true,
    custom: true,
  },
  annotations: true,
  signatures: true,
}
```

因为引擎是白名单，UI 必须把“未关闭的项”显式写出来。

## 8. 兼容性与边界

- 所有新字段可选，不传 `contentFilter` 时输出与现在完全一致。
- `PageContentFilter` 只新增导出，不修改现有类型字段。
- `IndependentBlock.annotationType` 是内部模型的可选字段，不进入公共 API；注释块缓存键不变。
- 过滤不影响页面尺寸、viewport、事件时序、`prepare` 语义。
- 过滤与文档权限无关；权限控制仍在 UI/上层。
- 注释 `Visible=false` 仍在准备阶段跳过，过滤只在其之上再加一层。
- 隐藏背景后 canvas 保留宿主原有像素（`page.render` 不清屏），宿主应自行铺白底/透明底；这与现有约定一致。
- 传 `{}` 会得到空白页，但仍正常执行 beginPage/endPage 并 resolve；这是白名单语义的自然结果。
- 非法输入按“未指定”处理（不绘制对应内容），不抛错；v1 不新增 warning 码。

## 11. 待确认问题

1. **Custom 层是否需要暴露？** 本文默认支持，UI 可以暂时不显示。

4. **UI 是否本期一起做？** 本文按“先 engine API，UI 后续”编写；如需要可以合并排期。
