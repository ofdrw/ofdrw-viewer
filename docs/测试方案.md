## 4. Fixture 生成器

### 4.1 合成 ZIP（`test/fixtures/zip-builder.ts`）

覆盖：

| 场景 | 方式 |
| --- | --- |
| stored / deflate | `method: 'store' \| 'deflate'` |
| ZIP64 条目 | `zip64: true`（本地/中央目录大小写 `0xFFFFFFFF` + 0x0001 extra） |
| ZIP64 EOCD | `{ forceZip64Eocd: true }`（EOCD + locator + ZIP64 EOCD） |
| data descriptor | `dataDescriptor: true`（bit 3，本地头大小/CRC 为 0） |
| 中文/UTF-8 | 名称含非 ASCII 自动置 bit 11；也可 `utf8: true` |
| 重复路径 | 允许多个同名条目 |
| 路径穿越 | 生成器原样写入 `../`，由容器层负责拒绝 |
| 坏包 | 测试侧截断/改魔数，断言解析器抛错 |

生成结果由**独立实现**的 `zip-inspector.ts` 交叉校验（EOCD/中央目录/本地头/解压/CRC），
避免“生成器自证”。

### 4.2 XML 与最小 OFD（`xml.ts`、`ofd-builder.ts`）

- `buildXmlDocument` 做转义并写 XML 声明；
- `buildMinimalOfd({ pageCount, widthMm, heightMm, fonts, ... })` 生成
  `OFD.xml` / `Doc_0/Document.xml` / `Doc_0/Pages/Page_N/Content.xml` /
  可选 `Doc_0/Res/Res.xml` + 字体文件；
- 页数、页尺寸、是否含 PathObject/TextObject 可配置，供容器/模型/管线冒烟。

### 4.3 矩阵/颜色与字体

- `MATRIX_CASES`：单位/平移/96 DPI 缩放/旋转 90°/镜像/页面原点；
- `COLOR_CASES`：RGB 三元组、十六进制、`#AARRGGBB`、CSS、CMYK 近似；
- `findSystemCjkFont()`：按 Linux 常见路径找 Noto/文泉驿，找不到返回 `null`，调用方 skip；
- `loadEmbeddedFontFromOfd()`：从本地 OFD 提取内嵌字体（业务样本只读）。

### 4.4 样本提取（调试用）

```bash
node scripts/golden/extract-fixture.mjs --sample hello
# 输出到 test/.fixtures/hello/（已 gitignore）
```

拒绝绝对路径与 `..` 越界条目；目录条目只建目录。

### 5.3 dense-text-perf 文本性能专项

样本特征：2 页 A4；page0 147 个 TextObject/15442 字符；page1 8331 个 TextObject/15074 字符、
1.45MB Content.xml、约 656k 路径命令；内嵌 SimSun 子集；无 g 压缩组。该样本是专门制造
海量 TextObject 与路径命令的**极端压力样本**，不是普通页的代表。

| 指标 | 采集 | dense stress 阈值（96 DPI） | 普通页目标（不变） |
| --- | --- | --- | --- |
| open | `renderOfdSample().openMs` | < 100 ms | — |
| page0 首次渲染 | 第一次 `page.render` 的 `drawMs` | < 800 ms | < 500 ms |
| 翻页（page1 首次） | 同文档第 2 页 `drawMs` | < 1000 ms | < 150 ms |
| 二次渲染（page0 缓存命中） | 同文档回到 page0 `drawMs` | < 600 ms | < 80 ms |
| PNG 编码 | 每次 `encodeMs` | 只记录，不入门禁 | 只记录，不入门禁 |
| 内存增量 | 3 次渲染前后 `heapUsed` 差 | < 150 MiB | — |

- 口径：`test/golden/lib/engine.ts` 把页准备+绘制（`drawMs`）与 PNG 编码（`encodeMs`）分开；
  `renderMs = drawMs + encodeMs` 仅作展示，**门禁只用 drawMs**；JSON 保留 draw/encode 两项（另附 renderMs 合计）。
- 例外依据：普通页仍按设计方案 18 的 500/150/80ms；dense 样本把阈值提高到 800/1000/600ms，
  只适用于本样本，不能写成普通页目标。用户已确认该例外；若后续优化降低 draw 耗时，仍保留
  stress 上限，不用放宽普通页。
- 当前测量（2026-10-22，96 DPI，连续 3 次）：open 14.2–19.3ms；page0 首次 draw 465.2–614.3ms，
  encode 189.2–216.5ms；翻页 draw 672.4–844.9ms；二次 draw 358.6–383.2ms；
  heap 增量 34.6–52.1MiB；3/3 通过 stress 阈值。
- 测试：`test/golden/text-perf.test.ts`，`pages=[1,2,1]` 一次打开内完成首次/翻页/二次渲染；
  产物写 `test/.artifacts/text-perf/<timestamp>/dense-text-perf.json`；
- 样本缺失时整组 skip；引擎未实现时单测 skip，T9/T11 由 `--require-engine` 对“不可用”判失败；
- 不以 manual 89 页替代本样本：本样本专门制造海量 TextObject/路径命令。

## 6. 黄金图 harness

### 6.1 渲染链路

```text
OFD ──OFDDocument.open({renderer:H5Canvas2DRenderer({createCanvas:@napi-rs/canvas})})──▶ page.render
    ──▶ 白底 PNG（engine）
PDF ──pdftoppm -r 96 -png -f N -l N -singlefile──▶ 参考 PNG（ref）
engine + ref ──pngjs 解码 + pixelmatch + Sobel/ΔE2000/SSIM──▶ 指标 + diff PNG
```

约定：

- **引擎不负责背景**；harness 在 `page.render` 前把画布填白，PDF 参考本身为白底；
- `dpi` 默认 96；PDF pt→px = `pt/72×96`，OFD mm→px = `mm/25.4×96`；
- 画布尺寸 `ceil(viewport)`，并把取整后的 viewport 传给引擎；若引擎严格校验小数尺寸，
  harness 会按 `OFD_CANVAS_SIZE_MISMATCH` 回退到精确 viewport 重试；
- 每个样本/页的产物命名：`pages/<sample>-p<NNN>-engine.png|ref.png|diff.png`。

### 6.2 比较口径（设计方案 19.2）

| 维度 | 判定 | 实现 |
| --- | --- | --- |
| 页面尺寸 | 偏差 ≤ 0.5 mm 或 1 设备像素（取较宽者） | 比较 PNG 宽高 |
| 版式/位置 | 内容 bbox 边缘偏差 ≤ 0.5 mm 或 1 px（取较宽者） | 非背景像素 bbox，换算 mm |
| 关键色 | ΔE2000 ≤ 5 | 双方各取前 8 个主色（排除 AA 边缘，占比 ≥0.2%），最近邻匹配 |
| 关键色占比 | 最近邻主色占比差 ≤ 20% | 防止“红/绿大块互换但两色都还在”漏判 |
| 抗锯齿 | 不计入差异 | Sobel 梯度 > 48 + 1px 膨胀掩码，pixelmatch `ignoreMask` |
| 辅助指标 | SSIM、像素差只记录不判定 | 灰度全局 SSIM；pixelmatch threshold=0.1 |
| 区域 | 3×3 区域记录像素差/覆盖率差 | 用于报告定位，不单独判定 |

判定顺序：`size-mismatch` → `layout-mismatch` → `color-mismatch` → `pass`。
失败原因写入 `metrics` 与 `notes`，报告可定位到页。

### 6.3 基线与人工审核

- 基线目录 `test/golden/baseline/<sample>/page-NNN.png`，白底、与 `dpi` 对应；
- 基线不是“自动快照”：只有人工确认差异属于预期改进后才复制；
- **不提供自动 `--update`**；更新流程见 `baseline/README.md`：
  看报告 → 对比 engine/ref/diff → 记录样本/页/原因/审核人 → 复制 → 重跑；
- 基线缺失不算失败；基线存在但不一致会在报告 `baselineMetrics` 与备注中体现。

阶段说明：

- **T8（当前）**：引擎尚未实现，`run-all` 会把 57 条样本清单记为 `engine-unavailable`，

## 8. 报告格式

产物目录（`test/.artifacts/golden/<timestamp>/`）：

```text
report.json     # 机器读取：summary、tolerance、每个样本/页的指标、warning、错误
report.html     # 人工审核：汇总卡片 + 容差表 + 按样本分组的页表 + 图片链接
pages/
  <sample>-p001-engine.png
  <sample>-p001-ref.png
  <sample>-p001-diff.png      # 差异标红、其余淡出
mock-reference.pdf            # harness 自检用合成 PDF
```

`report.json` 顶层字段：

| 字段 | 说明 |
| --- | --- |
| `schemaVersion` | 固定 1 |
| `kind` | `golden-report` / `mock-selfcheck` |
| `mode` | `engine` / `mock` |
| `dpi` | 输出 DPI |
| `environment` | node/platform/arch |
| `artifactsDir` | 产物绝对路径 |
| `tolerance` | 实际使用的容差 |
| `summary` | 样本/页通过、失败、跳过、不可用、耗时 |
| `samples[]` | 样本元数据、`engineStatus`、warnings、pages[] |

单页字段：`status`（pass/size-mismatch/layout-mismatch/color-mismatch/engine-error/
engine-unavailable/reference-missing/skipped）、尺寸、`metrics`、`baselineMetrics`、
`enginePng/referencePng/baselinePng/diffPng`（相对产物目录）、`renderMs/referenceMs`、`error`。

## 9. 性能、安全、取消与内存（T9/T11 口径）

T8 只提供采集能力，阈值在 T9/T11 按设计方案 18/19.5 判定：

| 项 | 采集方式 | 目标 |
| --- | --- | --- |
| 打开 1000 页 | `openMs` | < 100 ms |
| 首次渲染一页（含 CJK） | 页 `renderMs` | < 500 ms |
| 同文档后续页 | 页 `renderMs` | < 150 ms（96 DPI） |
| 翻页（缓存命中） | 多页循环 `renderMs` | < 80 ms |
| 内存（100 页） | `process.memoryUsage()` 前后快照 | < 250 MB |
| manual 89 页 | 上述指标 + T11 浏览器翻页 | 不崩溃、无明显泄漏 |
| dense-text-perf | `test/golden/text-perf.test.ts`：open/首次 draw/翻页 draw/二次 draw/内存；PNG encode 单列 | open<100ms；首次 draw<800ms、翻页 draw<1000ms、二次 draw<600ms（极端样本 stress 阈值）；heap 增量<150MiB。普通页仍为 500/150/80ms |
| 取消 | Web 验收：连续快速翻页 + `RenderTask.cancel` | promise 以 `OFD_ABORTED` 拒绝，无残留帧 |
| 安全 | 合成 ZIP 坏包/穿越/加密/压缩比 + 资源限制 | 抛 `OFD_*` 错误，不崩溃、不越界写文件 |

### 11.3 夹具、凭据与 Java oracle

统一夹具目录：`packages/ofdrw-viewer-crypto/test/fixtures/crypto/`。

- 12 个 OFD：`plain`、`password-encrypted`、`cert-encrypted`、`signed-sesv4`、`signed-sesv5`、
  `integrity`、`combined-signed-integrity`、`combined-password-encrypted`，以及 4 个负例
  （引用内容/SignedValue/Signature.xml 篡改、夹带未登记文件）。
- 20 个证书/私钥：`root-ca`、`signer`、`encrypt`、`seal`、`tsa` 各 PEM/DER 证书与 PKCS#8 私钥；
  全部为 test-only，禁止用于生产；私钥不设口令。
- 凭据：口令 `fixture-password-user` / `FixturePass123`；证书 `fixture-cert-user` +
  `certs/encrypt.key.pem`（DER 同）。
- 信任根：`certs/root-ca.crt.pem`；无根=`unknown`，配根=`valid`，错误根/配置根但缺中间证书=`incomplete`（链可建但锚不是配置根时为 `untrusted`）。
- `manifest.json` 记录 12 case 的 `credentials`/`expected`、路径/大小/SHA-256；`manifest.sha256`
  供 `(cd packages/ofdrw-viewer-crypto/test/fixtures/crypto && sha256sum -c manifest.sha256)`
  校验。测试不得硬编码随机 FEK/时间戳哈希，以 manifest 为准。

Java oracle（跨语言“真值”）：

```bash
# 校验已提交夹具的哈希与 ofdrw 语义；退出 0 为通过
bash scripts/crypto-fixtures/verify-fixtures.sh

# 可选：重新生成（会改变随机 FEK/时间戳与 manifest，需同步提交）
bash scripts/crypto-fixtures/generate-fixtures.sh
```

- 生成器使用 ofdrw 2.4.0 + JDK 21，只调用公开 API；`verify-fixtures.sh` 不依赖本仓库 JS 实现。
- `crypto/test/verification/decrypt/java-expected.json` 是 `OFDDecryptor` 的逐条目大小/SHA-256；
  `crypto/test/verification/sign/java-expected.json` 是 `OFDValidator`/完整性校验的预期结果。
- 已提交 JSON 后 CI 不需要 Java；仅重新生成/复核 oracle 时需要 JDK 21。
- 过期/未生效证书、双层/循环、超大 ASN.1 等极端输入由测试内生成，不新增静态大文件。

### 11.4 浏览器、SEA 与无障碍

- **crypto 浏览器**：`test/verification/core/build-import.verify.test.ts` 用 esbuild
  `--bundle --platform=browser` 生成 IIFE/浏览器 bundle；真实 Chromium 执行 SM3/SM4/KDF/SM2/证书链。
  源码不得 import `node:*`；Node ESM/CJS 与浏览器导出均须可用。
- **UI E2E**：`pnpm -C packages/ofdrw-viewer-ui exec playwright test` 使用项目 Playwright
  + 真实 Chrome，`webServer` 启动 Vite（默认 4179），只加载仓库夹具；结束后 Playwright 关闭
  Chrome、释放端口，失败截图/trace 放 `test/acceptance/artifacts/playwright/`（不入库）。
  若用 `playwright-cli` 手工复核，必须 `playwright-cli close` 并确认无残留浏览器/端口。
- **CLI SEA**：`pnpm -C packages/ofdrw-viewer-cli test:acceptance` 先构建普通 CLI 与 SEA，
  再跑黑盒 acceptance（含 `verification.acceptance.ts`）；SEA 必须验证 `info`/`verify`/
  口令解密转图，不依赖 Node 运行时。
- **无障碍**：凭据弹窗必须满足 `role=dialog`、`aria-modal=true`、`aria-labelledby`/
  `aria-describedby`、焦点陷阱、Esc 取消、错误 `role=alert`；**每个 input/select 必须有
  `<label for>` 或 `aria-label`/`aria-labelledby` 的程序化可访问名称**（t14 发现、t41 修复、
  t42 复验；独立 axe 扫描 password/cert 弹窗为 0 serious/critical）。验证面板与印章浮层需
  有可读文本、可聚焦控件和键盘路径；不能只用颜色表达失败。
- **秘密边界**：口令、PEM、`EncryptedWK` 不得出现在 stdout/stderr、异常 message、
  URL、localStorage/sessionStorage/cookie、DOM 属性/文本、state/event 或日志；CLI 人类可读
  stderr 需经过 `sanitizeDisplayText`（t43），JSON stdout 保留原值。

### 11.6 CLI 退出码口径

| 退出码 | 语义 | 典型场景 |
| ---: | --- | --- |
| 0 | 成功 | 转图片全部成功；`info` 查询成功（含加密包无凭据）；`verify` 仅 `overall=valid` |
| 1 | 用法/参数/路径错误 | 未知参数/子命令、缺输入、`info` 带凭据/根、`decrypt`、凭据冲突 |
| 2 | 文档级失败 | 非 OFD、包损坏、必需部件缺失、解密前结构错误 |
| 3 | 页级失败 | 至少一页失败且至少一页成功 |
| 4 | 加密/凭据失败 | 缺凭据、用户不存在、口令/私钥错误、解密失败、加密不支持 |
| 5 | 验证未通过 | `verify` 的 invalid/unknown/unsupported/not-applicable；错误根/篡改/夹带 |
| 130 | 用户中断 | SIGINT/AbortSignal |

`info` 不调用解密/验签；`verify` 只调用一次 `verifyOfd`；转图片内部的解密不属于公开
`decrypt` 命令，且不得产生明文文件。

1. 任何 `src/`、测试、`package.json`、锁文件、夹具/manifest 或构建配置变更，都可能使旧 verdict

2. 复验必须记录 `git rev-parse HEAD`、`git status --short`、受影响文件 SHA-256、完整命令与

   需重跑对应层。
4. t14 → t41 → t42 是“失败—修复—复验”的绑定链：t14 仍保留 failed 历史，t42 只证明修复后的

5. **t34 V-FINAL 是最终权威**：必须在所有已知 blocker/medium 修复和 review 完成后，按

6. 不得用“用例数相同/文件未改”推断通过；以当前文件哈希与真实命令输出为准。

## 12. 已知限制

- T8 阶段引擎为 skeleton，`run-all` 只能验证“清单/PDF 参考/报告链路”，
  实际渲染差异要等 T12 完成后用 `--require-engine` 跑；
- `pixelmatch` v8 的阈值基于 OKLab HyAB，与 v5 的 YIQ 不完全等价；
  SSIM 为全局近似，不作为硬门禁；
- PDF 是版式参考而非逐像素基线：字体替换、抗锯齿、色彩管理差异不计入失败；
- **参考不一致必须先裁决**：任何 PDF 参考与 Canvas 输出不一致（包括疑似字体缺失、参考宿主 `.notdef`、水印/内容差异），QA 必须先提交裁剪对比/bbox/ΔE 证据给 captain/用户核查，不得自行在 `samples.json` 标 `referenceMismatchPages` 或 `knownTolerancePages`；只有用户明确批准的页/项才能分类，且报告必须单列原因；
- manual 不提交仓库，CI 上会跳过 89 页/JBIG2 专项，需在本地或专用环境补跑；
- dense-text-perf 的性能数字受机器/Node GC 影响，T9/T11 同时记录 3 次原始值/中位数与机器负载，单次抖动
  不作唯一结论（门禁仍以中位数/当次实测是否达标为准）。
