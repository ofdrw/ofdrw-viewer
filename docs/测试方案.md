# OFD Viewer 测试方案

本方案描述四个包当前如何被验证：测什么、用什么夹具、跑什么命令、产物落在哪里、哪些结果构成门禁。实现契约见 [跨包契约](CONTRACTS.md)；公共 API 参数与返回值见各包 `skills/API.md`。测试方案不重复定义产品行为。

## 1. 目标与范围

### 1.1 测试对象

| 层 | 被测对象 | 主要手段 |
| --- | --- | --- |
| engine | 解包、XML/模型、布局、文本内容、图片、DisplayList、H5 Canvas2D 渲染、生命周期与资源限制 | 白盒单测 + 合成夹具 + 真实样本 + 黄金图 + 稳定性回归 |
| crypto | 来源适配、加密检测、口令/证书解密、多层/多用户、ASN.1/X.509、SM2/SM3/SM4、签名/完整性/时间戳、证书链 | 单测 + 受保护 OFD 夹具 + OpenSSL/Java 向量 + Node/jsdom |
| UI | 文档加载、页面编排、渲染队列、文本层、查找、打印、导出、签章、功能开关、来源、Web Component/React/Vue | jsdom 单测/集成（交互行为用本地 Playwright 临时验证，不入库） |
| CLI | 参数/子命令、转图、`info`、`verify`、加密文档、退出码、SEA | 单元/端到端 + 构建后黑盒验收 |
| 跨包 | engine 导入边界、公共 API 文档同步、crypto→engine 容器对接、UI/CLI 使用公共入口 | 根级 smoke + 各包集成/验收 |

### 1.2 范围边界

覆盖：单元、集成、批量黄金图、CLI 黑盒、性能/稳定性/取消/内存、独立向量验证。UI 的交互行为（点击、拖选、双击、缩放）以 vitest 单测覆盖可确定性部分，必要时用本地 Playwright 临时验证，不作为常设套件。

不覆盖：生产环境监控、PDF 参考样张的版权与业务审核、第三方 CA 的真实吊销服务、除 Chrome 外的浏览器矩阵、把 UI 视觉差异自动判定为产品缺陷。

### 1.3 判定原则

- 优先通过公共 API 验证；白盒单测只用于纯函数、内部边界和错误分支。
- 期望值尽量来自独立来源：PDF 参考图、OpenSSL 命令行、Java 生成的预期摘要、标准向量，而不是被测实现自身。
- 允许 skip 的条件必须显式：引擎不可用、样本缺失、`pdftoppm` 不可用、可选样本缺失。skip 不等于通过。
- 失败必须保留样本名、页号、命令、环境、指标和产物路径；不能只报“测试失败”。
- 测试产物写入忽略目录，不提交；基准和夹具的更新必须走人工确认。

### 1.4 Playwright 使用约束

Playwright 驱动的真实浏览器测试**允许在开发与本地调试时使用，但不允许进入仓库**。原因是这类测试依赖真实浏览器、时序与渲染差异，存在概率性波动，作为门禁会引入不稳定的失败。

- **允许**：本地开发、缺陷复现、交互行为验证期间，可临时用 Playwright 驱动真实 Chrome 做点击、拖选、双击、缩放、旋转、截图取证等操作。
- **禁止入库**：Playwright 测试文件（`*.spec.ts`）、`playwright.config.ts`、夹具生成脚本、截图与报告产物一律不得提交。
- **用完即删**：临时 spec 与截图在取得证据后立即删除；证据本身（实测数值、事件次数、DOM 结果）写进提交说明、PR 描述或设计文档，而不是以测试文件形式留在仓库。
- **仓库不保留** `packages/ofdrw-viewer-ui/test/e2e`、`playwright.config.ts` 与 `@playwright/test` 依赖。
- **回归替代**：文本层、选区、缩放等可确定性验证的逻辑用 vitest 单测覆盖；只有必须依赖真实浏览器才能判断的交互（如浏览器在 `pointerup` 补建 Range 的行为）才用一次性 Playwright 验证，结论沉淀为文档与单测断言。
- **证据要求**：涉及交互缺陷时，必须给出真实浏览器实测数据（例如一次双击产生的 `scalechanging` 次数、矩形底边与文本底边的差值），不接受仅凭静态阅读得出的结论。

## 3. 运行环境与依赖

### 3.1 基础环境

- Node.js `>=22`；仓库使用 `pnpm@11.24.0`；安装使用 `pnpm install --frozen-lockfile`。
- TypeScript 严格模式、`isolatedModules`、`verbatimModuleSyntax` 由各包 `tsconfig` 保证。
- 干净检出后先 `pnpm build`：UI/demo 的类型检查通过包 `dist` 引用 engine/crypto，直接 `typecheck` 可能找不到声明。
- Linux CI 使用 `fonts-noto-cjk`；本地无中文字体时，文本渲染/CLI 文本导出会出现缺字 warning，不能把字体缺失误判为解析失败。

### 3.2 分套件依赖

| 套件 | 额外依赖 | 缺失时行为 |
| --- | --- | --- |
| engine 单测 | 无系统依赖 | 正常运行 |
| engine 黄金图/批量回归 | `pdftoppm`/`pdfinfo`（poppler）、系统字体、`@napi-rs/canvas` | PDF 工具缺失时参考对比 skip；引擎不可用时测试 skip |
| crypto 单测 | Node 全局 `Blob`、`crypto.subtle`（加密 PKCS#8） | 对应用例失败或按能力 skip；不静默通过 |
| crypto 独立验证 | OpenSSL 3 CLI；Java 预期值已固化为 JSON，不需 Java 运行时 | OpenSSL 缺失时相关交叉验证用例 skip（skip 不等于通过）；版本/能力不满足导致命令失败时用例失败，不得静默通过 |
| UI 单测/集成 | jsdom、`@napi-rs/canvas`（如测试需要） | 正常运行 |
| CLI 单测 | Node、`@napi-rs/canvas` | 正常运行 |
| CLI 验收 | 先构建 `dist/bin.js` 与 SEA；临时目录可写 | 构建失败即失败；SEA 用例按平台跳过/失败 |

### 3.3 环境变量

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `GOLDEN_RUN_ALL=1` | 开启批量真实样本回归；未设置时整组 skip | 关闭 |
| `GOLDEN_REQUIRE_ENGINE=1` | 要求样本可用、样本无失败、页面无失败 | 关闭 |
| `GOLDEN_DPI` | 黄金图渲染 DPI | `96` |
| `GOLDEN_SAMPLE_FILTER` | 按样本名精确/子串筛选 | 全部 |
| `GOLDEN_MAX_PAGES` | 每样本最多比较页数 | 全部 |
| `GOLDEN_OUT_DIR` | 固定产物目录 | `test/.artifacts/golden/<时间戳>` |
| `BASE_PATH` | 演示站构建基路径 | `/` |

## 4. Fixture 与样本生成

### 4.1 engine 合成夹具

- `test/fixtures/zip-builder.ts` 的 `createZip` 支持 store/deflate、ZIP64、data descriptor、UTF-8 标志、重复条目、`../` 路径和自定义 EOCD，用于包结构、安全与边界测试；`readZipEntries`/`zip-inspector` 用于断言写入结果。
- `test/fixtures/ofd-builder.ts` 的 `buildMinimalOfd` 生成最小 OFD：页数、页宽/高（mm）、标题、可选内嵌字体、可选 PathObject、文本；`buildImageOfd` 等辅助构造图片/资源场景。
- 图片、字体、XML 等合成夹具在 `test/fixtures` 与各模块测试内构造；测试结束清理临时目录。
- 合成包不得写入业务敏感内容；安全用例的路径穿越、重复条目、超大条目等只用于断言拒绝行为。

### 4.2 crypto 受保护夹具

目录 `packages/ofdrw-viewer-crypto/test/fixtures/crypto` 是四包共用的受保护 OFD 回归资产：

- 12 个 `.ofd`：明文、口令加密、证书加密、SESv4、SESv5、完整性、签名+完整性、签名+完整性+口令加密，以及 4 个负例（内容篡改、SignedValue 篡改、Signature.xml 篡改、夹带文件）。
- 证书/私钥：根、签名者、加密、制章、TSA 五类，各提供 PEM/DER；私钥为 PKCS#8。
- `manifest.json` 记录每个 case 的路径、大小、SHA-256、凭据和预期结果；`manifest.sha256` 覆盖 cases/certs 文件，不覆盖 manifest/README。
- 固定凭据：口令用户 `fixture-password-user`，口令 `FixturePass123`；证书用户 `fixture-cert-user`，私钥 `certs/encrypt.key.pem`；信任根 `certs/root-ca.crt.pem`。
- 夹具字节已提交；重新生成会改变随机加密值和时间戳，必须同步重写 manifest 与 SHA-256。当前不提供自动再生成脚本。
- 所有证书/私钥均为公开测试材料，只能用于测试、演示和格式验证。

### 4.3 CLI 夹具

- `packages/ofdrw-viewer-cli/test/fixtures/minimal.ttf` 用于可控字体路径。
- 验收复用 `ofd_pdf_match` 的 `helloworld.ofd`、`999.ofd`、`dense-text-perf.ofd` 与 crypto 受保护夹具；临时输出目录由验收 helper 创建并清理。
- 字体候选依次为仓库 `test/.fixtures/fonts/DroidSansFallbackFull.ttf`、Linux DejaVu/Liberation、macOS Arial、Windows Arial；都缺失时文本导出可能为空并带 warning，测试需显式安装/传入字体。

### 4.4 黄金图样本 manifest

`packages/ofdrw-viewer-engine/test/golden/samples.json` 是样本清单唯一权威，当前 64 条、179 个比较页。每条记录样本名、分组、优先级（P0/P1）、是否可选、OFD/PDF 路径、页数、尺寸、内嵌字体/图片/JBIG2 数量、SHA-256、特殊页与说明。修改样本必须同步 manifest、PDF 参考和严格基线；不得只改 manifest 让审计通过。

## 6. 黄金图 harness

### 6.1 渲染与比较流程

1. 用 engine 公共 API 打开样本，H5 Canvas2D 渲染器 + `@napi-rs/canvas` 生成页面 PNG；默认 DPI 96。
2. 用 `pdftoppm` 把同页 PDF 参考转成 PNG；页尺寸/DPI 对齐后比较。
3. 计算内容掩码、抗锯齿边缘掩码、内容 bbox、区域网格、关键色和 SSIM；生成 diff PNG。
4. 按尺寸、布局、颜色三类指标判定单页 `pass`/`size-mismatch`/`layout-mismatch`/`color-mismatch`；批量报告再归纳样本结论。

### 6.2 默认容差

| 指标 | 默认值 | 说明 |
| --- | ---: | --- |
| `layoutMm` | 0.5 | 内容 bbox 偏差，mm |
| `sizeMm` | 0.5 | 页面尺寸偏差，mm |
| `colorDeltaE` | 5 | 关键色 ΔE2000 |
| `colorCoverageDelta` | 0.2 | 关键色占比差 |
| `aaEdgeThreshold` | 48 | 抗锯齿边缘灰度阈值 |
| `pixelmatchThreshold` | 0.1 | 像素差异阈值（0–1） |
| `backgroundDistance` | 8 | 背景距离 |
| `minAlpha` | 8 | 最小不透明度 |
| `regionGrid` | 3 | 区域网格数 |
| `textEdgeDensity` | 1.2 | 文字页边缘密度阈值 |
| `textSsimMin` | 0.6 | 文字页 SSIM 阈值 |
| `textInkMaxLuminance` | 100 | 文字页暗墨亮度上限 |
| `inkMaxLuminance` | 200 | 墨迹亮度上限 |
| `textCoverageDelta` | 0.9 | 文字页关键色占比差 |
| `textColorDeltaE` | 6 | 文字页关键色 ΔE2000 |
| `textLayoutMm` | 2 | 文字页 bbox 偏差，mm |

有效尺寸容差至少 1 px；有效布局容差取 `layoutMm`、1 px 对应毫米、文字页 `textLayoutMm` 的较大值。文字页判定为 `edgeDensity >= textEdgeDensity && ssim >= textSsimMin`，只有文字页使用 `text*` 颜色/覆盖/布局限值。关键色取主导色前 8 名，按最近颜色匹配并同时比较占比。

### 6.3 严格基线审计

`packages/ofdrw-viewer-engine/scripts/audit-strict.mjs` 把本次批量报告与 `test/golden/baseline/strict-baseline.json` 逐页比较，而不是重新判断“好不好看”：

- 基线必须是 64 个样本、179 页；全量运行才允许 `--update-baseline`。
- 页级比较指标容差：`layoutDeltaMm 0.01`、`colorP95DE 0.25`、`colorP95DEAll 0.25`、`blockColorP95DE 0.5`、`keyColorCoverageDelta 0.005`、`inkDiffRatio 0.002`、`contentDiffRatio 0.002`、`pixelDiffRatio 1e-7`。
- 退出码：`0` 与基线一致；`1` 指标漂移或基线过期；`2` 运行/输入错误。
- `--filter`、`--max-pages`、`--dpi`、`--out`、`--report`、`--baseline` 可缩小或改写运行；`--inject-pixel` 只用于自测比较器能否失败。
- 审计前会检查字体缓存隔离；`--update-baseline` 遇到缓存污染直接报错。

命令：

```bash
pnpm -C packages/ofdrw-viewer-engine test:audit
pnpm -C packages/ofdrw-viewer-engine test:audit --filter 999 --max-pages 3
pnpm -C packages/ofdrw-viewer-engine test:audit --update-baseline
```

### 6.4 PNG 页面基线

`test/golden/baseline/<sample>/page-XXX.png` 是人工确认的页面基线约定：文件存在时批量回归会比较并记录 `baselineMetrics`，不存在时不比较、不失败。基线 README 要求人工查看 engine/ref/diff 后再复制，禁止脚本自动覆盖。当前该目录只有 README 与严格基线 JSON，没有已提交的页面 PNG，因此该项不是当前门禁；真正执行的门禁是 §6.3 的严格指标基线。

### 6.5 批量回归与门禁开关

```bash
GOLDEN_RUN_ALL=1 pnpm -C packages/ofdrw-viewer-engine exec vitest run test/e2e/run-all.e2e.test.ts
GOLDEN_RUN_ALL=1 GOLDEN_REQUIRE_ENGINE=1 pnpm -C packages/ofdrw-viewer-engine exec vitest run test/e2e/run-all.e2e.test.ts
GOLDEN_RUN_ALL=1 GOLDEN_SAMPLE_FILTER=999 GOLDEN_MAX_PAGES=3 pnpm -C packages/ofdrw-viewer-engine exec vitest run test/e2e/run-all.e2e.test.ts
```

未设置 `GOLDEN_RUN_ALL=1` 时整组 skip。批量回归默认只生成报告，不因样本/页面差异失败；设置 `GOLDEN_REQUIRE_ENGINE=1` 后才要求 `samplesUnavailable=0`、`samplesFailed=0`、`pagesFailed=0`。严格质量门禁使用 §6.3 的 `test:audit`，不要用批量回归的默认模式替代。

```bash
GOLDEN_RUN_ALL=1 pnpm -C packages/ofdrw-viewer-engine exec vitest run test/e2e/run-all.e2e.test.ts
pnpm -C packages/ofdrw-viewer-engine test:audit

pnpm -C packages/ofdrw-viewer-crypto test
pnpm -C packages/ofdrw-viewer-crypto exec vitest run test/verification/core test/core test/cert

pnpm -C packages/ofdrw-viewer-ui test

pnpm -C packages/ofdrw-viewer-cli test
pnpm -C packages/ofdrw-viewer-cli test:acceptance
```

`pnpm test` 执行 engine 全部 vitest，包含可能较慢的黄金图/性能用例；日常单元回归用上面的排除命令。`pnpm test:golden` 只跑 `test/golden`，不包含 `test/e2e` 批量回归。

### 7.2 CI 门禁

`.github/workflows/ci.yml` 在 `ubuntu-24.04`、Node `26.10.0`、pnpm `11.24.0` 上执行：

1. 安装依赖并 `pnpm build`（先构建，保证 UI/demo 类型声明可解析）。
2. `pnpm -r --if-present run typecheck`。
3. engine 单元测试：排除 `test/golden/**`、`test/e2e/**`。
4. crypto 单元测试：`pnpm -C packages/ofdrw-viewer-crypto test`。
5. UI 单元/集成测试：`pnpm -C packages/ofdrw-viewer-ui test`（jsdom）。
6. CLI 单元/端到端/独立验证：`pnpm -C packages/ofdrw-viewer-cli test`。
7. 演示站构建：`BASE_PATH=/ pnpm -C demo build`。

CI 不运行黄金图与批量 e2e。原因是对参考图、系统字体与独占 CPU 的依赖在共享 runner 上不稳定；这些套件需在本地或专用环境执行，结果按 §8 保存。

### 7.3 发布门禁

`.github/workflows/release.yml` 的 verify 只做标签与四个包版本一致检查、安装依赖、`pnpm -r --if-present run typecheck`；发布阶段另跑 CLI typecheck、CLI 单元测试、SEA 构建和 Unix/Windows 冒烟（`--version`、`--help`、helloworld 转 PNG、dense text `--text --pages 1` 的 JSON 含 `"text"`）。发布工作流不复跑 crypto/UI 全量测试，也不跑黄金图；这些必须在合并前由 CI 或本地完成。

## 8. 报告与产物

### 8.1 黄金图报告

批量回归写入 `test/.artifacts/golden/<时间戳>/`（或 `GOLDEN_OUT_DIR`）：

```text
report.json
report.html
pages/
  <sample>-p<page>-engine.png
  <sample>-p<page>-ref.png
  <sample>-p<page>-baseline.png
  <sample>-p<page>-diff.png
```

`report.json` 顶层含运行时间、DPI、容差、`summary`（样本/页/通过/失败/跳过/不可用等计数）和 `samples[]`；每个样本含 `pages[]`，页记录含状态、尺寸、指标、warning、错误和图片相对路径。HTML 用同一数据渲染，附带容差表和图片链接。严格审计读取该 JSON，输出样本/页/已知页计数、失败项和退出码。

### 8.2 其他套件产物

- 稳定性：`test/.artifacts/<suite>/stability.json`，含 500 页耗时/堆采样、close、取消、恶意包结果。
- CLI：临时目录中的图片/文本/JSON；测试失败时保留 stdout/stderr/退出码，验收结束清理临时目录。
- crypto：验证套件直接断言报告对象/摘要；需要时在临时目录生成 OpenSSL 中间文件并清理。

### 8.3 失败记录

失败输出至少包含：套件/命令、样本名与页号、状态（size/layout/color/error）、关键指标与容差、引擎/参考/基线/diff 路径、Node/OS/Chrome/OpenSSL 版本、是否 skip 及原因。禁止把多个页面的失败汇总成一条无页号的“渲染失败”。

## 9. 性能、安全、取消与内存

### 9.1 性能口径

| 场景 | 指标 | 当前阈值/处理 | 是否门禁 |
| --- | --- | --- | --- |
| engine 文本性能 | engine draw / open / heapUsed | 普通页 500/150/80 ms；`dense-text-perf` 100/800/1000/600 ms、150 MiB | 否；常驻用例已按测试精简移除，仅作设计目标，需要时手工测量 |
| UI 1000 页 open/jump/zoom/find | 浏览器计时 | 目标 2000/500/500/5000 ms | 否；当前无常驻用例，需要时手工测量 |
| 黄金图批量 | 总时长 | 无固定阈值 | 否，产物用于审计 |

engine 文本性能的原有阈值不再有常驻测试执行，不能当成 CI 门禁；普通页与 `dense-text-perf` 的目标值保留在设计文档中。

### 9.2 稳定性与内存

- engine 连续渲染 500 页，要求无崩溃、页面结果有效，峰值堆增长量小于 512 MiB；重复 `close()` 20 次保持幂等，关闭后取页得到 `OFD_CLOSED`。
- 快速取消/重渲染要求至少产生 `OFD_ABORTED`，且成功的渲染仍能完成；取消不能留下悬挂任务。
- dense 压力样本的 150 MiB 内存目标只保留在设计文档中，当前无常驻用例。
- UI 千页要求 DOM 页面壳 1000、活动 canvas 数量不超过 8，验证虚拟化；缩略图只渲染可视窗口。
- CLI 转图失败不产页；部分页失败按页级退出码处理，不能把失败页当成功输出。

### 9.3 安全

- 恶意 ZIP/XML/图片/超限条目必须在资源限制内拒绝并返回稳定错误，不崩溃、不读取包外文件；路径穿越、重复条目、ZIP64、data descriptor 由合成夹具覆盖。
- crypto 的凭据、私钥、FEK、`EncryptedWK`、明文正文不得出现在错误、warning、日志、JSON 或测试快照；负例篡改必须失败而不是降级为通过。
- UI 的凭据弹窗/验证报告不得把私钥或口令写入 DOM、URL、localStorage；CLI 的 stderr 不得回显口令/私钥。
- 测试证书/私钥只用于测试；夹具的 SHA-256 校验防止资产被替换。
- 网络来源由宿主负责，UI/CLI 测试不得把真实外部服务作为必需依赖；需要 URL 行为时使用本地可控服务。

### 9.4 取消与关闭

| 层 | 触发 | 期望 |
| --- | --- | --- |
| engine | AbortSignal / RenderTask.cancel | `OFD_ABORTED`，任务不再完成，文档仍可关闭 |
| crypto | `signal` | `CRYPTO_ABORTED`，已构造容器关闭，不返回半成品 |
| UI | 取消加载/渲染/验证、destroy | 操作结束、状态一致、无后续 DOM 更新 |
| CLI | SIGINT | 退出码 `130`，未完成页不写成成功 |

## 10. 密码能力与跨包矩阵

### 10.1 能力矩阵

| 能力 | engine | crypto | UI | CLI |
| --- | --- | --- | --- | --- |
| 检测加密/用户/层数 | 不负责 | `inspect` | 打开前检测、凭据选择 | `info` 摘要 |
| 口令解密 | 接收明文容器 | `openDecryptingContainer` | 内置凭据弹窗/预置凭据 | `convert --user --password` |
| 证书解密 | 接收明文容器 | 私钥凭据 + SM2 | 私钥凭据弹窗/预置 | `convert --user --key` |
| 多层/多用户 | 不负责 | 层循环/限制/重复用户 warning | 展示层/用户诊断 | 文本/JSON 摘要 |
| 签名验证 | 提供容器/页面 | `verifyOfd` | 验证面板/自动验证/状态映射 | `verify` 文本/JSON |
| 完整性/夹带 | 不负责 | `verifyOfd` + `parseOfdEntriesXml` | 报告/告警 | `verify` |
| 时间戳 | 不负责 | `parseTimestamp`（只解析） | 展示“已解析，未验证” | `verify` 展示 |
| 证书链/信任根 | 不负责 | DER 根 + 链验证 | `rootCertificates`/loader | `--root` 转 DER |
| 解密后渲染 | 打开明文容器 | 返回 `VirtualContainer` | 正常加载/导出/打印 | 转图/文本 |

### 10.2 夹具与预期

- `plain.ofd`：明文基准，`inspect.encrypted=false`，可直接打开。
- `password-encrypted.ofd`：口令用户可解密，内容与 plain 一致；无凭据/错口令分别失败。
- `cert-encrypted.ofd`：`certs/encrypt.key.pem` 可解密；错私钥/缺 passphrase 按错误码失败。
- `signed-sesv4.ofd`/`signed-sesv5.ofd`：配置根时签名者链 `valid`，不配置根时 `unknown`；时间戳只解析。
- `integrity.ofd`/`combined-signed-integrity.ofd`：完整性与签名均通过；负例篡改必须 `invalid`/失败。
- 负例：内容、SignedValue、Signature.xml、额外文件分别覆盖签名/摘要/夹带失败。
- 多层/多用户/entriesmap 的构造与断言在 crypto 单测内完成；UI/CLI 只消费公共入口。

## 11. 已知限制

1. CI 只跑各包单元/集成（engine 排除 golden/e2e），不跑黄金图审计与批量真实样本；这些需本地/专用环境执行。
2. 批量 e2e 默认只产报告，不因页面差异失败；必须显式设置 `GOLDEN_RUN_ALL=1`，质量门禁另用 `GOLDEN_REQUIRE_ENGINE=1` 或 `test:audit`。
3. 严格审计是“与基线一致”检查，不是绝对画质判定；基线中的已知差异页在未变化时仍会通过，改动必须人工审核。
4. PNG 页面基线目录当前没有已提交的页面 PNG，比较逻辑存在但不构成门禁；实际门禁是严格指标基线。
5. engine 文本性能阈值（普通页 500/150/80 ms、dense 压力阈值）已随常驻用例移除，当前只有稳定性内存检查；这些数值仅作设计目标。
6. UI 1000 页 open/jump/zoom/find 的性能指标用例已按测试精简移除，需要时手工测量；真实 Chrome 之外没有 Firefox/WebKit 矩阵。
7. UI 交互回归以 vitest/jsdom 为主；必须依赖真实浏览器才能判断的行为，按 §1.4 用一次性 Playwright 验证并删除，不进入仓库与门禁。
8. crypto 的 OpenSSL 交叉验证依赖本机 OpenSSL 3 CLI；jsdom 用例只模拟浏览器单 realm，不等于真实浏览器全面验证。
9. CLI SEA 验收依赖平台工具链和构建产物；Windows/macOS 的发布冒烟只在 release 矩阵执行。
10. 样本只覆盖仓库 `ofd_pdf_match` 的 58 个 OFD/PDF 对；`manual` 只比较 5 页，`dense-text-perf` 只覆盖两页，不能代表所有业务文档。
11. 测试未设置覆盖率百分比门禁；公共 API 文档同步检查只覆盖 engine 根导出，其他包的 API 文档靠评审保证。
12. 黄金图比较依赖字体、`@napi-rs/canvas`、poppler 版本；环境变化可能造成系统性像素差异，必须保留环境信息并人工复核。
