# 警告与错误日志方案设计

本文件统一 `ofdrw-viewer-engine` / `ofdrw-viewer-crypto` / `ofdrw-viewer-ui` 三层的诊断（warning）与错误（error）体系：码表归属、级别与去重、三条消费通道（回调 / 事件 / 控制台）、格式约定、开关与隐私边界，以及评测。字体缺省与缺字口径见 [`渲染字体缺省方案设计.md`](./渲染字体缺省方案设计.md)；UI 字体配置见 [`字体配置方案设计.md`](./字体配置方案设计.md)。

## 1. 定位与问题

### 1.1 现有体系

诊断信息已经分三层存在，但**缺少统一的对外约定**：

| 层 | 码表 | 类型 | 上报方式 |
| --- | --- | --- | --- |
| engine | `W_*`，共 20 个，`WARNING_CODES` 冻结 | `OFDWarning { code, message, pageIndex?, resourceId? }` | `onWarning` 回调 |
| engine | `OFD_*`，共 14 个 | `OFDError { code, cause? }` | Promise reject |
| crypto | `W_CRYPTO_*`，共 13 个，`CRYPTO_WARNING_CODES` 冻结 | 同上 | `CryptoOptions.onWarning` |
| UI | `W_*` 自有码 34 个，已收敛为 `UI_WARNING_CODES` | `ViewerWarning { code, message, pageIndex?, resourceId? }` | `onWarning` + `warning` 事件 |
| UI | `OFD_*`，14 个 | `OFDViewerError` | `onError` + `error` 事件 / Promise reject |

### 1.2 已暴露的问题

1. **UI 的 warning 码没有码表**（已解决：见 §2.3 的 `UI_WARNING_CODES`，各模块字面量已改为常量引用）：`ViewerWarning.code` 仍是 `string`（兼容引擎/crypto 码），但 UI 自有码统一经常量引用，拼错会被类型系统发现。
2. **`resourceId` 在 UI 层类型上丢失**（已解决：`ViewerWarning` 已声明 `resourceId?: string`）：engine 的 `OFDWarning` 带 `resourceId`，UI 此前只能靠 `Partial<EngineWarningContext>` 强制断言取出来。
3. **只有回调就要靠宿主自己接**：不接 `onWarning` 的宿主看不到任何诊断，缺字、缺字体导致的空白页完全无从排查（本次用户实际遇到的问题）。
4. **控制台输出缺少统一规范**：前缀、格式、去重键、开关都是新加的局部实现，没有写进公共约定，后续新增诊断点容易各写一套。
5. **级别语义不统一**（已解决：`resolveDiagnosticLevel()` 按码取级别）：`W_*` 是 warning 还是 error 由调用点决定（例如 `reportWarningError` 把异常包装成 `W_*` 码上报），无法按级别过滤。

### 1.3 目标

1. 三层的码表**归属清晰、可枚举、可文档化**；
2. 诊断有**明确级别**与**稳定去重键**；
3. 诊断通过**三条通道**同时可达：程序化回调、事件、控制台；
4. 控制台输出**格式统一、可关闭、可过滤、不泄密**；
5. 不破坏既有 `onWarning`/`onError` 语义与错误码。

### 1.4 非目标

- 不改变 warning 不中断渲染的既有语义；
- 不把 warning 提升为异常；
- 不引入第三方日志库（保持浏览器/小程序可用）；
- 不把字节日志、PEM、口令、私钥写入任何通道（见 §7）。

## 2. 分层与码表归属

### 2.1 码表归属原则

| 前缀 | 归属 | 含义 | 示例 |
| --- | --- | --- | --- |
| `W_` | engine | 文档解析/渲染中的可容忍异常 | `W_FONT_MISSING`、`W_GLYPH_MISSING` |
| `W_CRYPTO_` | crypto | 解密/验证中的可容忍异常 | `W_CRYPTO_TRUST_UNKNOWN` |
| `W_`（UI 自有） | UI | 阅读器交互层的可容忍异常 | `W_NAV_DEST`、`W_OUTLINE`、`W_UI_LISTENER` |
| `OFD_` | engine | 打开/渲染失败 | `OFD_INVALID_PACKAGE` |
| `OFD_CRYPTO_` | crypto / UI | 密码能力失败 | `OFD_CRYPTO_FAILED` |
| `OFD_`（UI 自有） | UI | 交互失败 | `OFD_FEATURE_DISABLED`、`OFD_INVALID_OPTION` |

规则：

1. **归属看语义不看调用者**：引擎产生的 `W_FONT_MISSING` 由 UI 转发时仍属 engine 码，UI 只做附加（补 `pageIndex`），**不得改写码**；
2. UI 自有码统一以 `W_` 开头、语义类别作后缀（见 §2.3 表）；
3. 新增码必须同时更新码表与文档表格，`WARNING_CODES` 类常量保持冻结顺序（测试据此断言）。

### 2.2 engine 码表（20 个，已冻结）

`W_FONT_MISSING`、`W_GLYPH_MISSING`、`W_IMAGE_DECODE`、`W_UNSUPPORTED_PAINT`、`W_UNSUPPORTED_CLIP`、`W_BAD_NUMBER`、`W_BAD_PATH`、`W_DUPLICATE_RESOURCE`、`W_COMPOSITE_DEPTH`、`W_PATTERN_LIMIT`、`W_ZERO_BOUNDARY`、`W_PHYSICALBOX_ORIGIN`、`W_IMAGE_NO_CTM`、`W_NEGATIVE_BOUNDARY`、`W_LAYER_ORDER`、`W_BLEND_MODE`、`W_RADIAL_UNSUPPORTED`、`W_GOURAUD_APPROX`、`W_ANNOT_EMPTY`、`W_JBIG2_DECODE`。

### 2.3 UI 自有码表（已落地）

UI 码已收敛为 `packages/ofdrw-viewer-ui/src/diagnostics.ts` 的冻结常量 `UI_WARNING_CODES`（键与值相同，以 `UI_WARNING_CODES.W_XXX` 引用）；下表与代码逐项一致（34 个码，测试断言唯一性与内容）：

| 主题 | 码 | 触发点 |
| --- | --- | --- |
| 文档信息 | `W_METADATA`、`W_OUTLINE`、`W_BOOKMARKS` | 元数据/大纲/书签读取失败 |
| 导航 | `W_NAV_DEST`、`W_NAV_JUMP`、`W_NAV_ZOOM` | 目录项目标无效、跳页/缩放失败 |
| 缩略图 | `W_THUMBNAIL`、`W_THUMBNAIL_JUMP` | 缩略图渲染/跳转失败 |
| 文本 | `W_TEXT_LOAD`、`W_TEXT_EMPTY`、`W_TEXT_UNSUPPORTED`、`W_TEXT_LAYER_LIMIT` | 文本层加载、空文本、不支持、超限 |
| 查找 | `W_FIND_FAILED`、`W_FIND_LIMIT`、`W_FIND_PAGE`、`W_FIND_PAGE_LIMIT` | 查找失败/超限/翻页 |
| 导出打印 | `W_EXPORT_PARTIAL`、`W_EXPORT_PAGE`、`W_OUTPUT_LARGE_TASK`、`W_OUTPUT_DPI_REDUCED` | 部分导出、单页失败、大任务、DPI 降档 |
| 签名与附件 | `W_SIGNATURE_ASN1`、`W_SIGNATURE_RESOURCE`、`W_SIGNATURE_TIMESTAMP`、`W_SIGNATURE_ENTRIES`、`W_ATTACHMENT_RESOURCE` | ASN.1、资源、时间戳、条目读取、附件资源读取失败 |
| 密码能力 | `W_CRYPTO_VERIFICATION_CALLBACK`、`W_CRYPTO_VERIFY_FAILED`、`W_CRYPTO_CERT_SOURCE_UNSUPPORTED` | 验证回调异常、自动/重新验证失败、证书来源不支持 |
| 界面 | `W_UI_LISTENER`、`W_UI_CLEANUP`、`W_ENGINE_EVENT`、`W_FULLSCREEN_FALLBACK` | 事件监听器异常、清理失败、引擎事件异常、全屏降级 |
| 来源 | `W_QUERY_SOURCE` | 查询参数来源解析 |
| 资源限制 | `W_CANVAS_LIMIT` | 画布降档仍失败 |

与初版草稿的差异（以代码为准）：

- `W_SIGNATURE_ASN` → `W_SIGNATURE_ASN1`（代码实际拼写）；
- 补入 `W_ATTACHMENT_RESOURCE`（附件侧栏读取失败，原表漏列，归入签名与附件主题）；
- 补入 `W_CRYPTO_VERIFY_FAILED`（UI 调用密码能力自动/重新验证失败时自行上报，属 UI 自有码，原表漏列）；
- `W_ORDER` 只存在于引擎（`WARNING_CODES`），**不在** UI 表；引擎码（`W_FONT_MISSING`、`W_GLYPH_MISSING` 等）同理不属于 UI 表，由 UI 转发时保持原码。

### 2.4 错误码表

| 层 | 码 | 说明 |
| --- | --- | --- |
| engine | `OFD_INVALID_PACKAGE`、`OFD_ENTRY_NOT_FOUND`、`OFD_UNSUPPORTED_COMPRESSION`、`OFD_ENCRYPTED`、`OFD_XML_PARSE`、`OFD_PAGE_NOT_FOUND`、`OFD_CANVAS_TOO_LARGE`、`OFD_CANVAS_SIZE_MISMATCH`、`OFD_RENDERER_UNSUPPORTED`、`OFD_ABORTED`、`OFD_CLOSED`、`OFD_NOT_OPENED`、`OFD_LIMIT_EXCEEDED`、`OFD_FONT_PARSE`、`OFD_IMAGE_DECODE` | 打开/渲染失败 |
| UI | `OFD_FEATURE_DISABLED`、`OFD_INVALID_OPTION`、`OFD_INVALID_PAGE`、`OFD_NOT_OPENED`、`OFD_DESTROYED`、`OFD_UNSUPPORTED`、`OFD_EXPORT_FAILED`、`OFD_PRINT_FAILED`、`OFD_SIGNATURE_PARSE_FAILED`、`OFD_CLIPBOARD_FAILED` | 交互失败 |
| UI | `OFD_CRYPTO_CREDENTIAL_REQUIRED`、`OFD_CRYPTO_CANCELLED`、`OFD_CRYPTO_UNSUPPORTED`、`OFD_CRYPTO_FAILED` | 密码能力失败 |

**归因规则**（本次修复的经验）：`OFD_CRYPTO_FAILED` 的 message 必须区分「加密信息读取失败」与「凭据错误」，不得把前者表述为“请检查凭据”。同理，任何错误 message 都要说明**失败发生在哪个阶段**（检测/解密/打开/渲染/交互），而不是笼统归因。

## 3. 级别与去重

### 3.1 级别模型

三级，而非两级：

| 级别 | 语义 | 默认输出 | 通道 |
| --- | --- | --- | --- |
| `info` | 有诊断价值但不异常（如自动字体替代） | 不打控制台 | 回调/事件 |
| `warn` | 可容忍，影响部分内容（缺字、缺字体、部分导出） | `console.warn` | 回调/事件/控制台 |
| `error` | 阻断或操作失败 | `console.error` | 回调/事件/控制台 |

当前 UI 只有 `warn`/`error` 两级；`info` 为**预留**，新增诊断点默认用 `warn`。

**级别由码类别决定，而非调用点**：建议维护一张 `码 → 级别` 映射，`reportWarningError()` 这类“把异常包装成 warning 码”的调用统一取该映射的级别。

### 3.2 去重键

| 级别 | 去重键 | 生命周期 | 理由 |
| --- | --- | --- | --- |
| `warn` | `<code>:<pageIndex>:<resourceId>` | 一个文档会话（`open()` 时清空） | 同一资源的同一问题只在首次出现时提示；千页文档不刷屏 |
| `error` | `<code>:<pageIndex>` | 一个文档会话 | 错误通常伴随明确操作，不按 resource 细分 |

规则：

1. **去重只作用于控制台输出与状态列表**，`onWarning`/`onError` 回调与事件**每次都触发**（宿主可能依赖完整序列做统计）；
2. 去重集合在 `open()` 开始时清空（切换/重开文档重置）；
3. 状态里的 `ui.warnings` 已有 `slice(-100)` 上限，作为控制台之外的补充视图。

## 4. 三条消费通道

```text
                    ┌─→ onWarning / onError（宿主回调，每次触发）
诊断发生 ─→ 归一化 ─┼─→ 'warning' / 'error' 事件（Web Component: ofd-warning/ofd-error）
                    └─→ console.warn / console.error（去重后，可关闭）
```

### 4.1 归一化

所有来源（引擎回调、密码能力回调、UI 内部）先归一化为统一结构再分发：

```ts
/** 归一化后的诊断。 */
export interface ViewerDiagnostic {
  /** 诊断码；见 §2 码表。 */
  readonly code: string;
  /** 级别。 */
  readonly level: 'info' | 'warn' | 'error';
  /** 人类可读信息；不得包含字节日志或凭据。 */
  readonly message: string;
  /** 关联页索引，0-based。 */
  readonly pageIndex?: number;
  /** 关联资源/对象 ID（engine 的 `OFDWarning.resourceId`）。 */
  readonly resourceId?: string;
  /** 产生该诊断的包：engine / crypto / ui。 */
  readonly source: 'engine' | 'crypto' | 'ui';
  /** 原始错误；仅 error 级存在。 */
  readonly cause?: unknown;
}
```

`ViewerWarning` 增加 `resourceId?: string`（上表 §1.2 问题 2），`source` 字段**可选加入**，先保证不破坏现有结构。

### 4.2 回调通道

保持现状：`onWarning(warning)` / `onError(info)` 每次触发，参数结构向后兼容（只增不改）。

### 4.3 事件通道

保持现状：`warning` / `error` 事件已桥接为 `ofd-warning`/`ofd-error`（Web Component）、`onWarning`/`onError`（React）、`warning`/`error`（Vue）。

### 4.4 控制台通道

**格式**（单行，便于过滤与复制）：

```text
[ofd-viewer] <level> <code> <message> {pageIndex: 0, resourceId: "3"}
```

示例：

```text
[ofd-viewer] warning W_FONT_MISSING 字体缺失：FontName=宋体 {resourceId: "3"}
[ofd-viewer] warning W_GLYPH_MISSING 缺字：0x20BB7 {pageIndex: 0, resourceId: "12"}
[ofd-viewer] error OFD_CRYPTO_FAILED 读取文档加密信息失败：...
```

约定：

1. **前缀固定** `[ofd-viewer] `，跟级别与码，便于 `console` 过滤框输入 `[ofd-viewer]` 一次筛出全部；
2. 级别与码之间单空格，`message` 原样，上下文以 `{...}` 尾部附加；
3. 上下文只含 `pageIndex`（0-based）与 `resourceId`，**不打印 cause 的堆栈**（宿主需要时用 `onError` 的 `cause`）；
4. 第一参数是字符串（label），第二参数是 message，第三参数是上下文对象——保留 `console` 的结构化折叠能力，且 `expectNoPageErrors` 类断言可按首参前缀过滤。

**过滤与关闭**：

```ts
new OFDViewer({
  container: '#viewer',
  debug: {
    console: false,                    // 整体关闭（默认开启）
    levels: ['error'],                 // 只打印 error（可选）
    codes: ['W_FONT_MISSING'],         // 只打印指定码（可选）
  },
});
```

语义：`debug.console === false` 时完全不打印；`levels`/`codes` 为可选的二次过滤，未提供时按 §3.1 默认级别输出。过滤在去重**之前**判断（避免被过滤掉的诊断占用去重键）。

## 6. 典型场景的口径

| 场景 | 码 | 级别 | 可观测现象 |
| --- | --- | --- | --- |
| 文档字体完全缺省（如 `拿来主义_page6.ofd`） | `W_FONT_MISSING` | warn | 控制台一条（每资源一次）；文字对象跳过 → 页面空白 |
| 主字体缺某字 | `W_GLYPH_MISSING` | warn | 控制台按 `pageIndex+resourceId` 去重；该字形跳过，其余照常 |
| 字体 URL 读取失败（UI 层） | `W_FONT_MISSING` | warn | 控制台一条，含来源信息；不阻断打开 |
| 加密信息读取失败 | `OFD_CRYPTO_FAILED` | error | 控制台 `error`；message 说明“读取文档加密信息失败”，**不含“请检查凭据”** |
| 凭据错误 | `OFD_CRYPTO_FAILED` | error | 控制台 `error`；message 才出现“请检查凭据” |
| 签名条目缺 `Type` | 无（正常读入） | — | 不产生诊断；验证层按需记 `SIGNATURE_BASELOC_INVALID` issue |

## 7. 隐私与安全边界

1. **不得输出**：字体/证书/密钥字节、PEM、口令、`SignedValue` 密文、文档正文内容；
2. `message` 只含字体名、资源 ID、页序、错误摘要（`error.message`）与来源 URL/路径；
3. `cause` 只在 `onError` 回调中透出，控制台默认不打印堆栈；
4. 控制台输出受 `debug.console` 控制，生产环境可整体关闭；
5. 诊断去重集合只保留字符串键，不持有文档对象，避免内存泄漏（生命周期随 `open()`）。

## 8. 测试方案

| 用例 | 断言 |
| --- | --- |
| 缺字 warning | `console.warn` 被调用一次，首参为 `[ofd-viewer] warning W_GLYPH_MISSING` |
| 同码同页重复 | 只打印一次；`onWarning` 仍触发两次 |
| 不同页/不同资源 | 分别打印 |
| 重新 `open()` | 去重集合重置，同一诊断再次打印 |
| `debug.console=false` | 完全不打印；回调/事件照常 |
| `levels`/`codes` 过滤 | 被过滤的码不打印，且不占用去重键 |
| 码表 | `UI_WARNING_CODES` 冻结、键值一致、无重复；不含引擎码 `W_ORDER`/`W_FONT_MISSING` |
| 级别映射 | 未登记码（含引擎/crypto 码）默认 `warn`；`info` 默认不打印 |
| 格式化 | `formatDiagnostic()` 的 `label` 为 `[ofd-viewer] warning <code>`/`[ofd-viewer] error <code>`，`context` 只含 `pageIndex`/`resourceId` |
| error 级 | 走 `console.error`，首参前缀为 `[ofd-viewer] error` |
| 回调不受影响 | `onWarning`/`onError` 参数结构不变，每次触发 |
